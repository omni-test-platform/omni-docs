术语表

内容状态：基于代码与文档整理，待产品负责人复核。

术语按“业务对象 → 执行链路 → 引擎扩展 → 授权”排列。对象之间的关系见核心概念，运行时形态见平台架构。

术语定义边界
产品从禅道同步的产品，是平台业务的顶层数据源产品与项目一对一；顶部产品选择器即项目选择器
项目产品纳入平台后形成的过程记录与配置平台不“新建项目”，只“纳入”；归档不可逆
禅道实例一个独立的禅道服务及其数据同一产品 ID 在不同实例中可能重复，需用 (zentao_id, product_id) 联合定位
产品上下文当前选中的产品/项目及其可用数据范围切换产品后，环境、用例、任务等列表随之变化
阶段项目 IPD 流程中的一个阶段实例与计划里的“执行阶段”不是同一对象
评审点阶段内的检查点，分决策、技术、市场三类评审点通过是阶段推进的前置条件之一
质量门禁对阶段或发布设置的一组校验规则与评审点正交：门禁看指标，评审点看结论
提测单研发向测试提交版本进行验证的单据有提交、测试中、通过、退回、关闭等状态
版本项目下的一次发布候选计划发布时间与实际发布时间分开记录
用例可执行的最小测试单元平台内包含单接口、API、场景、Web 等形态
单接口用例针对一个接口定义的用例与 API 用例的区别在于是否组织多接口流程
API 用例由多个接口步骤组成的接口测试用例可包含断言、提取、变量传递
场景用例跨接口、按业务场景编排的用例强调步骤顺序与上下文复用
Web 用例基于元素与页面对象的浏览器用例需要 WebDriver 或 Playwright 环境
套件用例的集合用例与套件多对多；套件不等于一次执行
任务可选择用例/套件并发起执行的单元可手动、定时、API 或 Webhook 触发
计划由多个阶段与任务编排而成的执行单元支持阶段串行、阶段内任务依赖与定时触发
执行任务、阶段或计划的一次实际运行实例重跑产生新的执行记录，不覆盖历史
执行器执行具体步骤的组件，如 API、Web、CLI、K8s与“执行引擎”不同：引擎是框架，执行器是步骤实现
环境被测地址、凭据、变量、执行节点与前后置配置的集合属于产品上下文；任务执行时可临时覆盖
环境租约独占环境在执行期间的占用凭证共享环境不建立独占租约
报告一次或一批执行的结果汇总与明细平台报告页与 Allure 报告是不同呈现层
引擎omni-engine，基于 pytest 的执行框架可独立使用，也可由平台经 Jenkins 调度
步骤引擎执行的最小动作单元返回统一的 StepResult
Skill以 SKILL.md 描述的测试工作流能力，声明输入、步骤、产物与约束不是常驻服务；实际动作由 Agent 调用 CLI/MCP/脚本完成
技能家族按领域与动作命名的 omni-* 技能集合当前以 Web 为主，API 域按相同约定预留
编排（Pipeline）omni-pipeline 按依赖图调用阶段技能并支持断点续跑由 Agent 执行，不是后台 DAG 服务
相关性回归按变更模块/子系统/标签筛选应回归的用例映射缺失或筛选为空时回退全量并告警
Spec用 YAML/JSON 描述的用例或执行规范与代码用例双模并存
回调引擎向平台上报用例或任务结果的 HTTP 消息平台入口为 /at/executions/callback
License离线授权文件，绑定 edition、功能模块、用户数与机器码服务端内置公钥验签，无在线激活
EditionLicense 的授权档位：basic/standard/enterprise/ultimate/customcustom 由签发者指定 features
机器码由主机信息生成的设备标识换机或硬件变化后原 License 失效
