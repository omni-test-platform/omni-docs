数据库迁移脚本使用 MySQL/MariaDB 语法；切换到 PostgreSQL/Oracle/MSSQL 时，需单独评估 migrations/ 的兼容性。

升级路径

  1. 阅读目标版本的 CHANGELOG.md 与发布说明，确认破坏性变更。
  2. 备份数据库、config/、uploads/ 与当前二进制/镜像；记录当前 /version。
  3. 按顺序执行 migrations/ 脚本，再替换服务端二进制或镜像；前端重新构建并发布 dist。
  4. 执行端升级 omni-engine wheel 或源码，确认 omni-engine-cli --version。
  5. 验证 /health、/version、登录、项目列表、一次 AT 执行与回调；失败时按升级与回滚恢复。

omni-server 与 omni-worker 必须使用同一版本；Jenkins agent 上的引擎版本应与平台侧任务构造协议匹配。

已知不兼容

  • 旧插件模板导入 omni.engine.base / omni.engine.registry，当前代码为 omni.core.base / omni.core.registry；旧模板生成的插件需改导入路径。
  • 项目路由 /project/ipd/* 已下线且不提供重定向，升级后需改用 /project/*。
  • 引擎 platform/protocol.py 的 /api/v1/at/... 契约与 omni-server 当前 /at/... 路径存在前缀差异，接入时需在网关或客户端对齐。
  • 原文档站 /v1.1.2/... 链接已失效，新站点使用根路径与相对链接。

升级前建议先在测试环境走完“迁移 → 启动 → 登录 → 执行 → 回调 → 报告”闭环，再操作生产。
