平台集成

内容状态：基于代码与文档整理，待产品负责人复核。

omni-engine 与 omni-server 通过 HTTP 与 WebSocket 协同。协议模型在 omni/integrations/platform/protocol.py，HTTP 客户端在 client.py。生产链路为 server → Jenkins → agent → engine；下图是协议视角。

omni-server  ── POST /api/v1/at/execute ──────────────►  omni-engine
omni-engine  ── GET  /api/v1/at/envs/{env_id} ────────►  omni-server
omni-engine  ── POST /api/v1/at/cases/callback ───────►  omni-server
omni-engine  ── POST /api/v1/at/tasks/callback ───────►  omni-server
omni-engine  ── WebSocket 步骤进度 ───────────────────►  omni-server

路径与认证

用途方法与路径客户端方法
任务调度POST /api/v1/at/executedispatch_task()
环境注入GET /api/v1/at/envs/{env_id}fetch_env()
用例回调POST /api/v1/at/cases/callbackcallback_case()
任务回调POST /api/v1/at/tasks/callbackcallback_task()
用例同步POST /api/at/cases/sync-codesync_cases()
登录POST /api/system/permission/auth/login_login()
WS 进度由调用方传入 WebSocket URLreport_progress()

注意前缀差异：平台协同接口是 /api/v1/at/...，用例同步与登录在 /api/... 下。客户端用 x-token 头认证，可传现成 token，也可用用户名密码先登录换取 JWT。

平台当前实际只注册了统一回调 POST /at/executions/callback，按 CASE/DONE 分流；上表的 /api/v1/at/cases/callback 与 /api/v1/at/tasks/callback 是引擎协议模型中的路径，接入时需在客户端或网关做路径映射。平台侧字段与分流规则见回调协议。

TaskDispatch

任务调度请求体。平台侧用它下发任务；引擎侧 PlatformClient.dispatch_task() 可按同一契约向平台登记或发起任务，生产链路仍以平台调度为准。

字段类型说明
task_idstr平台任务执行 ID
spec_pathstrSpec 文件路径，与 case_ids 二选一
case_idslist[int]平台用例 ID 列表
testbedstr测试环境标识
env_idstr环境配置 ID，用于上下文注入
paramsdict执行参数，如 max_workers
tenantstr默认租户，可选

to_dict() 会省略空字符串、空列表和空字典。spec_path 与 case_ids 至少提供一个，否则无法确定执行对象。引擎侧提供 pytest 批处理、Spec/API 单条与 suite run 混合套件入口，平台按用例形态选择；后续回调统一用 task_id 关联。

EnvContext

GET /api/v1/at/envs/{env_id} 的响应模型，from_dict() 同时接受驼峰与下划线字段。

字段类型说明
env_idstr环境 ID
namestr环境名称
base_urlstr主服务地址
endpointsdict子系统到 base_url 的映射
tenantsdict租户到凭据的映射
variablesdict全局变量
clusterstrK8s 集群上下文

apply_to(context) 把 base_url、cluster、tenants、endpoints、variables 注入 RunContext；端点写入 subsystems 时使用 setdefault，不覆盖已有配置。

WS 进度

ProgressReport 是步骤级进度消息：task_id、type（STEP/CASE/TASK）、step_id、status（RUNNING/PASSED/FAILED）、duration_ms、step_type、message、progress（total/current/failed）。report_progress() 每次建立短连接发送一条消息，在未配置 WS 地址或发送失败时返回 False，不阻塞执行；该能力依赖可选的 websocket-client。

pytest 的 omni-case-callback 插件按 --callback 指定的 URL 上报脚本身份（file_path、class_name、method_name），由平台反查用例；它与上面的 CaseCallback 模型是两条链路，字段差异见平台侧回调协议。

用例同步：全量与增量

全量同步扫描 test_*.py，生成清单并推送：

omni-engine-cli sync --server <platform-url> --token <token> --product-id <product-id> --project-root <project-root>

增量同步用基线文件记录 {file_path: contentHash}，只推送变更用例：

omni-engine-cli sync --server <platform-url> --token <token> --product-id <product-id> --project-root <project-root> --incremental --baseline ./sync-baseline.json

--product-id 是禅道产品 ID，必填；也可用 --username、--password 代替 --token。无禅道用例 ID 的用例会被跳过，不上传为孤立数据。全量同步会按目录模块统计用例数；增量同步只推送 contentHash 变化的用例，并在推送成功后合并更新基线。--dry-run 只预览清单，--json 只输出扫描结果，两者都不会写基线；--project-id 默认 1。

从仓库生产用例并推送平台的完整流程（含脱敏命令与两次确认）见 Skills 全流程自动化 和 安装与运行。

UnifiedReport

多引擎结果统一报告，add_result() 自动累加计数与 engine_summary，finalize() 写入结束时间。

字段类型说明
task_idstr任务执行 ID
start_time / end_timeint毫秒时间戳
total / passed / failed / skippedint汇总计数
engine_summarydict引擎类型到统计的映射
resultslist[dict]逐条结果

results 的每条记录包含 case_name、status、duration_ms、engine、step_types、error_msg 以及调用方传入的扩展字段。to_dict() 输出驼峰键，如 taskId、startTime、engineSummary，便于平台直接消费。
