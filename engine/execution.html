执行与编排

内容状态：基于代码与文档整理，待产品负责人复核。

引擎的本地执行入口是 omni-engine-cli。平台内执行由 omni-server 经 Jenkins 下发，最终同样落到这些入口。单条脚本、配置文件用例与 AI 自然语言用例可以放进同一个 suite.yaml，按选择顺序逐条执行。

入口选择

场景命令
按 testconf 批量跑 pytestomni-engine-cli -f ./conf/debug.yaml
单个 pytest 文件omni-engine-cli pytest run ./testcase/test_api.py
YAML Specomni-engine-cli spec run ./specs/demo.yaml
JSON 接口用例omni-engine-cli api run ./cases/httpbin_api.json
混合套件omni-engine-cli suite run ./suite.yaml
AI 自然语言用例omni-engine-cli ai run --content "<自然语言>"

spec、suite、pytest run、api run 的用例路径都是位置参数。-f 与 --test_conf_path 等价；默认值仍指向旧的 ./demo/conf/demo.xml，但示例工程已拆分为 demo_minio 与 demo_saucedemo，请显式传入配置路径。

混合套件

desc: 混合套件
base_url: https://httpbin.org
case_list:
  - {type: script, location: ./testcase/test_echo.py, case_id: 101}
  - type: config
    case_id: 102
    content: |
      name: 脚本化配置用例
      steps:
        - id: 1
          name: 等待
          action: sleep
          sleep: 0.1
  - {type: ai, content: "打开登录页并断言登录成功", case_id: 103}

case_list 严格按声明顺序执行，不按类型分组。script 走单文件 pytest，config 走 Spec/传统配置通道，ai 走 LLM 生成 Spec 后由 StepExecutor 执行。testbed 可选，未写 base_url 时取 testbed 第一个环境的 endpoint 或 params.base_url。AI 条目需要真实 LLM；未配置时该条报错，不会静默通过。

omni-engine-cli suite run ./suite.yaml --json-report-file ./suite-result.json \
  --callback <callback-url> --callback-task-id <task-id>

输出两段纯文本 JSON：「套件结果：」为汇总，「套件明细：」逐条含 case_id、type、status。任一条失败或报错时进程退出码为 1。

并行

维度机制入口
用例级pytest-xdist 多进程OMNI_WORKERS=N / pytest -n=N
集合级ThreadPoolExecutorApiExecutor.execute_batch(cases, concurrency=N)
步骤级depends_on 拓扑分层StepExecutor(config={"max_workers": N})
OMNI_WORKERS=4 OMNI_DIST=loadscope omni-engine-cli -f ./conf/debug.yaml
OMNI_RERUNS=2 omni-engine-cli -f ./conf/debug.yaml

OMNI_DIST 默认 loadscope；OMNI_RERUNS 需要 pytest-rerunfailures，且与 flexreport 不兼容，启用重试时应关闭 flexreport。共享浏览器、数据库或环境的用例加 @pytest.mark.serial，框架会将其归组到同一 worker。pytest 直跑不读取 OMNI_WORKERS，需显式传 -n 与 --dist。

默认串行执行按用例或步骤的声明顺序；并行模式下，Spec 的 depends_on 用于分层，层内并行、层间按依赖顺序，依赖环会报 SpecValidationError。三层并发可叠加，但资源开销按乘积增长。

结果与退出码

CLI 的 pytest 通道输出「测试结果：」JSON 摘要（total/passed/failed/error/skipped/pass_rate/duration）；suite run 输出套件汇总与明细；spec run 逐步打印通过/失败并汇总。api run、api batch、spec run、suite run 在存在失败或错误时以非 0 退出，便于 CI 判定；pytest 通道的退出码沿用 pytest 语义。--collect-only 只收集不执行，适合在正式运行前确认用例清单与 node ID。

执行前确认 testconf、testbed、testset 的路径与相对位置，环境地址与凭据已注入；执行后检查报告目录与用例日志。若需要平台回收结果，传入 --callback 与 --callback-task-id，字段与认证见平台集成。

报告路径、Allure 与并行合并见报告，平台回调见平台集成。
