AI 能力

内容状态：基于代码与文档整理，待产品负责人复核。

AI 子系统分为两层：LLM 层调用 OpenAI 兼容接口，关键词层在 LLM 不可用时降级。未配置 api_key 时使用 MockProvider，它只返回固定的通过/未知结果，适合离线调试，不能当作真实分析。真实能力需安装 pip install "omni-engine[ai]" 并配置 OPENAI_API_KEY（或 settings.ini [AI] api_key），也可用 OPENAI_BASE_URL 指向兼容端点。

四项基础能力

能力入口说明
失败分析AIAnalyzer.analyze(result)分类为 BUG/ENV/SCRIPT/DATA/UNKNOWN，给出根因、置信度、严重性与建议；LLM 不可用时按关键词匹配
元素自愈LocatorHealer.heal(locator, dom_snapshot)先查缓存，再由 LLM 根据 DOM 推断新定位器；无 LLM 时返回未修复
数据生成DataGenerator按字段名与类型生成测试数据，可批量生成
语义断言AIValidator.semantic/schema/llm_judge自然语言语义匹配、Schema 校验与 LLM 裁判

失败分析结果会写入 StepResult.ai_meta，并进入报告。BaseEngine 还暴露 on_locator_failure、on_step_failure、on_assert_failure、on_data_prepare 四个钩子，见自定义引擎。

from omni.core.ai import AIAnalyzer, LocatorHealer

analysis = AIAnalyzer.analyze(result)
print(analysis.category, analysis.root_cause, analysis.confidence)

fixed = LocatorHealer().heal("#login-btn", dom_snapshot=html)
print(fixed.healed, fixed.new_locator)

用例生成与执行

SpecWriter 把自然语言转成 Spec YAML，SpecHealer 对失败 Spec 给出根因与修复建议。CLI 的 ai write 生成文件，ai run 则走完整执行通道：自然语言 → LLM 生成 Spec → SpecCompiler 校验 → StepExecutor 执行。ai run 不是 pytest 通道；未配置真实 LLM 时直接报错退出，不会静默通过。

omni-engine-cli ai write --text "测试用户登录接口，验证返回 token 非空" \
  --output ./specs/login.yaml
omni-engine-cli spec run ./specs/login.yaml
omni-engine-cli ai run --content "打开登录页，输入用户名密码，断言登录成功"

ai run 也接受位置参数用例文件或 --file。suite.yaml 中 type: ai 的条目复用同一通道，需要 LLM。

webai 四 Agent

webai 把 Web 用例生产拆成四个 Agent：

Agent命令产物
Plannerwebai planspecs/plan.md 测试大纲
Designerwebai testcasetestcases/*.md 与 case.csv
Generatorwebai generate页面对象与 test_*.py
Healerwebai heal执行失败分类、修复建议、修复报告
omni-engine-cli webai run --url https://www.saucedemo.com --output ./webai-out
omni-engine-cli webai plan --url https://www.saucedemo.com --prd ./prd.md -o ./plan.md
omni-engine-cli webai generate --plan ./plan.md --output ./tests
omni-engine-cli webai heal --tests ./tests

webai run 串联探索、生成、执行与自愈，支持 --request、--seed、--prd。webai generate 的输入是计划文件，不是 URL；旧文档中的 webai generate --url ... --task ... 与当前参数不符。probe（顶层命令或 webai probe）用于页面元素探查，必须提供 --page 与 --url。

配置与降级

优先级为：构造或 set_provider() 注入的自定义 Provider > OpenAIProvider（配置了 key）> MockProvider。环境变量 OPENAI_API_KEY、OPENAI_MODEL、OPENAI_BASE_URL、OPENAI_TIMEOUT 优先于 settings.ini [AI]。LLM 调用失败、超时或返回不可解析内容时，各组件按自身策略降级：SpecWriter 生成模板 Spec，AIAnalyzer 回退关键词匹配，自愈返回未修复。ai run 例外，它要求真实 LLM，未配置时直接失败。

边界

AI 生成的用例、定位器与修复建议必须人工评审后再入库；语义断言适合模糊匹配，核心业务与安全断言仍用精确断言。AI 产物可能引入无关依赖、弱断言或数据污染，评审时重点检查断言有效性、数据隔离与是否包含硬编码。所有 AI 能力的行为与降级结果以当前版本为准。

与 Skills 体系的分工

webai 四 Agent 适合从 URL 快速探索、生成原型用例和做临时回归；Skills 体系适合需要禅道同步、用例 ID 追溯、质量门与平台推送的工程化流程。两者共用 Spec、StepExecutor、报告与回调能力，可以按阶段混用。完整流程见 Skills 全流程自动化。
