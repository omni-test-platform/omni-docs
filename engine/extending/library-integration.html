作为库集成

内容状态：基于代码与文档整理，待产品负责人复核。

本页讲“自有 pytest 工程引入引擎作为依赖”的场景，与在引擎工程内编写用例不同：后者使用引擎仓库自带的 demo、配置与目录约定；前者保留自己的工程结构，只复用 TestCaseBase、断言、配置加载与报告能力。

安装与自动加载

在项目虚拟环境中安装发布包：

pip install omni-engine

引擎的 setup.py 注册了 pytest11 入口（omni-engine、omni-json-report、omni-case-callback），安装后 pytest 会自动加载框架插件，不需要在 conftest.py 中手动 -p。建议锁定版本（如 omni-engine==<version>），避免 CI 与本地解析到不同构建。

继承 TestCaseBase

from omni.common.case import TestCaseBase


class TestHealth(TestCaseBase):
    def test_status(self, api_base_url):
        import requests

        response = requests.get(f"{api_base_url}/health", timeout=5)
        self.assertEqual(response.status_code, 200)
        self.assertIn("ok", response.text)

TestCaseBase 复用 unittest 风格的断言（assertEqual、assertTrue、assertIn、assertIsNone、assertGreater、assertRegex 等），并由 CaseMetaClass 自动包装 test_* 方法。日志直接使用 from loguru import logger；引擎不会向用例实例注入 self.logger。需要业务基类时，可以先继承 TestCaseBase 再派生项目基类，与 demo 的做法一致。

配置覆盖

引擎启动时会读取 settings.ini，再按项目 conf/settings.ini 增量覆盖。pytest 直跑时，需要在 conftest.py 中指定 testconf，否则 GlobalContext 不知道测试床与测试集：

import os
from omni.context import GlobalContext

if not GlobalContext.test_conf_path:
    GlobalContext.test_conf_path = os.path.join(
        os.path.dirname(os.path.abspath(__file__)), "conf", "debug.yaml"
    )

testconf 只负责引用测试床与测试集，最小结构如下：

description: local
testbed: conf/testbed/local.yaml
testset: conf/testset/smoke.yaml

testbed 定义环境地址与凭据，testset 定义 case_list 的 location。凭据放在项目级 conf/settings.ini 或环境变量中，不要提交到版本库。报告开关可用 --reports=allure,rf 或 OMNI_REPORT_* 环境变量临时覆盖。

目录约定

推荐保留 testcase/（用例）、conf/（testconf、testbed、testset 与 settings.ini）、data/（数据）与 reports/（产物）四类目录。引擎不要求固定目录名，testconf 的 testset 决定收集范围；把配置与用例分开，可以让同一套用例通过切换 testconf 在本地、CI 与平台任务之间复用。

fixtures

pytest fixture 与普通工程完全一致，适合共享会话、Token 与客户端：

import os
import pytest


@pytest.fixture(scope="session")
def api_base_url():
    return os.environ.get("API_BASE_URL", "http://127.0.0.1:9000")


@pytest.fixture(scope="session")
def auth_token(api_base_url):
    token = os.environ.get("API_TOKEN", "")
    yield token

用例方法可以直接声明 def test_x(self, api_base_url, auth_token)。需要清理的资源放在 yield 之后；类级前后置使用 setup_class / teardown_class，方法级使用 setup_method / teardown_method，重载 setup_method 时调用 super().setup_method(method) 保留截图收集列表的重置逻辑。

通过 pytest 或 CLI 触发

在项目根目录直接运行 pytest：

pytest testcase -q

也可以使用引擎的单文件执行通道，命令会输出「测试结果：」JSON 摘要，便于 CI 解析：

omni-engine-cli pytest run testcase/test_health.py

按 testconf 批量执行时使用根命令，-f 等价于设置 GlobalContext.test_conf_path：

omni-engine-cli -f conf/debug.yaml

CI 集成

python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pytest testcase --junitxml=reports/junit.xml

Windows 激活脚本为 .venv\Scripts\activate。CI 中建议固定引擎版本、把 conf/ 作为受控配置注入、归档 reports/ 与日志目录；报告格式的选择与 Allure 回退见报告，并行与批量执行见执行。
