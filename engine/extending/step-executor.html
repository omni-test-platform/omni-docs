步骤执行器

内容状态：基于代码与文档整理，待产品负责人复核。

步骤执行器是路径 A/B 中的轻量扩展。ApiRunner 遇到非 API、非 CASE_REF 的 step_type 时，会从 ExecutorRegistry 取出对应执行器并调用 execute(step, context)。它适合“单个命令、一次查询、一段脚本”这类原子动作；需要独立连接池或复杂生命周期的能力，写成自定义引擎更合适。

基类与最小实现

from typing import Any, Dict

from omni.core.base import StepResult
from omni.drivers.api.models import TStep
from omni.drivers.api.step_executors.base import BaseStepExecutor, ExecutorRegistry


@ExecutorRegistry.register
class UppercaseExecutor(BaseStepExecutor):
    step_type = "UPPERCASE"

    def execute(self, step: TStep, context: Dict[str, Any]) -> StepResult:
        text = step.command or ""
        return StepResult(
            success=True,
            step_name=step.step_name or step.sid,
            step_type=self.step_type,
            data={"text": text.upper()},
        )

@ExecutorRegistry.register 是裸装饰器写法，自动读取 step_type；也可以写成 @ExecutorRegistry.register("UPPERCASE")。execute() 是抽象方法，必须返回 StepResult。基类提供 _handle_exception(step, exc)，可把异常统一包装为失败结果：

def execute(self, step: TStep, context: Dict[str, Any]) -> StepResult:
    try:
        ...
    except Exception as exc:
        return self._handle_exception(step, exc)

注册表与分发

ExecutorRegistry 的分组是 omni_engine.executors，发现时会校验对象必须是 BaseStepExecutor 子类。常用查询方法有 get(step_type)、list()、is_registered()、all_types()，以及兼容别名 has()。

ApiRunner 的分发逻辑在 __run_step()：当 step.step_type 不是 API 或 CASE_REF 时，先 ExecutorRegistry.get(step_type)，再以无参方式实例化执行器。传入的 context 包含 runner（当前 ApiRunner）、session（HttpSession）、variables（当前变量映射）与 project_meta。执行器的返回值会被包装成 StepData，继续参与断言、提取与报告流程。

编写建议

执行器应保持无状态：每次 execute() 都从 context 取当前 runner、session 与 variables，不要缓存上一次步骤的数据；需要跨步骤传递时写入 StepResult.export_vars。命令、脚本等可能产生大量输出的步骤，建议截断后放入 data，完整内容写日志或附件，避免报告体积失控。超时、编码与工作目录应显式处理，不要依赖运行机器的默认值。

内置执行器

执行器step_type用途
ShellExecutorSHELL本地或远程 Shell 命令
ScriptExecutorSCRIPTPython 内联脚本
SleepExecutorSLEEP等待指定秒数
SQLExecutorSQLMySQL / SQLite 查询与更新
GrpcExecutorgRPCgRPC 调用
WsExecutorWebSocketWebSocket 通信

这些类型由 omni.drivers.api.step_executors 包导入时自动注册。自定义执行器应避免与它们重名；重复键会覆盖并输出警告。内置执行器只覆盖通用场景，业务专用动作应放在自定义执行器或适配器中，不要修改框架内置类。

entry_points 发布

独立分发的插件包在 setup.py 中声明：

entry_points={
    "omni_engine.executors": [
        "uppercase = my_package.steps:UppercaseExecutor",
    ],
}

pytest 启动时 discover_all() 会加载该分组。若只是本地验证，直接构造步骤并调用注册表即可：

from omni.drivers.api.models import TStep

step = TStep(
    id=1,
    sid="upper_1",
    step_name="转大写",
    step_type="UPPERCASE",
    command="hello",
)
executor = ExecutorRegistry.get("UPPERCASE")()
result = executor.execute(step, {})
assert result.success and result.data["text"] == "HELLO"

注意 step_type 必须是唯一字符串；API 与 CASE_REF 由 ApiRunner 自己处理，不会进入执行器注册表。执行器应捕获可预期异常并返回失败结果，避免未处理异常中断整条用例。
