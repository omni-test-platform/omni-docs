自定义引擎

内容状态：基于代码与文档整理，待产品负责人复核。

当你要新增一类测试执行能力（数据库、消息队列、自定义协议等），并且它有自己的连接、会话或资源生命周期时，使用 BaseEngine。只处理单个轻量步骤时，优先考虑步骤执行器；为了让 YAML 的 action 可执行，使用Spec 适配器。

最小实现

子类必须设置唯一的 step_type，并实现 run_step(step_data) -> StepResult：

from typing import Any

from loguru import logger

from omni.core.base import BaseEngine, StepResult
from omni.core.registry import EngineRegistry


@EngineRegistry.register("ECHO")
class EchoEngine(BaseEngine):
    step_type = "ECHO"
    description = "回声引擎"

    def run_step(self, step_data: Any) -> StepResult:
        logger.info("echo step: {}", step_data)
        return StepResult(
            success=True,
            step_name="echo",
            step_type=self.step_type,
            data=step_data,
            export_vars={"last_echo": step_data},
        )

注册有三种写法：@EngineRegistry.register("ECHO") 显式指定键；@EngineRegistry.register() 或裸装饰器 @EngineRegistry.register 自动读取 step_type；独立分发的包则在 setup.py 中声明 omni_engine.plugins = echo = my_package.echo:EchoEngine。同一 step_type 被重复注册时，后注册的类会覆盖前一个并输出警告，因此键要保持全局唯一。

生命周期

钩子类型时机
setup_class()classmethod当前类所有用例执行前
setup()实例方法每个用例或步骤执行前
run_step()实例方法执行单个步骤，必须实现
teardown()实例方法每个用例或步骤执行后
teardown_class()classmethod当前类所有用例执行后

start() / end() 是 setup() / teardown() 的兼容别名。四个钩子都可选重载；框架在对应执行路径中调用它们，如果你直接实例化引擎，需要自行调用 setup() 与 teardown()。BaseEngine 已经使用 StepMetaClass，子类方法自动获得步骤日志与 Allure 步骤层级，不要重复声明元类。

StepResult

所有路径都返回同一结果类型，失败时也应返回 success=False 的对象，而不是把异常抛给上层：

字段说明
success是否成功
step_name / step_type步骤名与类型标识
statusTestStatusEnum 值
data原始结果，如响应对象、查询结果
export_vars导出到上下文的变量
error失败或异常信息
duration耗时（秒）
ai_metaAIAnalysisMeta，失败分类、根因与建议

四个 AI 钩子

钩子返回用途
on_locator_failure(locator, dom_snapshot="", screenshot=None)Optional[str]元素定位失败时返回修复后的定位器
on_step_failure(step, result, context=None)Optional[dict]步骤失败时返回分类、根因、置信度与建议
on_assert_failure(actual, expected, context=None)Optional[dict]断言失败时返回原因与建议
on_data_prepare(schema)dict按 schema 生成测试数据，返回空字典表示不使用

默认实现分别返回 None、None、None、{}。它们由上层在对应事件发生时调用，未启用相关 AI 能力时不影响普通执行。

注意事项

BaseEngine 不注入 self.config 或 self.logger。需要配置时，通过无参构造之外的显式注入、类属性，或读取 GlobalContext / SettingsService；日志使用模块级 loguru.logger。如果引擎会被 Spec 适配器通过 runner_cls() 无参实例化，构造函数不要要求必填参数。验证时可以写一个最小测试：

from omni.core.registry import EngineRegistry

engine = EngineRegistry.get("ECHO")()
result = engine.run_step({"hello": "world"})
assert result.success and result.data == {"hello": "world"}
