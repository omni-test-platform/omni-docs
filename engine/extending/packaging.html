打包与发布

内容状态：基于代码与文档整理，待产品负责人复核。

omni-plugin 脚手架目前只生成引擎插件（omni_engine.plugins）；步骤执行器、Spec 适配器、报告器与通知器需要手动在 setup.py 中增加对应分组。脚手架源码在 omni/plugin/template.py，CLI 入口为 omni.plugin.__main__。

创建与验证

在准备存放插件的目录执行：

python -m omni.plugin create smoke_plugin
pip install -e smoke_plugin
python -m omni.plugin list

也可以先 cd smoke_plugin 再 pip install -e .。list 应在内建引擎之外显示自定义项（节选）：

已注册的引擎:
  [API] omni.drivers.api.api_runner.ApiRunner
  [SMOKEPLUGIN] smoke_plugin.engine.SmokePluginRunner
  [WEB] omni.drivers.web.web_runner.WebRunner

该链路要求当前 Python 环境已安装 omni-engine；若引擎来自源码且未安装，先执行 pip install -e <omni-engine 源码目录>。脚手架还支持 --desc / -d 与 --output-dir / -o。

生成结构：

smoke_plugin/
├── setup.py
├── README.md
└── src/smoke_plugin/
    ├── __init__.py
    └── engine.py

engine.py 中的 step_type 为 SMOKEPLUGIN，类名为 SmokePluginRunner，导入路径是 omni.core.base / omni.core.registry。模板生成的 entry point 为 smoke-plugin = smoke_plugin.engine:SmokePluginRunner；安装后 python -m omni.plugin list 会先执行自动发现，应直接显示 [SMOKEPLUGIN] ...。如果使用旧模板生成的包仍把 entry point 指向模块路径，列表会提示“不是合法插件类型，跳过”，把值改为 模块:类 后重新安装即可。

五组 entry_points

分组注册表取键属性示例值
omni_engine.pluginsEngineRegistrystep_typemy_engine = pkg.engine:MyEngine
omni_engine.executorsExecutorRegistrystep_typemy_step = pkg.steps:MyExecutor
omni_engine.adaptersAdapterRegistryaction_typemy_action = pkg.adapters:MyAdapter
omni_engine.reportersReporterRegistrynamemy_report = pkg.reporter:MyReporter
omni_engine.notifiersNotifierRegistrynamemy_channel = pkg.notifier:MyNotifier

一个包可以同时声明多组，只保留实际实现的分组即可：

from setuptools import setup, find_packages

setup(
    name="my-omni-plugin",
    version="0.1.0",
    packages=find_packages("src"),
    package_dir={"": "src"},
    python_requires=">=3.9",
    install_requires=["omni-engine>=1.1,<2"],
    entry_points={
        "omni_engine.plugins": ["my-engine = my_pkg.engine:MyEngine"],
        "omni_engine.executors": ["my-step = my_pkg.steps:MyExecutor"],
    },
)

key 必须全局唯一，重复注册会覆盖并输出警告。开发期用 pip install -e .；发布时用 python -m build 生成 dist/*.whl，再 pip install dist/<wheel>。

版本与依赖

插件版本从 0.1.0 起独立演进，install_requires 应同时约束引擎与自身第三方依赖；升级引擎时先在小范围 agent 验证，再批量发布。发布前应在干净虚拟环境执行一次 create、install、list 闭环。不要把引擎源码目录、虚拟环境或 wheel 缓存提交到插件仓库，dist/、*.egg-info/ 与 __pycache__/ 应加入忽略列表。

私有源与离线安装

pip install --index-url https://<private-index>/simple my-omni-plugin

也可以使用 --extra-index-url、PIP_INDEX_URL 或 pip.conf 指向私有源。凭据通过环境变量、keyring 或本机配置注入，不要写入仓库。无外网时先在有网机器构建 wheel，再在目标机执行：

pip install --no-index --find-links ./wheels my_omni_plugin-0.1.0-py3-none-any.whl

部署到 Jenkins agent

在 agent 上激活与 omni-engine 相同的虚拟环境，安装 wheel，然后重启 agent 或重新触发 Jenkins job：

pip install --no-index --find-links ./wheels my_omni_plugin-0.1.0-py3-none-any.whl
python -m omni.plugin list

entry_points 来自已安装包的元数据，只把源码目录加到 PYTHONPATH 不会被发现。多 agent 环境需要逐台安装，或把插件烘进执行机镜像。Jenkins 通道的参数、共享存储与联调步骤见部署 Jenkins 通道。

发布前应声明 __omni_compat__ 并固定引擎版本范围；插件单测、注册表自检与常见错误见兼容性与测试。
