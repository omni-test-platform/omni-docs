兼容性与测试

内容状态：基于代码与文档整理，待产品负责人复核。

插件发布后要面对引擎升级与多插件共存。引擎提供 __omni_compat__ 版本声明、on_load / on_unload 生命周期与 unregister()；测试侧建议覆盖“注册成功、唯一键、结果契约、entry_points 可发现”四件事。五类注册表的定义见扩展开发总览。

版本声明

插件类可以声明兼容的框架版本：

from omni.core.base import BaseEngine
from omni.core.registry import EngineRegistry


@EngineRegistry.register("ECHO")
class EchoEngine(BaseEngine):
    step_type = "ECHO"
    __omni_compat__ = "1.1"

    def run_step(self, step_data):
        ...

发现时只比较 major.minor。版本不一致会输出“框架当前 X，插件声明兼容 Y”的警告，但不会阻止注册；声明无法解析时按兼容处理。因此它适合作为升级提示，不能替代依赖约束；setup.py 仍应写 install_requires=["omni-engine>=1.1,<2"]。当前引擎版本为 1.1.2，对应兼容声明 1.1。

生命周期

钩子时机说明
on_load()entry_points 发现并注册后定义为 classmethod；异常只记录警告
on_unload()unregister(key) 移除时（先从注册表弹出，再调用）释放连接、注销外部资源；异常只记录警告
@EngineRegistry.register("ECHO")
class EchoEngine(BaseEngine):
    step_type = "ECHO"

    @classmethod
    def on_load(cls):
        ...

    @classmethod
    def on_unload(cls):
        ...
EngineRegistry.unregister("ECHO")  # 返回 True；键不存在返回 False

unregister() 的键是注册键（引擎为 step_type，适配器为 action_type，报告器/通知器为注册名），不是类名或 entry point 名。仅用装饰器注册不会触发 on_load，只有 discover() 路径会调用；如果初始化逻辑必须在两种方式下都执行，把它放到模块导入时或显式调用。

插件单测

注册表是进程级字典，测试时要隔离并恢复，避免影响其它用例：

import pytest

from omni.core.base import BaseEngine, StepResult
from omni.core.registry import EngineRegistry


@pytest.fixture
def isolated_engine_registry():
    saved_store = dict(EngineRegistry._store)
    saved_discovered = EngineRegistry._discovered
    EngineRegistry._store.clear()
    EngineRegistry._discovered = False
    yield
    EngineRegistry._store.clear()
    EngineRegistry._store.update(saved_store)
    EngineRegistry._discovered = saved_discovered


def test_echo_engine(isolated_engine_registry):
    @EngineRegistry.register("ECHO")
    class EchoEngine(BaseEngine):
        step_type = "ECHO"

        def run_step(self, data):
            return StepResult(
                success=True,
                step_name="echo",
                step_type=self.step_type,
                data=data,
            )

    assert EngineRegistry.get("ECHO") is EchoEngine
    result = EchoEngine().run_step({"x": 1})
    assert result.success and result.data == {"x": 1}

执行器、适配器、报告器、通知器用同样的方式操作各自的 _store。五张表相互独立，同名键不会互相污染。除了单元测试，还应在干净虚拟环境中安装 wheel，然后用 python -m omni.plugin list（引擎）或 discover_all()（五类）验证 entry_points 确实可发现。

注册表自检

from omni.core.plugin_manager import discover_all
from omni.core.registry import EngineRegistry

result = discover_all()
print(result)
print(sorted(EngineRegistry.list_engines()))

discover_all() 返回 {分组名: 发现数量}，正常情况下包含 omni_engine.plugins、omni_engine.adapters、omni_engine.executors、omni_engine.reporters、omni_engine.notifiers 五个键。发现幂等，第二次调用时各分组返回 0；安装新插件后传 force=True 或重启进程。Python 3.9 上 importlib.metadata.entry_points(group=...) 可能不可用，发现会被静默跳过并返回 0，此时改用装饰器注册或升级到 3.10+。

常见错误

现象原因处理
ModuleNotFoundError（旧版引擎模块前缀）使用重构前的导入路径改为 omni.core.base / omni.core.registry
必须设置 step_type 或 action_type类未声明键，或对 Reporter/Notifier 用了裸装饰器补属性；报告器/通知器显式传键
不是合法插件类型，跳过entry point 指向模块，或基类不匹配写成 pkg.module:Class，并继承正确基类
版本不兼容 警告__omni_compat__ 与当前 major.minor 不一致调整声明或引擎版本
已被 ... 注册，将被 ... 覆盖多个插件使用同一键改为唯一键
list 中没有插件未装进同一虚拟环境、发现已缓存或未重启pip install -e .、重启、force=True
on_load 未执行只用了装饰器注册显式调用初始化，或改用 entry_points
报告器/通知器被发现但未生效管理器仍使用函数式注册表/固定通道名在 on_load 中调用 register() 或手动发送

发现顺序不保证稳定；重复键以最后注册者为准。插件应保持无参可构造、失败返回 StepResult，并避免在 on_load 中执行不可恢复的阻塞操作。
