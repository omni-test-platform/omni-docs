通知器

内容状态：基于代码与文档整理，待产品负责人复核。

通知器负责在测试会话结束后发送一条结果摘要，与报告器“产出文件”的职责互补。引擎内建邮件、企业微信、钉钉、飞书与通用 Webhook 五种通道；新增通道需实现 Notifier.send() 并注册到 NotifierRegistry。报告器本身见报告器。

接口与最小实现

from omni.notification.base import Notifier, NotifierRegistry


@NotifierRegistry.register("my_channel")
class MyNotifier(Notifier):
    name = "my_channel"

    def send(self, subject: str, body: str, **kwargs) -> bool:
        try:
            # 在此调用你的 Webhook、IM API 或内部网关
            return True
        except Exception:
            return False

send() 必须返回布尔值；通道名同时作为注册键。管理器会用 cls(**kwargs) 实例化通道，因此构造函数应接受关键字参数并给出默认值。注意装饰器要显式传键：@NotifierRegistry.register("my_channel") 是正确写法；裸装饰器只会查找 step_type / action_type，Notifier.name 不参与装饰器取键。

触发时机

pytest 会话结束时，engine_plugin 调用：

notify_report_result(GlobalContext.report_summary)

该函数读取 settings.ini 的 [NOTIFY] 段，按 notify_mode 决定是否发送：failure_only（默认，仅有失败或错误时发送）、always、off。正文包含总数、通过、失败、错误、跳过、通过率与耗时，并列出最多 20 条失败用例。没有 [NOTIFY] 配置或所有通道关闭时静默跳过，不抛异常。

注册与发现

NotifierRegistry 的分组是 omni_engine.notifiers，发现时校验对象必须是 Notifier 子类。entry_points 写法：

entry_points={
    "omni_engine.notifiers": [
        "my-channel = my_package.notifier:MyNotifier",
    ],
}

发现时键取 name 属性或 entry point 名。这里有一个当前实现的边界：create_notifiers() 只遍历内置的五个通道名（mail、qw_chat、webhook、dingtalk、feishu），因此仅通过 entry_points 发现的“全新通道名”不会自动被管理器实例化。要接入新通道，可在自己的会话钩子中取类并发送：

from omni.notification.base import NotifierRegistry

notifier = NotifierRegistry.get("my_channel")()
notifier.send("测试执行完成", "全部通过")

也可以注册为内置通道名来替换其实现，但这会全局覆盖内建通道，不建议在共享环境中使用。新增通道的配置键同样需要由调用方自行传入，管理器不会自动读取未知键。

注意事项

发送动作应设置超时并捕获异常，避免阻塞 CI；管理器还会再包一层异常保护，但通道内部失败应返回 False 以便统计。通知是“摘要级”能力，不适合传输大附件；详细结果应通过报告或平台查看。notify_mode=off 可以在不删除配置的情况下临时关闭。
