报告器

内容状态：基于代码与文档整理，待产品负责人复核。

报告器负责在执行过程中接收步骤、标题、附件与日志事件，并在结束时产出自己的报告文件。ReportManager 本身也是 Reporter，它把同一事件广播给所有启用的报告器，因此一次执行可以同时产出 Allure、RF 风格报告与日志 HTML。报告格式与产物的整体说明见报告。

Reporter 接口

方法说明
step(title)上下文管理器，标记一个报告步骤
dynamic_title(title)动态设置用例标题
dynamic_description(desc)动态设置用例描述
dynamic_label(label_type, value)设置 epic / feature / story / suite 等标签
dynamic_testcase(url, name)关联外部用例链接
attach(body, name, attachment_type="text")附加文本或文件
message(content, level="INFO")向当前步骤添加日志
set_module_hierarchy(hierarchy)设置模块层级
finalize(output_dir=None, formats=None, project_name=None)输出最终文件，返回退出码

只有 step() 是抽象方法，其余方法都有空实现。自定义报告器至少要实现 step()；需要产出文件时再实现 finalize()。

注册与管理

报告器有两层注册：

  • 函数式注册：omni.reporter.registry.register(name, enabled_key, factory)，内建 allure、rf、log 走这条路径，create_reporters(config) 按 enabled_key 决定是否实例化。
  • 类式注册：ReporterRegistry 接收 omni_engine.reporters 分组的 entry_points，用于第三方报告器发现。

GlobalContext 初始化时会调用 setup_reporter_from_config()，把 settings.ini 的 [REPORT] 配置传给 create_reporters()；get_reporter() 返回当前 ReportManager，执行结束时 finalize_reporter() 触发各报告器落盘。allure、rf、log 是 Reporter 实现；html、flexreport、json 是 pytest 插件开关，不属于 Reporter。

内建报告器

allure 通过 AllureReporter 写入 Allure 结果；rf 由 RfReporter 输出 HTML、JSON 或 xUnit；log 把日志转成 HTML。三者由 settings.ini 的 allure_enabled、rf_enabled、log_enabled 控制，实际默认值以项目配置为准。它们与自定义报告器共享同一套 Reporter 事件，因此新增报告器不会影响既有产物。

自定义报告器

from contextlib import contextmanager

from omni.reporter.base import Reporter
from omni.reporter.registry import ReporterRegistry, register


@ReporterRegistry.register("summary")
class SummaryReporter(Reporter):
    name = "summary"

    def __init__(self):
        self.lines = []

    @classmethod
    def on_load(cls):
        # 类被发现后，把它接入 ReportManager 使用的函数式注册表
        register("summary", "summary_enabled", lambda cfg: cls())

    @contextmanager
    def step(self, title):
        self.lines.append(f"STEP {title}")
        yield

    def attach(self, body, name, attachment_type="text"):
        self.lines.append(f"{name}: {body}")

    def finalize(self, output_dir=None, formats=None, project_name=None):
        print("\n".join(self.lines))
        return 0

entry_points 声明：

entry_points={
    "omni_engine.reporters": [
        "summary = my_package.reporter:SummaryReporter",
    ],
}

discover_all() 在 pytest 启动时发现该类并调用 on_load()，从而完成函数式注册；如果只在本地模块里用装饰器注册，on_load 不会自动执行，需要在导入时显式调用 register(...)。enabled_key 缺省为启用；要支持关闭，需要把 summary_enabled 放进传给 setup_reporter_from_config() 的配置字典，或在项目配置解析处补充该键。

注意事项

报告器会被 ReportManager 广播调用，方法应尽量轻量，避免在 step() 中做阻塞 I/O。finalize() 的返回值会作为退出码向上传递，成功返回 0。多个报告器按注册顺序依次进入 step()，退出顺序相反。报告器只负责产物，不负责发送通知；会话结束后的消息发送见通知器。
