扩展开发

内容状态：基于代码与文档整理，待产品负责人复核。

omni-engine 把可变能力收敛为五类注册表。扩展只需继承对应基类、声明唯一标识，再通过装饰器或 entry_points 注册，不需要修改框架源码。除插件机制外，还可以把引擎当作普通依赖嵌入自有 pytest 工程，见作为库集成。

五类扩展点

扩展点基类注册表entry_points 分组扩展内容主要路径
执行引擎BaseEngineEngineRegistryomni_engine.plugins新的 step_type 与测试执行域A/B，也可被适配器委托
步骤执行器BaseStepExecutorExecutorRegistryomni_engine.executorsApiRunner 内的原子步骤A/B
Spec 适配器ActionAdapterAdapterRegistryomni_engine.adaptersYAML action 到实现的映射C
报告器ReporterReporterRegistryomni_engine.reporters报告输出后端全路径
通知器NotifierNotifierRegistryomni_engine.notifiers会话结束后的通知通道全路径

代码中的导入路径分别为 omni.core.base、omni.core.registry、omni.drivers.api.step_executors.base、omni.spec.adapters、omni.reporter.base 与 omni.notification.base。重构前的旧导入前缀已删除，不再向后兼容。

选择指南

  1. 只是想在自有 pytest 工程里使用引擎：不需要写插件，按作为库集成安装并继承 TestCaseBase。
  2. 新增一类测试域（数据库、消息队列、自定义协议）：写自定义引擎，提供独立的 step_type、连接生命周期与 run_step()。
  3. 在现有 API 用例里插入一个轻量原子步骤：写步骤执行器，实现 execute(step, context)。
  4. 让 YAML Spec 中的新 action 可执行：写Spec 适配器。
  5. 改变报告产物：写报告器；只想在跑完后发消息：写通知器。

三者的边界容易混淆：引擎面向“一类测试能力”，通常持有连接或会话，输入是引擎自定义的 step_data；步骤执行器面向 ApiRunner 内部的单个非 API 步骤，输入是 TStep 与上下文字典；适配器只服务于 Spec 路径，负责把 SpecStep 转成 StepResult，也可以复用 DelegatingAdapter 把工作委托给某个引擎。报告器与通知器的区别是“产物”与“消息”：报告器参与执行过程并生成文件，通知器只在会话结束时发送摘要。

注册与自动发现

装饰器在模块导入时完成注册，适合本地开发或随包发布的插件：

from omni.core.base import BaseEngine, StepResult
from omni.core.registry import EngineRegistry


@EngineRegistry.register("ECHO")
class EchoEngine(BaseEngine):
    step_type = "ECHO"

    def run_step(self, step_data):
        return StepResult(
            success=True,
            step_name="echo",
            step_type=self.step_type,
            data=step_data,
        )

entry_points 适合独立分发的插件包，在 setup.py 中声明分组即可：

entry_points={
    "omni_engine.plugins": ["echo = my_package.echo:EchoEngine"],
}

五组分组与注册表一一对应，键分别取 step_type、action_type 或 name。omni.core.plugin_manager.discover_all() 会依次触发五组发现，返回 {分组名: 发现数量}；发现幂等，重复调用时各分组返回 0，需要重新扫描时传 force=True。pytest 启动时由引擎的 pytest_configure 自动调用一次，python -m omni.plugin list 也会先发现再列出引擎。

发现成功后，若插件类定义了 on_load，会被调用；unregister(key) 移除插件时会调用 on_unload。注意：仅用装饰器注册不会触发 on_load，只有 entry_points 发现路径会触发。生命周期、版本声明与测试方法见兼容性与测试，打包与安装见打包与发布。
