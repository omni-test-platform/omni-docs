执行引擎

内容状态：基于代码与文档整理，待产品负责人复核。

omni-engine 是 Omni 测试与质量平台的 Python 执行引擎，基于 pytest 构建，负责把测试用例、Spec 规范或平台下发的任务执行成可回传的结果。引擎要求 Python >= 3.9，采用 MIT 协议。

核心优势：Web 测试全流程自动化（Skills）

omni-engine 不只执行用例，还把测试工程流程本身产品化：技能包内置 12 个推荐的 omni-* 技能，覆盖「反向 PRD/设计 → 测试方案 → 禅道用例 → 回写 → 自动化编写 → 执行自愈 → 质量审查 → 推送平台」。由 Agent 按依赖图驱动，阶段产物落盘，支持断点续跑与全链路用例 ID 追溯。

两种使用方式

方式适用场景执行路径
平台内使用平台创建任务或计划，经 Jenkins 通道调度到执行机平台下发 → omni-engine-cli / pytest → 回调平台
独立使用自有测试项目、CI 流水线、本地调试omni-engine-cli、pytest、Python API

平台内使用时，引擎是平台的标准执行器，除执行外还承担用例同步、环境注入、结果回调与进度上报；独立使用时，它不依赖 omni-server，只需在虚拟环境中安装，由开发者自行组织用例、配置与报告。两种方式共用同一套用例、执行器和报告能力，差异主要在调度来源与结果去向。

能力全景

能力说明主要入口
API 测试HTTP 接口、断言、提取、数据驱动ApiRunner、api run
Web 测试Selenium 浏览器操作，元素与页面对象WebRunner
CLI/SSH本地命令与远程 SSH 执行CmdRunner
APP 测试Appium 移动端 UIAppRunner
DFX可靠性、可服务性等非功能场景用例与执行器组合
K8sPod、Deployment、CRD 操作与 HAMi 调度验证omni-engine[k8s]、action: k8s
混沌Chaos Mesh 故障注入与 Prometheus 稳态验证omni-engine[chaos]、action: chaos
性能Locust/k6 负载、SLA 断言与基线对比omni-engine[performance]、action: performance
混合编排单用例内混合 API、Web、SQL、CLI 等步骤Spec depends_on、suite run、EngineComposer
AI失败分析、元素自愈、Spec 生成与自愈omni-engine[ai]、webai、ai run
Skills 全流程自动化12 个 omni-* 技能覆盖需求到回归，支持禅道同步、用例 ID 追溯与平台推送omni-engine-cli skills 安装；Agent 调用 omni-pipeline
平台协同任务下发、环境注入、用例与任务回调、WS 进度、用例同步omni/integrations/platform/

K8s、混沌、性能与 AI 能力依赖对应的 extras；未安装时相关 action 不可用，API、Web、CLI、APP 等核心能力不受影响。平台协同能力需要 omni-server 及 Jenkins 通道配合。

运行形态

  • 命令行：omni-engine-cli 执行 XML 配置、Spec、API 用例、混合套件，或同步用例到平台。
  • pytest：直接收集 test_*.py，适合本地调试和既有 pytest 工程。
  • 库：在自有 pytest 工程中继承 TestCaseBase，把引擎作为依赖使用。

独立使用时，开发者需要自行维护 testconf、testbed、testset 或 Spec；平台内使用时，这些配置通常由平台按所选环境生成并随任务下发。

设计约束

  • 所有执行器都返回统一的 StepResult，上层据此做校验、提取、报告和回调。
  • 扩展通过注册表与 entry_points 完成，不修改框架源码。
  • 代码用例与 Spec 用例双模并存；平台下发时按任务选择 pytest、Spec/API 单条或混合套件入口。
  • 版本以产品版本 v1.1.2 为准，组件版本差异见兼容矩阵。
