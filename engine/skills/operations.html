安装与运行

内容状态：基于 omni-engine-cli skills、技能安装脚本与项目配置整理，待产品负责人复核。

本页面向第一次把 Skills 体系落到项目里的开发者或测试负责人。按“前置条件 → 安装 → 配置 → 发起 → 验证 → 排障”的顺序执行即可。

前置条件

依赖用途要求
Python 与 omni-engine执行技能、运行 pytest/CLIPython >= 3.9；pip install omni-engine
Agent 运行时加载 SKILL.md 并调度技能支持技能加载的 Agent；CLI 默认适配 AtomCode 目录
Node.js + zentao-cli阶段 3/4 的禅道访问Node.js >= 18；npm install -g zentao-cli
浏览器与驱动阶段 0/1/5 的页面实测与执行Chrome/Chromium + WebDriver；或 Playwright 环境
LLM（可选）AI 生成、分析、自愈OpenAI 兼容接口；未配置时部分能力降级
禅道账号用例库/产品读写具备用例库与产品用例权限
平台配置（可选）阶段 P 推送conf/settings.ini [PLATFORM] 或环境变量
网络访问被测页面、禅道、平台按团队网络策略放行

安装 Skills

pip install omni-engine 已包含技能包。安装到 Agent 的技能目录：

# 查看可安装技能
omni-engine-cli skills list

# 安装到全局（~/.atomcode/skills）
omni-engine-cli skills install --global

# 或安装到当前项目（./.atomcode/skills）
omni-engine-cli skills install --target ./.atomcode/skills

# 覆盖已有同名技能（升级技能包后使用）
omni-engine-cli skills install --global --force

# 开发调试：符号链接，技能包更新即时生效
omni-engine-cli skills install --target ./.atomcode/skills --link

说明：

  • 安装器只处理包含 SKILL.md 的 omni-* 目录。当前技能包共 14 个目录：12 个推荐技能 + omni-test-plan、omni-case-write 两个通用技能。Web 场景使用 omni-web-* 版本。
  • --target 缺省为当前目录下的 .atomcode/skills；--global 安装到 ~/.atomcode/skills。
  • 安装后需要新开 Agent 会话，技能才会被加载。
  • 源码运行时如果找不到技能目录，可用 OMNI_SKILLS_DIR 指向 omni-engine/skills。
  • 其他支持 SKILL.md 的 Agent 运行时应按其技能加载规则安装；技能契约本身不依赖特定 IDE。

配置

禅道

npm install -g zentao-cli

# 方式一：环境变量（推荐，Token 失效可自动重登）
export ZENTAO_URL=https://<zentao-host>/
export ZENTAO_ACCOUNT=<account>
export ZENTAO_PASSWORD=<password>

# 方式二：命令行登录（写入本地 profile，不含密码）
zentao login -s https://<zentao-host>/ -u <account> -p <password>
zentao profile
  • 技能脚本读取本地 ~/.config/zentao/zentao.json 的 admin 配置；zentao-cli 的 robot token 失效（403）时，以技能脚本的 admin token 路径为准。
  • 阶段 3 需要用例库 ID与产品/项目 ID；阶段 4 需要阶段 3 的 import-result.json。
  • 凭据只放在环境变量或本地 profile，不写入技能文档、csv、日志或版本库。

平台推送

在项目根 conf/settings.ini 配置：

[PLATFORM]
server = https://<platform-host>
project_id = <project-id>
product_id = <product-id>  ; 禅道产品 ID
zentao_id = 0              ; 0=从产品反查
git_config_id = 0
token = <token>

也支持环境变量覆盖：OMNI_PLATFORM_SERVER、OMNI_PLATFORM_PROJECT_ID、OMNI_PLATFORM_PRODUCT_ID、OMNI_PLATFORM_ZENTAO_ID、OMNI_PLATFORM_GIT_CONFIG_ID、OMNI_PLATFORM_USERNAME、OMNI_PLATFORM_PASSWORD、OMNI_PLATFORM_TOKEN。token 优先于用户名/密码。

LLM（AI 阶段）

export OPENAI_API_KEY=<key>
export OPENAI_BASE_URL=https://<compatible-endpoint>/v1
export OPENAI_MODEL=<model>

也可在 settings.ini [AI] 配置。未配置时使用 MockProvider，只返回固定的通过/未知结果，适合离线调试，不能当作真实分析；ai run 在未配置真实 LLM 时会直接失败，不会静默通过。

浏览器与 testbed

  • Web 用例通过 GlobalContext.envs[0] 读取 testbed 的 web_url、web_user、web_pwd。
  • 页面实测需要浏览器与 WebDriver；omni-engine-cli manage --install <browser> 可安装驱动。
  • 账号与地址写入本地 testbed，不硬编码在页面对象或用例中。

发起流程

一键全流程

使用 omni-pipeline，target：需求 PRD ./docs/prd/login.md 与页面 https://demo.example.com/login，
start：1，依次完成测试方案 → 禅道 csv → 上传 → 回写 → 自动化用例 → 执行 → 验证。

从失败阶段续跑

使用 omni-pipeline，target：登录页，start：5（上游同步后 csv 已存在）。

start 的前提是上游文件存在且格式正确；续跑前 Agent 会核对 csv 是否含 用例ID / 模块树路径、自动化用例是否已存在。

分阶段发起

目标对话指令示例
补 PRD使用 omni-web-prd-write，target：https://demo.example.com/login，fragments：./docs/legacy-login.md
补设计使用 omni-web-design-write，target：./docs/design/platform/login/login-<date>-prd.md
生成测试方案使用 omni-web-test-plan，target：https://demo.example.com/login
转禅道 csv使用 omni-case-export，source：./docs/design/platform/login/login-<date>-testplan.md
上传禅道使用 omni-zt-case-push，csv：./docs/design/platform/login/login-<date>-testcase.csv
回写 ID使用 omni-zt-case-pull，csv：<同一 csv>，import_result：./import-result.json
写自动化使用 omni-web-case-write，target：登录页，cases：<同步后 csv>
执行闭环使用 omni-case-run，target：testcase/platform/login/，change：login 模块
静态审查使用 omni-case-verify，csv：<同步后 csv>，testcase：testcase/platform/login/
推送平台使用 omni-platform-case-push，project_root：testcase/platform/login

阶段 3 如果未提供用例库/产品 ID，技能会暂停询问；不要臆造 ID，也不要把凭据贴进对话。

MCP 接入（可选）

MCP 把引擎能力暴露给支持 MCP 的 Agent。安装可选依赖：

pip install "omni-engine[mcp]"

当前包通过 Python 入口启动 stdio Server：

python -c "from omni.integrations.mcp import run; run()"

客户端配置示例（不同客户端字段可能不同，以其文档为准）：

{
  "mcpServers": {
    "omni-engine": {
      "command": "python",
      "args": ["-c", "from omni.integrations.mcp import run; run()"]
    }
  }
}

暴露 5 个工具：

工具输入输出
generate_case自然语言描述、模块名、可选输出路径Spec YAML 与落盘路径
run_testsSpec 路径列表、并发数用例级通过/失败与错误
analyze_report报告路径或失败列表失败用例、分类、根因、建议
fix_failure用例名、错误信息、上下文修复建议/补丁、是否已修复
trigger_regression用例池、变更模块/子系统/文件选中数量、告警、回归结果

MCP 为可选能力；未安装时用 CLI 或 Python API 等效执行。run_tests 走 Spec/StepExecutor，代码用例仍建议直接用 pytest。

运行与验证

收集与执行

# 只收集，确认用例被正确发现
python -m pytest testcase/platform/login --collect-only

# 单条用例单跑（验证独立性）
python -m pytest testcase/platform/login/test_login_main.py::TestCaseLoginFlow::test_login_success_000042

# 模块回归
python -m pytest testcase/platform/login

# Spec / 套件
omni-engine-cli spec run ./specs/login.yaml
omni-engine-cli suite run ./suite.yaml

Windows 下建议使用项目虚拟环境的解释器（如 .venv/Scripts/python.exe -m pytest），避免裸 python 缺少 omni 模块。控制台中文乱码时设置 PYTHONIOENCODING=utf-8 或重定向到文件。

报告

  • pytest 通道输出“测试结果：”JSON 摘要；suite run 输出套件汇总与明细；spec run 逐步打印并汇总。
  • Allure 结果与 HTML/JSON 报告按 settings.ini [REPORT] 开关生成；报告地址与文件托管见 报告。
  • 需要平台回收结果时，传入 --callback 与 --callback-task-id，字段与认证见 平台集成。

回归验证顺序

  1. --collect-only 无警告。
  2. 每个新增用例单跑通过。
  3. 连跑两次通过（无“已存在”“无数据可删”残留）。
  4. 全量回归或 -m P0 不受影响。

排障

现象可能原因处理
skills list 报找不到技能目录安装版本不含 skills，或源码目录未定位升级 omni-engine；设置 OMNI_SKILLS_DIR 指向 omni-engine/skills
安装成功但 Agent 看不到技能未新开会话，或装错目录新开会话；确认全局/项目级目录；必要时 --force 重装
禅道上传/回写 403token 过期、robot token 权限不足重新登录；使用技能脚本的 admin token 路径
创建用例报缺少 productIDproductID 放在 body使用技能脚本；不要把 productID 放 body
导入成功但 status:"fail"禅道约定，message 为“导入成功 N 条”以 message/导入结果为准
同步后 用例ID 为空名称不匹配、未导入、产品模块缺失核对标题唯一性、导入结果与产品 story 模块
页面打不开网络、登录态、SSO/验证码配测试账号或可控绕过；不可达时显式标记未验证
ai run 直接失败未配置真实 LLM配置 OPENAI_API_KEY 或 [AI]；MockProvider 不能用于真实执行
pytest 报找不到 omni未激活虚拟环境，或用了系统 Python用 .venv/Scripts/python.exe -m pytest
控制台中文乱码Windows 编码PYTHONIOENCODING=utf-8 或重定向文件
python -m omni.integrations.mcp 报错当前包未提供 __main__.py改用 python -c "from omni.integrations.mcp import run; run()"
平台推送配置错误[PLATFORM] 缺键或凭据失效补齐 server/project_id/product_id/token；先用 --dry-run
Allure 报告打不开报告文件未托管或匿名只读未开检查 Jenkins/共享存储与访问权限

验收清单

在一个模块上完成试点，至少确认：

  • [ ] omni-engine-cli skills list 能看到推荐技能，Agent 新会话能加载。
  • [ ] 禅道登录可用，用例库与产品 ID 已确认。
  • [ ] 阶段 1 方案中的 selector 全部来自实测，且有抓取记录。
  • [ ] 阶段 2 csv 9 列齐全，步骤与预期条数一致。
  • [ ] 阶段 3 dry-run 计划正确，正式上传后导入数量符合预期。
  • [ ] 阶段 4 同步后 csv 含 用例ID 与 模块树路径，模块 ID 正确。
  • [ ] 阶段 5 新用例可单跑、连跑两次，--collect-only 无警告。
  • [ ] 阶段 6 失败用例有归因，回归结果可复核。
  • [ ] 阶段 7 静态审查 PASS；若有 FAIL，已回到对应阶段修复。
  • [ ] 阶段 P 两次确认后才推送，日志与仓库中没有明文凭据。

边界

  • 不承诺无人值守：PRD/设计、AI 产物、禅道写入、平台推送保留人工关卡。
  • 不是调度器：定时、并发、环境租约由平台 AT 或 CI 负责，omni-pipeline 只负责阶段编排。
  • 当前技能链以 Web UI 为主；API 域按同一命名约定预留，尚未提供完整技能链。
  • 禅道标题唯一是当前回写假设；同名用例需要先消除歧义。
  • 页面不可达、SSO/验证码/MFA 等场景需要测试账号或可控策略，否则只能标记未验证，不能伪造通过。
