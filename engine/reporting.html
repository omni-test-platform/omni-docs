报告

内容状态：基于代码与文档整理，待产品负责人复核。

引擎采用多报告器并行输出：ReportManager 把步骤、附件、动态标题等事件广播给所有启用的报告器。内建报告器为 Allure、RF 风格内建报告与日志转 HTML；pytest 侧还可开启 HTML、JSON 与 flexreport。

报告器与开关

报告器产物配置键默认
AllureAllure 结果与 HTMLallure_enabled开
RF 内建HTML/JSON/xUnitrf_enabled、rf_output_formats开，html,json
日志 HTMLlog.htmllog_enabled关
pytest-html单文件 HTMLhtml_enabled关
flexreport结构统计 HTMLflexreport_enabled关
JSONpytest JSON 报告json_enabled关

配置在 settings.ini 的 [REPORT] 段。直接运行 pytest 时可用 --reports=allure,rf,log,html,flexreport,json 白名单，以及 --no-allure-report、--no-rf-report、--no-log-report 关闭对应报告器；通过 omni-engine-cli 主命令执行时，用 settings.ini 或 OMNI_REPORT_* 环境变量控制。

[REPORT]
allure_enabled = true
rf_enabled = true
rf_output_formats = html, json, xunit
html_enabled = false
json_enabled = false

rf_output_formats 使用 html、json、xunit，不是 xml；xUnit 产物扩展名仍为 .xml。

Allure 3 优先与 Allure 2 回退

[ALLURE] version = auto 时先探测 Allure 3（PATH 中版本为 3.x 的 allure，其次 npx allure），未安装则回退内置 Allure 2。version = 3 找不到时直接失败，不回退；version = 2 跳过 Allure 3。环境变量 OMNI_ALLURE_VERSION 与 OMNI_ALLURE_BIN 优先于配置文件。

[ALLURE]
version = auto
single_file = true
language = zh
group_by = epic,feature,story,suite
cleanup_results = true

Allure 3 由框架生成临时 allurerc，支持 Awesome 单文件、界面语言、分组与页脚/图标替换；Allure 2 走 --single-file 与 prepare_history。数据流不变，allure-pytest 仍写入 allure-results。报告生成失败只记录日志，不改变测试退出码。

产物位置

reports/
├── latest/
│   ├── allure-reports/          # 最新 Allure HTML
│   └── rf-report/report.html    # 最新内建报告
└── history/<ID>/
    ├── allure-results/          # 本轮 Allure 原始结果
    ├── rf-report/               # 本轮内建报告
    ├── html/  json/  log/       # 按开关生成

report_root 默认 ${REPORT_DIR}，历史保留轮数由 history_retention 控制。latest/ 每次覆盖，适合 CI 与人工快速查看；history/<ID>/ 保留每轮原始数据，适合对比与追溯。清理策略只删除超出保留轮数的目录，不会删除当前轮。

命令示例

omni-engine-cli -f ./conf/debug.yaml
omni-engine-cli -f ./conf/debug.yaml --no-report-allure
OMNI_REPORT_JSON=1 omni-engine-cli -f ./conf/debug.yaml \
  --json-report-file ./reports/latest/report.json
omni-engine-cli -f ./conf/debug.yaml --report ./reports/latest/flexreport.html

主命令的 Allure 开关是 --report-allure / --no-report-allure，默认生成；旧文档中的 --report_allure 不是当前选项。JSON 报告需要 json_enabled=true 或 OMNI_REPORT_JSON=1，--json-report-file 只指定路径。--report 只用于 flexreport。

常见问题

  • 报告仍是 Allure 2 样式：确认 allure --version 输出 3.x，且未设置 OMNI_ALLURE_VERSION=2 或指向 Allure 2 的 bin_path。
  • Allure 3 报告打开空白：保持 single_file = true；多文件报告通过 fetch() 加载数据，file:// 下会被浏览器拦截。
  • 历史趋势为空：连续多轮执行后才会累积；Allure 3 使用 allure-history.jsonl，Allure 2 单文件模式依赖 allure-history 目录。
  • 报告目录没有产物：检查 [REPORT] 开关、--no-report-allure 以及 Allure CLI 是否可执行；生成失败只记录日志。
  • 并行报告缺失：确认 controller 正常结束；worker 分片需要由 controller 合并。
  • 重试与 flexreport 同时启用会触发 INTERNALERROR，重试时关闭 flexreport。

并行与合并

xdist 下各 worker 写 JSON 分片，controller 在会话结束合并为单一报告；RF 报告按 report_summary.<workerid>.json 分片合并；Allure/HTML 各 worker 独立生成后汇总到统一报告目录。平台数据库写入用文件锁保护。并行细节见执行与编排，平台报告页见执行报告。
