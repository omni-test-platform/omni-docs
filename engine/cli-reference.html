CLI 参考

内容状态：基于代码与文档整理，待产品负责人复核。

omni-engine-cli 是唯一命令入口，由 Typer 构建。下表的参数均可用 <命令> --help 查看完整帮助；统一使用 omni-engine-cli，python -m omni.cli.main 走单命令入口，不会展开子命令。示例中的 <...> 为占位值。

通用约定

  • 云原生域与 AI 域的新命令支持 --format table|json，默认 table；JSON 便于管道消费。
  • chaos、perf 支持 --dry-run，只打印将生成/执行的参数，不产生副作用。
  • 用例路径、目录路径通常是位置参数；过滤条件与开关通常是选项。以 --help 为准。
  • 命令成功一般返回 0，失败或存在未通过用例返回非 0；具体命令的判定见各页。
  • 凭据、平台地址、Token 使用占位值或环境变量，不要写入命令历史与文档。
  • 命令中的时间使用 30s、1m 等字符串；并发数、超时等数值参数按命令实际类型传入，不支持的组合以 --help 为准。

全局与默认命令

omni-engine-cli --version
omni-engine-cli --help
omni-engine-cli -f ./conf/debug.yaml
选项说明
--test_conf_path / -ftestconf 路径；默认值仍指向旧的 ./demo/conf/demo.xml，请显式传入
--json-report-fileJSON 报告输出路径；开关由 json_enabled 或 OMNI_REPORT_JSON 控制
--report-allure / --no-report-allure是否生成 Allure，默认生成
--reportflexreport 输出路径
--jenkins-workspaceJenkins 工作区路径
--collect-only只收集不执行
--loglevelTRACE/DEBUG/INFO/SUCCESS/WARNING/ERROR
--desc测试描述
--callback / --callback-task-id用例级进度回调 URL 与任务 ID

执行域

omni-engine-cli api execute --method GET --url https://httpbin.org/get
omni-engine-cli api run ./cases/httpbin_api.json --verbose
omni-engine-cli api batch ./cases --pattern '*.json'
omni-engine-cli spec validate ./specs/demo.yaml
omni-engine-cli spec run ./specs/demo.yaml
omni-engine-cli spec compile ./specs/demo.yaml -o ./generated
omni-engine-cli pytest run ./testcase/test_api.py --collect-only
omni-engine-cli suite run ./suite.yaml --json-report-file ./result.json
命令关键参数
api execute--method/-m、--url/-u、--headers/-h、--body/-b、--validate、--base-url、--output/-o、--verbose/-v
api run位置参数用例文件；--env/-e（当前版本未注入执行器）、--async、--callback/-c、--output/-o、--verbose/-v
api batch位置参数目录；--pattern/-p（默认 *.json）、--callback/-c、--output-dir/-o
spec validate/run位置参数 Spec 路径；run 另有 -v
spec compile位置参数 Spec 路径；--output-dir/-o（默认 generated）
pytest run位置参数 .py 文件；--json-report-file、--collect-only、--alluredir、--case-log-path
suite run位置参数套件文件；--json-report-file、--alluredir、--allure-report-dir、--allure-bin、--case-log-path、--callback、--callback-task-id

api run/api batch 当前按 JSON 读取；spec 与 suite 的用例路径是位置参数，不是 --spec。

omni-engine-cli skills install --global
命令关键参数
sync--server/-s、--token/-t 或 --username/-u/--password/-p、--project-id/-i、--product-id、--project-root/-r、--incremental、--baseline、--dry-run/-n、--json、--yes
manage--project/-p（默认 demo）、--install/-i（chrome/firefox/ie/edge）；当前 --project 脚手架仍引用已拆分的 demo/ 目录，可能失败，可用 demo_minio/demo_saucedemo 作为模板
config dump--project
zentaoupload/ensure-modules/query/sync；--csv、--root、--product-id、--caselib-id
skillslist；install --target/--global/-g/--force/-f/--link

sync 的 --product-id 必填；上传前会要求确认产品。manage 的脚手架模板在当前工作版本仍引用旧 demo/ 目录，--project 与 --install 都可能因此失败；请以仓库现有 demo_minio/demo_saucedemo 为参考，行为以当前版本为准。

退出码与帮助

api run、api batch、spec run、suite run 在失败时返回非 0；k8s、chaos、perf、prom 按单次操作结果返回。批量脚本应检查退出码，而不是只解析标准输出。所有命令组都支持 -h/--help，子命令同理；参数变更时先以 --help 的实际输出为准。
