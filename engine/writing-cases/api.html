API 用例

内容状态：基于代码与文档整理，待产品负责人复核。

接口测试有三条写法：pytest 中直接调用 HttpSession；用 config + teststeps 的 JSON 文件交给 api run；或在 Spec 中写 action: api。三者都复用 HTTP 会话、变量解析、校验与提取能力，区别在组织方式与执行入口。

JSON 用例文件

{
  "name": "HTTPBin 接口验证",
  "config": {
    "case_name": "健康检查与回显",
    "base_url": "https://httpbin.org",
    "verify": false,
    "variables": {"user": "demo"}
  },
  "teststeps": [
    {
      "step_name": "GET headers",
      "step_type": "API",
      "request": {"method": "GET", "url": "/headers"}
    },
    {
      "step_name": "POST json",
      "step_type": "API",
      "request": {
        "method": "POST",
        "url": "/post",
        "json": {"username": "${user}"}
      }
    }
  ]
}
omni-engine-cli api run ./cases/httpbin_api.json
omni-engine-cli api run ./cases/httpbin_api.json --verbose --output ./result.json

api run 的位置参数是用例文件。帮助文本写作“JSON/YAML”，但当前实现以 json.load() 读取，请使用 JSON；YAML 用例请转成 JSON，或改写为 Spec。--env 选择环境，--async 异步提交并可用 --callback 回传。成功退出码为 0，失败为 1。

单接口与批量

omni-engine-cli api execute --method GET --url https://httpbin.org/get
omni-engine-cli api execute --method POST --url https://httpbin.org/post \
  --body '{"user":"demo"}' --headers '{"Content-Type":"application/json"}'
omni-engine-cli api batch ./cases --pattern '*.json' --output-dir ./results

api execute 适合调试单个请求，输出序列化后的步骤结果；--validate "status_code == 200" 可附加简单校验。api batch 按文件名排序逐个执行目录中的 JSON，全部通过才返回 0。批量为逐文件串行；需要用例集合级并发时使用编程接口 ApiExecutor.execute_batch(cases, concurrency=N)。

pytest 写法

from omni.common.case import TestCaseBase
from omni.drivers.api.client import HttpSession


class TestApi(TestCaseBase):
    def setup_class(self):
        self.session = HttpSession()

    def test_headers(self):
        resp = self.session.get("https://httpbin.org/headers")
        self.assertEqual(resp.status_code, 200)
        self.assertIn("headers", resp.json())

参数与输出

参数适用命令说明
--env / -erun环境名称；当前版本未注入执行器，环境以 config.base_url 为准
--asyncrun异步执行，返回任务 ID
--callback / -crun、batch回调 URL；batch 当前版本仅接收参数
--output / -oexecute、run结果写入文件
--verbose / -vexecute、run输出完整 JSON
--pattern / -pbatch文件匹配，默认 *.json

用例字段

config 支持 case_name、base_url、verify、variables、export 等字段；teststeps 的每一步至少要有 step_name 与 request。request 支持 method、url、params、headers、json、data、cookies、timeout、allow_redirects。步骤还可以声明 extract、validate、skipif、sleep、export 与前后置 hooks。变量用 ${var} 引用 config.variables，请求 URL 为相对路径时会与 base_url 拼接。

api execute 的 --validate 只适合简单表达式；复杂断言应写进用例文件或 pytest。api run 当前不解析 YAML，即使帮助文本写作 JSON/YAML；需要 YAML 时使用 Spec。异步执行只提交任务，结果通过 --callback 回传，不写入命令输出。

常见问题

  • 404 或连接失败：确认 base_url 与 url 的拼接结果，以及目标环境是否可达。
  • 断言通过但结果为失败：检查步骤级 validate 与 hooks 的返回值，失败信息通常在 result.json 中。
  • 回调未到达：确认回调 URL 可从执行机访问，认证头与任务 ID 已按平台协议传入。
  • 批量结果文件缺失：--output-dir 只在用例执行成功或失败后写入，加载 JSON 失败的文件不会生成结果。

同一用例内的步骤按 teststeps 顺序执行；步骤间共享 config.variables 与已提取变量。需要步骤依赖或失败即跳过时，使用 depends、skipif 等步骤字段。批量执行时每个文件独立构建 TCase，文件之间不共享会话与变量，测试数据要自行隔离。

执行详情、报告与回调字段见执行与编排、报告与平台集成。Spec 的 api 动作见Spec。
