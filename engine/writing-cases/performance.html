性能用例

内容状态：基于代码与文档整理，待产品负责人复核。

性能能力由 PerformanceEngine 提供，Spec 使用 action: performance（别名 perf），CLI 使用 omni-engine-cli perf run。Locust 后端依赖 pip install "omni-engine[performance]"；k6 后端还需要本机安装 k6 二进制。负载会真实打到目标服务，只在授权环境执行。

Spec 写法

name: 接口负载与 SLA
env:
  base_url: https://httpbin.org
steps:
  - id: 1
    name: Locust 负载
    action: performance
    data:
      tool: locust
      url: https://httpbin.org/get
      method: GET
      users: 10
      spawn_rate: 2
      duration: 10s
    validate:
      - qps: [qps, 1]
      - p99_latency: [p99_ms, 2000]
      - error_rate: [error_rate, 0.05]
  - id: 2
    name: 基线对比
    action: performance
    depends_on: [1]
    data:
      tool: locust
      url: https://httpbin.org/get
      method: GET
      users: 10
      duration: 10s
    validate:
      - baseline: ./baseline.json

data 支持 tool（locust/k6）、url、method、body、headers、users、spawn_rate、duration、script、stages、k6_bin、timeout。k6 用 script 指定脚本路径或内联脚本，用 stages 传入阶段 JSON。

CLI 写法

omni-engine-cli perf run --tool locust --url https://httpbin.org/get \
  --users 10 --spawn-rate 2 --duration 10s
omni-engine-cli perf run --tool k6 --script ./k6/demo.js \
  --stages '[{"duration":"10s","target":10}]' --dry-run

--dry-run 只打印将使用的参数，不发起负载。--format json 输出结构化结果。

断言与基线

断言语义
qps: [qps, N]实际 QPS 不低于 N
p99_latency: [p99_ms, N]P99 延迟不高于 N 毫秒
p95_latency: [p95_ms, N]P95 延迟不高于 N 毫秒
error_rate: [error_rate, N]错误率不高于 N
total_requests: [total_requests, N]总请求数不低于 N
baseline: <file>与基线 JSON 对比，超过回归阈值则失败

基线文件格式：

{"qps": 100, "p99_ms": 500, "error_rate": 0.01, "regression_threshold": 0.1}

baseline 判定 QPS 降幅、P99/P95 延迟与错误率涨幅是否超过阈值，默认 10%。断言采用列表形式；旧文档中的 - qps: 10 标量写法不会被当前 loader 收集。

工具选择与指标

工具依赖适合场景
Locustomni-engine[performance]Python 脚本、快速构造 HTTP 负载
k6本机 k6 二进制高并发、阶段式压测、JS 脚本

Locust 直接用 url、method、body、users、spawn_rate、duration；k6 更适合用 script 描述请求与检查，stages 控制爬坡。QPS 看吞吐下限，P95/P99 看尾延迟上限，错误率看稳定性；基线对比用于发现相对历史版本的回归，而不是替代绝对 SLA。

结果判定

一次压测是否通过由步骤的成功状态与 validate 共同决定：qps、total_requests 是下限，p95_latency、p99_latency、error_rate 是上限；任一断言不满足，步骤即失败。基线对比只检查基线文件中存在的指标，未提供的指标跳过。压测结果的稳定性受采样窗口、预热、客户端瓶颈与网络影响，建议先做短时冒烟，再做正式时长。

注意事项

压测前确认目标环境、数据与限流策略，避免打到生产或共享环境；逐步增加并发，观察服务端资源与错误率。测试数据应可重复使用，避免压测后留下大量脏数据。Locust/k6 的进程与端口由引擎管理，执行机需预留 CPU、内存与网络带宽。结果受环境噪声影响，建议多次执行取稳定值。

输出与参考

StepResult.data 含 tool、qps、p50_ms、p95_ms、p99_ms、error_rate、total_requests 等指标，报告与平台回调可按需消费。执行编排见执行与编排，命令行参数见 CLI 参考。
