pytest 用例

内容状态：基于代码与文档整理，待产品负责人复核。

pytest 是引擎的代码用例路径（路径 A/B）。用例放在 testcase/ 下，按 test_<module>.py 命名；继承 omni.common.case.TestCaseBase 后，类中的 test_* 方法与前后置钩子由 CaseMetaClass 自动记录步骤、写入 Allure 标签，并从方法名末尾提取禅道用例 ID。

最小用例

from omni.common.case import TestCaseBase
from omni.drivers.api.client import HttpSession


class TestHttpBin(TestCaseBase):
    """HTTPBin 基本验证"""

    def setup_class(self):
        self.session = HttpSession()

    def teardown_class(self):
        self.session.close()

    def test_get_headers(self):
        """GET /headers 应返回请求头回显"""
        resp = self.session.get("https://httpbin.org/headers")
        self.assertEqual(resp.status_code, 200, "状态码应为 200")
        self.assertIn("headers", resp.json(), "响应应包含 headers")

    def test_post_json(self):
        """POST JSON 应回显请求体"""
        resp = self.session.post("https://httpbin.org/post", json={"user": "demo"})
        self.assertEqual(resp.status_code, 200)
        self.assertEqual(resp.json()["json"]["user"], "demo")

TestCaseBase 复用 unittest 断言：assertEqual、assertIn、assertTrue、assertIsNone、assertRegex 等。BasePage、BaseApi 另提供 assert_equal、assert_in 等 snake_case 断言，不要把两者混用。

前后置与 fixture

pytest 原生钩子与 fixture 均可直接使用。重载 setup_method 时必须调用 super().setup_method(method)，保留框架的截图收集列表重置逻辑；类级钩子使用 @classmethod。

import pytest
from omni.common.case import TestCaseBase


@pytest.fixture(scope="class")
def token():
    return "demo-token"


class TestWithFixture(TestCaseBase):
    def setup_method(self, method):
        super().setup_method(method)

    def test_token(self, token):
        self.assertIsNotNone(token)

共享依赖优先放 conftest.py，按 session/module/class 作用域复用；不要依赖用例执行顺序。

配置与执行

入口配置由 testconf 指向 testbed 与 testset。测试集里的 location 是 pytest node ID 或目录：

# conf/debug.yaml
description: 本地调试
testbed: conf/testbed/testbed_debug.yaml
testset: conf/testset/testset_debug.yaml

# conf/testset/testset_debug.yaml
case_list:
  - {location: testcase/api/test_bucket.py::TestBucket::test_create}
  - {location: testcase/api}
omni-engine-cli -f ./conf/debug.yaml
omni-engine-cli pytest run ./testcase/api/test_bucket.py

第一条按 testset 顺序批量执行；第二条只跑单个 .py 文件，并输出「测试结果：」JSON 摘要。pytest run 仅接受 .py 文件，不接受目录。

标记与并行

@pytest.mark.CI、@pytest.mark.P0 等标记可直接使用；自定义标记需在 conftest.py 注册。并行由 pytest-xdist 提供，CLI 读取 OMNI_WORKERS，共享浏览器或数据库的用例加 @pytest.mark.serial：

OMNI_WORKERS=4 OMNI_DIST=loadscope omni-engine-cli -f ./conf/debug.yaml

目录的 __init__.py 可声明 __module_zh__，供报告展示中文模块名；用例方法末尾的 _<数字> 会作为禅道用例 ID 关联，便于平台回写执行结果。用例类与方法名保持稳定，重命名会影响用例 ID 映射与历史报告对比。

数据与日志

测试数据放 data/ 或 testdata/，用 JSON/YAML 读取，不在代码中硬编码环境差异。敏感信息走配置或环境变量。用例内使用 self.logger 记录关键步骤，日志会进入报告；失败时结合用例日志、Allure 附件与 StepResult.error 排查。一个用例只验证一个核心业务点，前置数据与清理逻辑放在 fixture 或后置钩子中。

执行结果

pytest 通道输出「测试结果：」JSON 摘要，包含总数、通过、失败、错误、跳过、通过率与耗时；进程退出码由 pytest 结果决定。只收集不执行时加 --collect-only，用于确认 testset 中的 node ID 是否正确。用例未被收集时，检查文件名是否以 test_ 开头、类名是否以 Test 开头、文件是否在 testset 的 location 中。

参数构建、退出码与报告合并见执行与编排与报告。把引擎嵌入自有 pytest 工程（而不是在引擎工程内写用例）见作为库集成。
