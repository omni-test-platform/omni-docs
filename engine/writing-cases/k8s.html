K8s 用例

内容状态：基于代码与文档整理，待产品负责人复核。

K8s 能力基于官方 kubernetes Python 客户端，安装 pip install "omni-engine[k8s]" 后可用。Spec 使用 action: k8s，命令放在 data 中；CLI 使用 omni-engine-cli k8s 直接调试。两者委托同一 KubeCtlEngine，行为一致。

Spec 写法

name: K8s 基础验证
env:
  variables:
    namespace: omni-test
    app_name: nginx-demo
steps:
  - id: 1
    name: 创建 Namespace
    action: k8s
    data:
      command: create
      kind: namespace
      name: "${namespace}"
  - id: 2
    name: 创建 Deployment
    action: k8s
    depends_on: [1]
    data:
      command: create
      kind: deployment
      name: "${app_name}"
      namespace: "${namespace}"
      image: nginx:1.27
      replicas: 2
  - id: 3
    name: 等待 Deployment 就绪
    action: k8s
    depends_on: [2]
    data:
      command: rollout_status
      kind: deployment
      name: "${app_name}"
      namespace: "${namespace}"
      timeout: 120
    validate:
      - deployment_ready: [ready_replicas, 2]
  - id: 4
    name: 列出 Pod
    action: k8s
    depends_on: [3]
    data:
      command: list
      kind: pod
      namespace: "${namespace}"
    validate:
      - greater_than: [count, 0]

执行前需配置 kubeconfig 并有创建 Namespace/Deployment 的权限；示例会创建真实资源，请在测试集群运行并及时清理。

command 支持 get、list、create、apply、delete、rollout_status、inspect_vgpu、check_schedule_strategy。apply 的 manifest 可写内联 YAML 或 @文件路径。多集群通过 data.context 或 env.cluster 指定 kubeconfig 上下文。

CLI 写法

omni-engine-cli k8s get --kind pod --name <pod-name> --namespace <namespace>
omni-engine-cli k8s list --kind pod --namespace <namespace> --format json
omni-engine-cli k8s rollout-status --name <deployment> --namespace <namespace> --timeout 300
omni-engine-cli k8s apply --manifest @./crd/netpol.yaml
omni-engine-cli k8s inspect-vgpu --name <pod-name> --namespace <namespace>
omni-engine-cli k8s check-schedule --strategy binpack --namespace <namespace>

CLI 的 kind、name、namespace 都是选项，不是位置参数。旧文档中的 k8s get pod --name ... 形式与当前命令不符。

前置条件与命令对照

执行前需具备可用的 kubeconfig、目标命名空间的访问权限，并安装 omni-engine[k8s]。多集群时 --context 指定 kubeconfig 上下文，Spec 可用 env.cluster 或步骤 context.cluster 覆盖。Spec 的 command 使用下划线，CLI 子命令使用连字符：

Spec commandCLI 子命令用途
get / listk8s get / k8s list查询单个或列表资源
create / apply / deletek8s create / apply / delete创建、应用清单、删除
rollout_statusk8s rollout-status等待 Deployment 滚动完成
inspect_vgpuk8s inspect-vgpu查看 HAMi vGPU 切分
check_schedule_strategyk8s check-schedule验证 binpack/spread 调度

inspect_vgpu 依赖目标 Pod 带 HAMi annotations，普通 Pod 只验证调用链路；check_schedule_strategy 用于 HAMi 调度策略场景，断言字段以当前版本为准。

断言与输出

断言示例说明
Pod 状态- pod_phase: Running断言 phase
Deployment 就绪- deployment_ready: [ready_replicas, 2]断言就绪副本数等于期望副本数
Namespace 存在- namespace_exists: [name, <namespace>]断言资源存在
通用比较- greater_than: [count, 0]列表结果计数等

--format table 为默认，--format json 便于管道消费。缺少依赖时命令提示安装 omni-engine[k8s]。断言失败的字段说明以当前版本为准。

权限与命名空间

执行账号需要目标资源的 get/list/create/delete 权限；创建 Namespace 还需要集群级权限。默认 namespace 是 default，生产化用例应显式声明命名空间，避免误操作共享资源。apply 对已存在资源执行更新，create 对已存在资源可能报错；需要幂等时优先 apply。删除 Namespace 会级联删除其下资源，确认命名空间专用后再执行。

结果与排障

StepResult.data 为资源状态字典：Pod 含 phase、name、namespace，Deployment 含 replicas、ready_replicas，列表结果含 count 与 items。常见失败包括 kubeconfig 上下文错误、RBAC 权限不足、资源不存在、Deployment 在超时内未就绪。先单独执行 kubectl get 或 CLI k8s get 验证连接与权限，再排查 Spec 的命名空间、名称与选择器。创建类步骤会留下真实资源，用例结束应删除 Namespace 或 Deployment，避免污染集群。
