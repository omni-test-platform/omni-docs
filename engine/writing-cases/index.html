编写用例

内容状态：基于代码与文档整理，待产品负责人复核。

omni-engine 同时支持代码用例与声明式用例。代码用例走 pytest，框架用 TestCaseBase、StepMetaClass、CaseMetaClass 统一日志、步骤与 Allure 元数据；声明式用例走 YAML Spec，由 SpecCompiler 加载、StepExecutor 调度、ActionAdapter 分发。两条路径共用执行器、变量、断言与报告能力。

三条编写路径

路径用例形态执行入口适合场景
A手写 test_*.pyomni-engine-cli -f <testconf> 或 pytest复杂业务逻辑、需要编程与调试
BAI 生成的 test_*.py同上webai generate 等工具产出后人工评审
C*.yaml Specomni-engine-cli spec run <spec.yaml>接口编排、跨协议流程、声明式回归

A/B 使用 drivers/ 下的 Runner 与元类；C 不使用元类，步骤由 action 映射到适配器。单条脚本或多类型混排还可以交给 suite run，见执行与编排。

项目结构

脚手架或示例工程通常按下列目录组织，conf/、testcase/、specs/ 与 reports/ 都位于测试项目根目录：

my-project/
├── conf/                 # settings.ini、testconf、testbed、testset
├── testcase/             # pytest 用例（test_*.py）
├── features/             # 页面对象、业务封装
├── specs/                # YAML Spec
├── testdata/ 或 data/    # 测试数据
└── reports/              # 执行输出

仓库自带两个参考工程：demo_minio 覆盖 API、CLI、混合步骤与云原生 Spec，demo_saucedemo 覆盖 Web 页面对象与流程用例。早期文档中的单个 demo/ 已拆分，命令与路径请以这两个目录为准。

选择建议

  • 需要循环、条件、复杂数据构造或复用 Python 生态：写 pytest 用例，见 pytest。
  • 流程由多个接口或多种协议组成，希望配置化、可读、可编译为代码：写 Spec，见 Spec。
  • 只验证接口：可从 API 的 api run 或 action: api 起步。
  • 浏览器操作：见 Web；本地/SSH 命令：见 CLI；移动端：见 APP。
  • K8s、混沌、性能分别见 K8s、混沌、性能，均需安装对应 extras。

通用约定

用例文件命名为 test_<module>.py，类名为 Test<Feature>，方法名为 test_<scenario>；方法名末尾的 _<数字> 会被识别为禅道用例 ID。环境地址、账号与 Token 放在 conf/ 或环境变量中，不写进用例。一个用例只验证一个核心业务点，并自行准备和清理数据。

omni-engine-cli -f ./conf/debug.yaml
omni-engine-cli spec run ./specs/demo-spec.yaml
omni-engine-cli suite run ./suite.yaml

执行前检查

  1. 确认虚拟环境已激活，omni-engine-cli --version 能输出版本；引擎应作为依赖安装，不要把框架源码复制进测试项目。
  2. 确认 conf/ 下的 testconf 指向存在的 testbed 与 testset，且 location 相对测试项目根目录可解析。
  3. 按用例类型安装 extras：K8s、混沌、性能、AI、并行分别需要 k8s、chaos、performance、ai、parallel；未安装时对应动作会返回明确的依赖错误。
  4. 环境地址、账号、Token 通过 testbed、settings.ini 或环境变量注入，不要写进用例文件。

结果与排障

pytest 通道输出「测试结果：」JSON 摘要，suite run 输出「套件结果：」与逐条明细，spec run 逐步打印通过/失败。失败时先看用例级日志与 StepResult.error；Web 失败会附页面 URL、标题与 DOM 片段，API 失败会附请求/响应摘要。若命令找不到，检查虚拟环境的 Scripts（Windows）或 bin 是否在 PATH 中。

执行结果、退出码与并行方式见执行与编排，报告产物见报告，全部命令行参数见 CLI 参考。
