APP 用例

内容状态：基于代码与文档整理，待产品负责人复核。

APP 测试由 AppRunner 提供。它组合持有 AppDriver，再委托到 SeleniumDriver 的通用元素操作；Appium 专有能力（安装应用、后台切换等）由 AppDriver 实现。运行前需要可用的 Appium Server、设备或模拟器，以及 Appium-Python-Client。APP 能力不参与 Spec 的 action 适配器，主要通过 pytest 代码用例或平台下发的脚本执行；如果需要把移动端步骤混入 YAML 流程，当前版本以代码用例封装后再调用更稳妥。

配置

APP 引擎参数在 GlobalContext.app（AppEngineInfo）中：app_server 是 Appium 服务地址，app_info 是 desired capabilities，app_package 与 extensions 供驱动使用。仓库当前没有独立的 APP 示例工程，参数注入方式以当前版本为准；下面的写法按驱动公开接口组织。

import os
from appium.options.android import UiAutomator2Options
from omni.context import GlobalContext
from omni.common.case import TestCaseBase
from omni.drivers.app.app_runner import AppRunner


class TestMobile(TestCaseBase):
    def setup_class(self):
        GlobalContext.app.app_server = os.environ["APPIUM_SERVER_URL"]
        options = UiAutomator2Options()
        options.app = os.environ["APP_PATH"]
        options.app_package = "<app-package>"
        options.app_activity = "<launch-activity>"
        GlobalContext.app.app_info = options
        self.runner = AppRunner()
        self.runner.init(images=[], new_browser=True)

    def teardown_class(self):
        self.runner.quit()

    def test_login(self):
        self.runner.type(id_="<resource-id-user>", text="<username>")
        self.runner.type(id_="<resource-id-password>", text="<password>")
        self.runner.click(xpath="//android.widget.Button[@text='登录']")
        text = self.runner.get_element(xpath="//android.widget.TextView").text
        self.assertIn("首页", text)

服务地址、应用包名、账号与密码均用环境变量或 testbed 提供，示例中的占位符必须替换。用例结束要关闭会话并释放设备，避免下一次执行占用同一台模拟器。

步骤接口

AppRunner.run_step() 接受字典，支持 click、type、text、sleep：

result = self.runner.run_step({
    "action": "type",
    "locator": {"id_": "<resource-id-user>"},
    "text": "<username>",
})
self.assertTrue(result.success, result.error)

text 动作返回 data["text"]；sleep 的秒数来自 seconds。定位器策略沿用 Web 驱动的约定，Android 上常用 id_、xpath，iOS 可用 accessibility_id 等 Appium 策略，具体映射以当前版本为准。

前置条件

项目要求
Appium Server已启动，app_server 指向其地址
设备真机或模拟器已连接，adb / Xcode 工具可用
驱动已安装 Appium-Python-Client 与对应平台驱动
应用已安装或可在 capabilities 中指定安装包
定位准备好 resource-id、accessibility id 或 XPath

app_info 使用 Appium 的 options 对象，而不是普通字典；Android 用 UiAutomator2Options，iOS 用 XCUITestOptions。app_package 与 extensions 字段由驱动按需读取，具体支持范围以当前版本为准。首次运行建议先用最小 capabilities 打开应用并截一张图，确认会话能建立，再补充业务步骤。

定位与等待

Android 原生控件常用 id_（resource-id）和 xpath；iOS 常用 accessibility_id。页面切换、弹窗与加载状态建议使用显式等待，不要在用例中堆叠固定 sleep。元素文本可先 get_element 再读 .text，也可通过 run_step({"action": "text", ...}) 获取结构化结果。失败时 StepResult.error 会包含异常类型与消息。

执行与边界

APP 用例仍由 pytest 收集，运行方式与执行与编排一致；执行机需能访问 Appium Server 与设备。APP 能力不依赖 K8s/混沌/性能 extras。若需要平台调度，执行机需预装 Appium 与设备驱动，环境注入方式见平台集成。仓库没有 APP 示例工程，示例中的定位器与 capabilities 需按被测应用替换。
