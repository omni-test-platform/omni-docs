混沌用例

内容状态：基于代码与文档整理，待产品负责人复核。

混沌能力通过 Chaos Mesh CRD 注入故障，安装 pip install "omni-engine[chaos]" 后可用。Spec 中 action: chaos 负责注入、终止与查询实验，action: prometheus 负责查询 PromQL 并断言系统稳态。混沌会真实影响被测环境，只允许在授权测试环境执行。

Spec 写法

name: 网络延迟与稳态验证
env:
  base_url: http://prometheus:9090
  variables:
    chaos_ns: <namespace>
    app_label: <app-label>
steps:
  - id: 1
    name: 注入网络延迟
    action: chaos
    data:
      command: inject
      kind: networkchaos
      name: net-delay-demo
      namespace: "${chaos_ns}"
      selector:
        namespaces: ["${chaos_ns}"]
        labelSelectors: {app: "${app_label}"}
      mode: all
      action: delay
      delay: {latency: 100ms, jitter: 10ms}
      duration: 30s
  - id: 2
    name: 验证 QPS 稳态
    action: prometheus
    depends_on: [1]
    data:
      query: 'sum(rate(http_requests_total{app="<app-label>"}[1m]))'
    validate:
      - greater_than: [value, 1]
  - id: 3
    name: 终止实验
    action: chaos
    depends_on: [2]
    data:
      command: terminate
      kind: networkchaos
      name: net-delay-demo
      namespace: "${chaos_ns}"

支持的实验类型包括 PodChaos（kill/pause）、NetworkChaos（delay/loss/duplicate/corrupt/partition）、DiskChaos、StressChaos、IoChaos、TimeChaos。kind 与 action 的组合由 Chaos Mesh CRD 决定，字段名需与已安装版本匹配；不确定时先用 CLI 的 --dry-run 观察生成结果，再写入 Spec。ChaosEngine 在同一 Spec 内按集群上下文复用，Spec 结束时 StepExecutor 会调用 teardown() 清理未终止的实验；仍建议显式写终止步骤。

CLI 写法

omni-engine-cli chaos inject --kind networkchaos --name net-delay-demo \
  --namespace <namespace> --action delay --latency 100ms --duration 30s --dry-run
omni-engine-cli chaos status --name net-delay-demo --namespace <namespace>
omni-engine-cli chaos terminate --name net-delay-demo --namespace <namespace>
omni-engine-cli prom query --query 'up' --url http://<prometheus-host>:9090

先跑 --dry-run 查看将生成的 CRD 清单，再实际注入。--format json 便于脚本消费。

断言与输出

Prometheus 步骤返回 data["value"]，可用 greater_than、less_than、equals 等列表形式的比较器断言。混沌步骤返回实验名称、状态等字段；inject/terminate 的成功表示请求已被 API 接受，实验是否生效仍需结合 status、业务指标或 K8s 断言验证。查询结果为空时 value 可能为 None，比较器会报缺少字段，应先确认 PromQL 与时间窗口。

执行前检查

项目检查内容
集群kubeconfig 可用，当前上下文指向测试集群
Chaos Mesh已安装 CRD 与控制器，目标命名空间未被排除
选择器selector.labelSelectors 能匹配到预期 Pod，先用 kubectl get pod -l 验证
观察指标Prometheus 可达，PromQL 在实验前能返回数据
回滚明确实验名称、命名空间与终止命令，必要时准备手动删除 CRD

网络延迟、丢包、Pod kill 等故障对业务的影响不同，先用最小范围（mode: one）和短 duration 验证，再扩大。--dry-run 可检查 CLI 生成的参数，Spec 侧建议先在测试集群跑单步骤。

安全边界

仅在获得授权的测试集群与命名空间执行；不要对生产环境、共享环境或他人资源注入故障。实验前确认回滚方式、影响范围与观察指标，实验后检查残留 CRD。混沌结果依赖被测系统、网络与集群状态，注入成功不等于业务一定受影响，需结合 Prometheus、日志与功能断言综合判断；具体实验字段与清理行为以当前版本为准。
