源码部署（systemd + nginx）

内容状态：基于代码与配置整理，待产品负责人复核。

deploy.py 把本地源码构建后通过 SSH/SFTP 推送到目标机，适用于不使用 Docker、已具备 systemd 与 nginx 的环境。脚本只更新产物并重启服务，不安装或修改目标机的 systemd 服务与 nginx 配置。

前提

  • 本地：Python 3、paramiko、Go、pnpm；omni-server、omni-web、omni-engine 与 omni-deploy 同级。
  • 目标机：已创建 systemd 服务（默认 omni_server.service，ExecStart 指向服务端二进制，WorkingDirectory 为部署根目录）；nginx 站点根目录已指向前端 dist；omni-engine 安装在独立 venv 中。
  • 目标机 nginx 若以只读 bind mount 挂载 dist，必须使用脚本的就地同步方式，不能替换目录本身。

参数

参数说明
-e/--env <target-key>选择 TARGETS 中的目标环境；默认使用脚本内 DEFAULT_TARGET
-o/--only <list>只部署 server、web、engine，逗号分隔；不传则交互选择
--skip-build跳过本地构建，直接上传已有产物；产物缺失会报错
-y/--yes免交互部署全部组件
-h/--help查看用法
python -m pip install paramiko
python deploy.py -e <target-key> -y
python deploy.py -e <target-key> --only web,engine
python deploy.py -e <target-key> -o server --skip-build

部署动作

组件本地构建远端动作校验与回滚
servergo build，CGO_ENABLED=0、linux/amd64，注入 git 版本号上传到 <server-bin>.new，备份原文件，替换后 systemctl restart90 秒内 active 且 6 秒观察窗口内重启计数不变；失败打印 systemctl status 并恢复 .bak
webpnpm build打包 dist 上传，清空并回填 nginx 站点根目录（保留 inode）校验 index.html，失败用 .bak 回填
enginepip wheel --no-deps上传 wheel，在 venv 内 pip install --force-reinstall执行 omni-engine-cli --version 自检；失败报错，无自动回滚

所有产物覆盖前生成 .bak.<YYYYmmddHHMMSS>，每个产物保留最近 3 份，超出自动清理。脚本先完成全部本地构建再连接目标机，避免构建失败导致目标机半更新。

目标机配置

连接信息集中在 deploy.py 顶部的 TARGETS，每套包含 host、ssh_port、ssh_user、ssh_password、server_service、server_bin、web_dist、web_nginx_conf、engine_venv。新增环境时复制一份字典，再用 -e 选择。

TARGETS 含明文 SSH 凭据，属敏感配置：不要把真实主机、账号、密码提交到公共仓库或粘贴到文档；建议使用本地私有副本或改用密钥认证。

deploy.py 不部署 omni_server_worker。源码环境若依赖后台异步任务与定时调度，需自行构建 worker 二进制并配置独立的 systemd 服务。

nginx 与验证

脚本不推送目标机 nginx.conf，仅在首次部署 web 后把在用配置归档到 omni-deploy/nginx/ 供参考。源码环境的 nginx 需自行保证：

  • / 回退到 index.html（history 路由）；
  • /api/ 去掉前缀后反代到 system.addr；
  • /uploads/ 反代到后端。
ssh <ssh-user>@<server-host> 'systemctl status omni_server --no-pager'
ssh <ssh-user>@<server-host> 'journalctl -u omni_server -n 100 --no-pager'
curl -fsS http://<server-host>:8888/health
curl -s -o /dev/null -w '%{http_code}\n' http://<server-host>/

启动日志横幅包含版本号，可用于确认实际运行版本。回滚与备份保留策略见升级与回滚。
