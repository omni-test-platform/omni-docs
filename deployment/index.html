部署运维

内容状态：基于代码与配置整理，待产品负责人复核。

质量平台提供三种交付形态，均从源码构建，没有官方镜像仓库拉取流程。生产部署前建议先阅读产品架构中的运行时拓扑，再按下表选择形态。

部署形态

形态适用场景数据库主要组件
Compose 内嵌 MySQL单机交付、POC、小规模生产容器 mysql:8.0，命名卷持久化omni-server、omni-worker、omni-web、mysql
Compose 外部 MySQL已有托管或高可用 MySQL外部 MySQL 8omni-server、omni-worker、omni-web
源码 systemd + nginx不使用 Docker，复用目标机 nginx外部 MySQLsystemd 管理的 omni-server、nginx 静态站点、Jenkins agent 上的 omni-engine

选择建议：

  • 没有现成数据库、希望一条命令跑起来：选内嵌 MySQL。
  • 数据库由 DBA 统一运维、需要备份与高可用：选外部 MySQL。
  • 目标机已有 nginx、禁止容器运行时，或需要沿用现有目录与只读挂载：选源码部署。

部署前确认：目标机时间已同步（影响 JWT 与日志时间）、数据盘容量足够存放上传文件与报告、防火墙放行 Web/API/回调端口、已有数据库备份与回滚方案。

端口

端口用途说明
8888omni-server API由 system.addr 决定；源码环境可能改为其他端口
9527 → 80omni-webCompose 宿主机端口由 .env 的 WEB_PORT 控制
3306MySQL仅内嵌方案映射到宿主机；外部方案由数据库侧开放
8098JenkinsJenkins 通道；具体端口以现场为准

源码部署的 Web 端口取决于目标机 nginx 监听配置，不以 9527 为准；反向代理到后端的地址必须与 system.addr 一致。
