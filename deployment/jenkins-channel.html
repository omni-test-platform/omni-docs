Jenkins 执行通道

内容状态：基于代码与配置整理，待产品负责人复核。

Jenkins 通道让平台把测试任务或计划下发到远端 agent，由 agent 上的 omni-engine 执行并逐用例回调平台。平台只负责触发、轮询与聚合，Allure 报告仍由 Jenkins 托管。

链路与网络

omni-web → omni-server → 触发/轮询/取消 → Jenkins controller
                ↑                              │
                └──── 用例/完成回调 ──── agent（label: linux）
                                               └─ omni-engine
方向要求
omni-server → Jenkins能访问 <jenkins-url>，用于触发 build、轮询状态与取消
agent → omni-server能访问 <callback-base-url>，不能使用 localhost
浏览器 → Jenkins打开构建页与 Allure 报告，需匿名只读或统一登录

agent 前提

  • Linux agent，label 为 linux（与 job 的 agent { label } 一致），已配置远程工作目录与 Java 21。
  • Python 3.12；omni-engine 安装在独立 venv，<engine-venv>/bin/omni-engine-cli 可执行。
  • 已安装 Playwright Chromium；Linux 无 XServer，job 注入 OMNI_WEB_HEADLESS=true。
  • Allure 3 CLI 位于 /usr/bin/allure，Jenkins 全局 Allure3 工具的 home 配置为 /usr/bin。
  • 被测系统依赖 Host 头时，在 agent 的 /etc/hosts 添加域名映射。

平台侧连接

在「AT 设置 → Jenkins 配置」新增一条配置：URL 填 <jenkins-url>，填写用户名与密码或 API Token，启用并设为默认。密码加密存储。平台触发、构建地址与状态轮询都按默认配置解析。

任务级 job 名优先级：执行参数 job_name > 任务字段 jenkins_job_name > default_job_prefix 加默认 job。

回调地址

回调基址解析优先级：

  1. 环境变量 OMNI_CALLBACK_BASE_URL；
  2. 系统配置 system.callback-base-url；
  3. 本机回环默认地址（仅开发）。

平台最终拼接 /at/executions/callback 传给 job。该基址必须是 agent 可达的地址；容器部署时不要填写容器内服务名或 localhost。启用回调签名时，omni-server 与 agent 必须设置相同的 OMNI_CALLBACK_SECRET。

参数化 job

job 定义以 omni-deploy/jenkins/*.groovy 为准，在 Jenkins Script Console 执行以创建或更新参数化 Pipeline。阶段为 Checkout → Restore Task Files → Run omni-engine → Publish Allure。脚本关闭沙箱以注册 Allure 报告动作；首次触发若报 UnapprovedUsageException，需在 Script Console 批准脚本签名。

参数必填说明
TASK_EXEC_ID是平台任务执行记录 ID
CALLBACK_URL是平台回调地址
TASK_FILES是引擎任务文件 JSON，内容为 base64
PARALLEL否并行度，空或 1 为串行
BRANCH否被测代码分支，空则用 job 默认值
REPORT_NAME否报告名
ENV_NAME/ENV_URL/ENV_VERSION/PRODUCT_NAME否报告 Environment 元数据
CASE_LOG_DIR否用例日志目录，必须落在共享存储

共享存储

平台读取路径为 <enginePath>/reports/case-logs/task-<TASK_EXEC_ID>/。omni-server 与所有可能执行任务的 agent 必须把该目录挂载到完全相同的绝对路径，并保证 Jenkins 用户可写、omni-server 运行用户可读。各节点使用本地目录会导致平台读不到日志。日志按 10 MB 轮转、保留 1 天。

Allure 匿名只读

平台跳转 Allure 时不携带 Jenkins 登录态。使用 Matrix-based security 给 Anonymous 授予 Overall/Read、Job/Read、View/Read，不要授予 Configure、Build、Delete、Administer。验证：

curl -s -o /dev/null -w '%{http_code}\n' \
  <jenkins-url>/job/<job-name>/<build-no>/allure/

返回 200 后用无痕窗口确认报告有数据。匿名只读会暴露 job 名称与构建历史，安全要求高时改用更细粒度授权。

验证清单

  1. Jenkins 配置已启用且为默认，回调基址为 agent 可达地址，任务已配置 job 名。
  2. 触发任务后，omni-server 日志出现触发 build 记录。
  3. Jenkins 四个阶段全部成功，console 能看到逐条用例结果。
  4. 平台任务进度实时更新，执行记录落到终态。
  5. 报告页能打开对应执行记录，Allure 链接可访问。
  6. 用例日志目录在双端路径一致且可读。

常见失败见故障排查；平台侧集成配置见管理员指南 · 集成。
