Docker Compose 部署

内容状态：基于代码与配置整理，待产品负责人复核。

前提

  • omni-deploy、omni-server、omni-web 位于同一父目录：两套编排的构建上下文分别是 ../omni-server 与 ../omni-web。
  • 已安装 Docker Engine 与 Compose v2（命令为 docker compose，不是 docker-compose）。
  • 两套编排共用 project name 与容器名，同一主机只能启用一套。

两套编排

文件包含服务服务端配置数据卷
docker-compose.ymlmysql、omni-server、omni-worker、omni-webconfig/production.yamlmysql_data、uploads、server_logs
docker-compose.external-mysql.ymlomni-server、omni-worker、omni-webconfig/production.external-mysql.yamluploads、server_logs

外部 MySQL 需提前创建数据库（utf8mb4）并授予账号权限；启动前修改配置中的 mysql.path、username、password、db-name。外部编排不等待数据库健康检查，数据库未就绪时由 restart: unless-stopped 自动重试。

启动与停止

内嵌 MySQL：

cd omni-deploy
docker compose config
docker compose up -d --build
docker compose ps
docker compose logs -f omni-server

外部 MySQL：

docker compose -f docker-compose.external-mysql.yml up -d --build

访问 http://<server-host>:9527 打开 Web，http://<server-host>:8888/swagger/index.html 查看 API 文档。

常用操作：

docker compose down                  # 停止并删除容器，保留数据卷
docker compose down -v               # 同时删除 mysql_data/uploads/server_logs
docker compose up -d --build omni-server
docker compose exec omni-server sh
docker compose logs -f omni-worker

数据卷

卷容器路径内容
mysql_data/var/lib/mysql数据库文件
uploads/app/uploads上传文件与报告产物
server_logs/app/logs后端日志

down 不会删除命名卷，down -v 会清空全部数据；生产执行前先完成备份。

初始化

  • omni-server 与 omni-worker 每次启动都会执行 GORM AutoMigrate，补建缺失的表和列，幂等且只加不删。
  • omni-server 启动命令带 -init-db，首次启动注入菜单、角色、字典等种子数据，重复执行幂等；worker 不带该参数。
  • 需要纯运行环境时，可从 compose 的 omni-server command 中移除 -init-db，但升级新增的种子数据也不会自动写入。

首次 up --build 需要下载基础镜像并编译 Go、Vue 产物，耗时取决于网络与机器性能；后续只在源码变化时重建对应服务。容器异常退出由 restart: unless-stopped 自动拉起，持续重启时应查看日志定位根因，而不是反复手动启动。

注意项

  1. MySQL 密码需在 .env、docker-compose.yml 的回退默认值与 config/production.yaml 三处保持一致，详见配置。
  2. 宿主端口冲突时修改 .env 的 WEB_PORT、SERVER_PORT、MYSQL_PORT，再执行 docker compose config 校验。
  3. 前端构建读取 omni-web/.env.prod 的 VITE_SERVICE_BASE_URL，当前默认 /api，由容器内 nginx 去掉前缀后反代到 omni-server:8888；不要改成指向宿主机的绝对地址。
  4. 容器之间通过服务名 mysql、omni-server 互访，不要填写宿主机 IP。
  5. IMAGE_TAG 决定镜像标签。生产按发布版本打 tag，便于回滚，见升级与回滚。

验证

curl -fsS http://<server-host>:8888/health
curl -s -o /dev/null -w '%{http_code}\n' http://<server-host>:9527/
docker compose ps

健康检查成功、Web 返回 200、所需服务均为 running 即部署完成。
