备份与恢复

内容状态：基于代码与配置整理，待产品负责人复核。

脚本位于 omni-deploy/scripts/backup.sh 与 restore.sh，只依赖 mysqldump、mysql、gzip、tar。恢复演练目标 RTO 小于 2 小时，演练库与生产库隔离。

备份

变量默认说明
DB_CONTAINER空设置后在容器内执行 mysqldump，并忽略 DB_HOST/DB_PORT
DB_HOST本机回环地址直连模式数据库主机
DB_PORT3306直连模式端口
DB_NAMEomni数据库名
DB_USERroot数据库用户
DB_PASSWORD无直连模式必填；容器模式作为 MYSQL_PWD 传入
BACKUP_DIR/opt/omni-platform/backups备份目录
BACKUP_KEEP14数据库备份保留份数，必须为正整数
INCLUDE_UPLOADS0为 1 时同时打包上传目录
UPLOADS_DIR/opt/omni-platform/uploads/file上传目录

容器模式：

cd omni-deploy
DB_CONTAINER=<db-container> DB_NAME=omni DB_PASSWORD=<db-password> \
  BACKUP_DIR=/opt/omni-platform/backups BACKUP_KEEP=14 \
  ./scripts/backup.sh

直连模式：

DB_HOST=<mysql-host> DB_PORT=3306 DB_USER=<db-user> DB_PASSWORD=<db-password> \
  DB_NAME=omni BACKUP_DIR=<backup-dir> ./scripts/backup.sh

不要同时设置 DB_CONTAINER 与 DB_HOST。

产物：omni-YYYYmmdd-HHMMSS.sql.gz（结构 + 数据，--single-transaction）；uploads-YYYYmmdd-HHMMSS.tar.gz（仅 INCLUDE_UPLOADS=1）。脚本校验文件非空，失败以非零状态退出；保留策略只清理 omni-*.sql.gz，上传包需自行轮转。

定时示例：

15 2 * * * cd /opt/omni-platform/omni-deploy && DB_CONTAINER=<db-container> DB_NAME=omni DB_PASSWORD=<db-password> BACKUP_DIR=/opt/omni-platform/backups BACKUP_KEEP=14 ./scripts/backup.sh >> /var/log/omni-backup.log 2>&1

Compose 部署的 uploads 是命名卷，默认 UPLOADS_DIR 指向宿主目录并不适用；需要时先把同一目录挂载到宿主机，或进入容器打包。

恢复

变量必填说明
BACKUP_FILE是.sql.gz 备份文件
TARGET_DB是目标库，不存在会自动创建
CONFIRM是必须等于 TARGET_DB
ALLOW_PROD否目标库与 DB_NAME 同名时必须为 1
DB_*条件连接信息同备份
BACKUP_FILE=<backup-dir>/omni-<timestamp>.sql.gz \
TARGET_DB=omni_restore_drill CONFIRM=omni_restore_drill \
DB_CONTAINER=<db-container> DB_NAME=omni DB_PASSWORD=<db-password> \
  ./scripts/restore.sh

保护机制：缺少 TARGET_DB 或 CONFIRM 不匹配直接退出；目标库与生产库同名时默认拒绝；备份文件包含 USE/CREATE DATABASE 语句时拒绝导入（旧版 --databases 导出格式）。导入后输出 sys_users、at_test_cases、at_test_tasks、at_task_executions、at_plan_executions 行数。

演练与生产恢复

  1. 备份生产库。
  2. 恢复到 omni_restore_drill 等临时库。
  3. 对比备份时点行数；备份后生产库继续写入，当前生产计数更大属正常。
  4. 确认后删除临时库。

恢复生产库前停止 omni-server 与 omni-worker，避免恢复期间继续写入；恢复后启动并检查 /health、登录与 AT 任务列表。报告产物不在数据库备份内，位于 uploads/file/reports，受 at.execution.artifact-retention-days（默认 90 天）清理；需要长期保留时用 INCLUDE_UPLOADS=1 或单独做文件快照。

备份含密码哈希与凭据密文，按敏感数据管理：限制目录权限、加密存储、不放入公开仓库或聊天工具。升级流程见升级与回滚。
