故障排查

内容状态：基于代码与配置整理，待产品负责人复核。

命令按部署形态选择：Compose 使用 docker compose，源码部署使用 systemctl/journalctl。把 <...> 换成实际值，不要在工单或文档中粘贴真实密码与 Token。

启动失败

docker compose ps
docker compose logs --tail=300 omni-server
docker compose config >/dev/null && echo config-ok
curl -fsS http://<server-host>:8888/health

源码部署：

systemctl status omni_server --no-pager -l
journalctl -u omni_server -n 300 --no-pager

先看日志第一条 error：配置解析失败、数据库连不上、端口占用、License 异常最常见。容器反复重启时用 docker inspect --format '{{.State.ExitCode}}' omni-server 查看退出码。

端口冲突

ss -lntp | grep -E ':(8888|9527|3306)\b'
docker compose ps

修改 .env 的 SERVER_PORT、WEB_PORT、MYSQL_PORT 后执行 docker compose up -d。源码部署需同时确认 nginx 反代端口与 system.addr 一致；deploy.py 不以端口监听作为就绪判断。

MySQL 凭据不一致

docker compose logs omni-server | grep -iE 'access denied|unknown database'
docker compose config | grep -E 'MYSQL_ROOT_PASSWORD|MYSQL_DATABASE'
docker compose exec mysql mysql -u<db-user> -p<db-password> -e 'SELECT 1'

内嵌方案同步 .env、compose 回退值、production.yaml 的 mysql.password。外部方案检查 production.external-mysql.yaml 的 path、port、db-name、username、password，并在数据库侧确认账号授权与库已创建。容器内连通性可用 docker compose exec omni-server sh -c 'nc -vz mysql 3306'。

JWT 重启后失效

症状：重启后所有用户被登出，接口返回“无效签名”。原因是 jwt.signing-key 为空，进程每次启动生成随机密钥。

docker compose exec omni-server sh -c 'grep -n "signing-key" /app/config/production.yaml'
docker compose logs omni-server | grep -i '无效签名'

配置固定密钥，或设置 JWT_SIGNING_KEY 环境变量后重启一次。更换密钥会让现有 token 全部失效，需通知用户重新登录。见配置。

回调失败

# 在 agent 上验证平台回调地址可达
curl -sS -o /dev/null -w '%{http_code}\n' -X POST \
  <callback-base-url>/at/executions/callback \
  -H 'Content-Type: application/json' -d '{}'
docker compose logs omni-server | grep -iE 'callback|回调'

返回 4xx 说明网络可达但请求不完整，属正常；连接超时或拒绝则是网络或地址问题。确认回调基址不是 localhost、agent 防火墙已放行、启用签名时 OMNI_CALLBACK_SECRET 两端一致。

Allure 无法访问

curl -s -o /dev/null -w '%{http_code}\n' \
  <jenkins-url>/job/<job-name>/<build-no>/allure/
curl -s <jenkins-url>/job/<job-name>/<build-no>/consoleText | tail -n 80

403：未给 Anonymous 只读权限。200 但空白：检查 Publish Allure 阶段是否失败、OMNI_KEEP_ALLURE_RESULTS=true 是否生效、allure-results 中是否有 *-result.json。构建被清理后链接也会失效，需调整保留策略。见Jenkins 执行通道。

License 异常

docker compose logs omni-server | grep -iE 'license|授权|过期'
curl -s -H 'x-token: <token>' http://<server-host>:8888/system/license/info
curl -s -H 'x-token: <token>' http://<server-host>:8888/system/license/machine-code

接口返回 LICENSE_RESTRICTED 表示当前 License 未授权该功能模块。核对机器码与签发时是否一致（机器码由 Host UUID 与 CPU 指纹派生）、有效期是否过期、模块是否覆盖该功能。签发、导入与续期见管理员指南 · License。

日志位置

来源位置或命令
API 容器 stdoutdocker compose logs -f omni-server
Workerdocker compose logs -f omni-worker
后端文件日志命名卷 server_logs → 容器 /app/logs；zap.director=logs
Web/Nginxdocker compose logs omni-web；源码部署为 /var/log/nginx/
systemdjournalctl -u omni_server -f
Jenkinsjob 构建页 Console Output；Allure 在 /job/<job-name>/<build-no>/allure/
用例日志<enginePath>/reports/case-logs/task-<TASK_EXEC_ID>/

排查前先确认日志级别（zap.level）与时间范围，避免只看容器启动瞬间的输出。
