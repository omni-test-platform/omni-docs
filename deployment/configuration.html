配置

内容状态：基于代码与配置整理，待产品负责人复核。

部署配置分两层：.env 只被 Compose 读取，负责镜像标签、宿主端口与内嵌 MySQL 初始凭据；config/production*.yaml 是服务端运行配置。全量字段索引见配置索引，本页只讲部署时最容易出错的项。

.env（6 项）

变量默认/示例作用
IMAGE_TAGlatest构建镜像标签；生产按版本打 tag 便于回滚
WEB_PORT9527Web 宿主机端口
SERVER_PORT8888API 宿主机端口
MYSQL_PORT3306内嵌 MySQL 宿主机端口
MYSQL_ROOT_PASSWORD<db-password>内嵌 MySQL root 密码
MYSQL_DATABASEomni内嵌 MySQL 初始数据库

修改后先执行 docker compose config 校验展开结果，再执行 docker compose up -d 生效。

production.yaml 分组

JWT signing-key

签名密钥解析优先级：环境变量 JWT_SIGNING_KEY > 配置文件 jwt.signing-key > 进程内随机生成。两者都为空时，每次重启都会生成新密钥，重启前签发的 token 全部报“无效签名”。生产必须显式配置固定值。

修改签名密钥会使所有已登录会话立即失效，需提前通知用户重新登录。

encrypt-key

system.encrypt-key 用于加密落库的凭据字段（如测试环境密码、集成账号密码）。服务启动时对其做 SHA-256 派生，得到 AES-256 密钥：

  • 配置为空时回退 jwt.signing-key；
  • 两者都为空时回退代码内置常量。

该密钥必须在首次写入凭据前确定，写入后不可更换，否则历史密文无法解密。升级与迁移时连同配置文件一起备份。

MySQL 密码一致性

内嵌方案中密码出现在三处，必须同步修改：

  1. .env 的 MYSQL_ROOT_PASSWORD；
  2. docker-compose.yml 中环境变量与健康检查的 ${MYSQL_ROOT_PASSWORD:-<默认值>} 回退值；
  3. config/production.yaml 的 mysql.password。

外部方案只需保证 config/production.external-mysql.yaml 的 mysql.password 与数据库实际密码一致。验证：

docker compose config | grep -A3 MYSQL_ROOT_PASSWORD
docker compose exec omni-server sh -c 'grep -n "password" /app/config/production.yaml'
docker compose logs omni-server | grep -i 'access denied'

最后一条无输出表示未出现认证失败。更多参数含义见配置索引。
