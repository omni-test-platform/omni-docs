10 分钟部署

内容状态：基于代码与配置整理，待产品负责人复核。

适用范围

本页只给「Compose + 内嵌 MySQL + 源码构建」的最短可运行路径，用于试用、演示和功能验证。生产环境请继续阅读部署运维，按外部 MySQL、备份、升级与 Jenkins 通道的要求实施。

前提

  • 已安装 Docker Engine 24+ 与 Docker Compose v2。
  • omni-deploy、omni-server、omni-web 位于同一级目录；Compose 的构建上下文指向 ../omni-server 与 ../omni-web。
  • 宿主机的 9527、8888、3306 未被占用；机器建议 4 核 8 GB 起步。
  • 平台没有官方镜像 pull 流程，首次启动会从源码构建。

部署步骤

  1. 进入部署目录并检查配置：
cd omni-deploy
docker compose config
  1. 编辑 .env，至少设置数据库密码与端口：
IMAGE_TAG=latest
WEB_PORT=9527
SERVER_PORT=8888
MYSQL_PORT=3306
MYSQL_ROOT_PASSWORD=<MySQL root 密码>
MYSQL_DATABASE=omni

  1. 编辑 config/production.yaml，让 mysql.password 与上一步一致；mysql.path 保持 Compose 服务名 mysql，db-name 与 MYSQL_DATABASE 一致。

  2. 构建并后台启动：

docker compose up -d --build
  1. 查看状态与首次启动日志：
docker compose ps
docker compose logs -f omni-server

端口与数据卷

服务宿主端口说明
omni-web9527Nginx 静态站点，/api 反向代理到后端
omni-server8888REST API 与 Swagger
mysql3306仅内嵌方案；生产建议不直接暴露到公网

命名卷 mysql_data、uploads、server_logs 分别保存数据库、上传文件和日志；docker compose down 不会删除它们，down -v 会清空，执行前务必确认。

首次初始化与账号

omni-server 的启动命令带有 -init-db，首次启动会自动建表并注入菜单、角色、字典等种子数据；初始化逻辑幂等，重复启动无害。

初始账号以种子配置为准。 不要在文档或工单中记录真实密码；首次登录后立即修改初始密码，并确认管理员已按交付要求替换种子账号。

验证

  1. 浏览器打开 http://<host>:9527，能看到登录页。
  2. 打开 http://<host>:8888/swagger/index.html，能看到 API 文档。
  3. docker compose ps 中 mysql、omni-server、omni-worker、omni-web 均为运行状态。
  4. 用初始账号登录，进入首页；后续步骤见首次登录与初始化。

停止、回滚与排障

# 停止但保留数据
docker compose down

# 重新构建单个服务
docker compose up -d --build omni-server
  • 数据库认证失败：检查 .env 的 MYSQL_ROOT_PASSWORD 与 config/production.yaml 的 mysql.password 是否一致。
  • 页面能打开但接口报错：确认 omni-web 构建使用生产环境配置，浏览器请求走 /api，且 Nginx 能解析 omni-server。
  • 首次启动慢或构建失败：确认三个仓库目录关系、网络与 Docker 资源；构建阶段需要拉取 Go/Node 依赖。
  • 端口冲突：修改 .env 的 WEB_PORT、SERVER_PORT、MYSQL_PORT 后重新 docker compose up -d。
