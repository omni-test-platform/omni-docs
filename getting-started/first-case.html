第一个自动化用例

内容状态：基于代码与配置整理，待产品负责人复核。

用途

用一条 API 用例走通「建用例 → 建任务 → 绑用例 → 执行 → 看结果」的最短闭环；复杂编排见用户手册 · AT。

入口与前置

  • 已登录并选择当前产品，见首次登录与初始化。
  • 账号具有测试平台与「接口测试 / 测试执行」菜单权限；License 需含 test-platform（Standard+）。
  • 至少有一个可用执行环境；没有时先在「测试平台 → 环境与配置 → 环境管理」创建，字段以实际页面为准。
  • 被测服务地址需从执行节点可达；走 Jenkins 通道还需管理员配置 job 与 agent。

操作步骤

  1. 打开「测试平台 → 接口测试 → 单接口用例」，点击「+ 新建用例」。
  2. 填写用例名称（必填），按需选择所属接口；选择接口后部分字段可能自动带入。
  3. 填写请求方法、请求路径（以环境服务地址为基准，如 /api/v1/users）；是否支持完整 URL 以页面提示为准。
  4. 按需填写请求头、请求体（JSON）与预期结果；无请求体可保留空对象。点击「保存」。
  5. 进入「测试执行 → 测试任务」，新建任务，类型可选「用例集合」，填写名称、执行环境、分支与关联版本；必填项以页面为准，无可选版本需先同步或配置。
  6. 保存后，在任务行点击「配置用例」，在「API测试」页签中勾选用例，确认加入。
  7. 在任务行点击「执行」，按需覆盖环境、版本或填写临时参数，点击「确认执行」。
  8. 查看进度；结束后打开「执行记录」或「测试报告」查看结果、耗时与日志。

字段与状态

字段/区域说明
用例名称必填，用于检索与报告展示
所属接口可选，关联接口定义
请求方法 / 请求路径方法与环境基准路径
请求头 / 请求体JSON 格式；无内容时保留 {}
预期结果期望状态码或关键响应；断言解析以实际执行为准
优先级 / 描述用于筛选与说明，不影响执行
执行环境任务使用的环境，可临时覆盖
分支 / 关联版本执行上下文，影响报告归档与回填
用例数为 0 时任务无法执行，需先配置用例
执行状态待执行、执行中、成功、失败、已取消

注意事项与 FAQ

  • 任务执行按钮不可点？ 用例数为 0，先点「配置用例」。
  • 执行失败但接口正常？ 检查执行节点网络、环境地址与凭据，以及路径是否重复拼接前缀。
  • 找不到刚建的用例？ 列表按当前产品过滤，确认顶部产品一致，或按名称搜索。
  • 需要更细的断言？ 单接口用例只做基础请求；复杂场景用 API/场景用例或在执行引擎中写 pytest。
  • 报告在哪里？ 任务详情与「测试报告」页均可查看；Allure 访问方式见测试报告。
