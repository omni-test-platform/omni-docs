快速开始

内容状态：基于代码与配置整理，待产品负责人复核。

这一组文档解决什么

用最短路径把平台跑起来，并完成「登录 → 理解概念 → 创建第一个用例并执行」的闭环。生产部署、配置、升级与排障不在本组展开，见部署运维。

推荐阅读路径

顺序页面产出
110 分钟部署用 Compose 内嵌 MySQL 启动 Web、API、worker 与数据库
2首次登录与初始化登录、确认初始化、修改密码、选择产品与角色
3核心概念理解产品/项目、角色、用例、套件、执行、环境、报告
4第一个自动化用例创建 API 用例、编排任务、执行并查看结果

只想先看产品能力，可读产品介绍与平台架构。

环境要求

项要求
DockerDocker Engine 24+
ComposeDocker Compose v2（使用 docker compose 命令）
机器配置建议 4 核 CPU、8 GB 内存起步；源码构建镜像时预留足够磁盘与构建时间
端口9527（Web）、8888（API）、3306（MySQL）未被占用；可在 .env 中改宿主端口
浏览器Chrome 90+（推荐最新稳定版）
源码布局omni-deploy、omni-server、omni-web 位于同一级工作区，Compose 构建上下文依赖该布局
执行网络若使用 Jenkins 通道，server 需能访问 Jenkins，Jenkins agent 需能访问引擎与回调地址

按角色选择路径

角色建议
业务用户部署完成后直接读首次登录、核心概念、第一个自动化用例
管理员/实施先读部署，再读管理员指南与部署运维
引擎使用者读执行引擎，了解独立使用与平台内使用的差异
开发者读开发与参考与平台架构

说明

  • 默认数据库为 MySQL 8；Compose 方案会启动内嵌 MySQL，也可复用外部实例。
  • 平台是模块化单体，API 与 worker 共用镜像、不同入口；测试执行由 Jenkins 调度引擎完成。
  • 页面字段与按钮可能随版本调整，文档中标注「以实际页面为准」的地方请以当前环境为准。
