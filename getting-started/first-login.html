首次登录与初始化

内容状态：基于代码与配置整理，待产品负责人复核。

用途

完成首次登录，确认初始化，设置产品与角色，修改初始密码。

入口与前置

  • 入口：http://<host>:9527，未登录时会进入 /login。
  • 前置：平台已部署且 API 正常；已获得初始账号，初始账号以种子配置为准；浏览器 Chrome 90+。
  • 推荐先完成10 分钟部署，确认 omni-server 启动日志无数据库或 License 错误。

界面区域

登录页含用户名、密码、登录按钮与「记住我」；连续失败后出现图形验证码，点击可刷新。验证码登录、注册、找回密码入口以配置为准。

登录后，顶栏显示产品，头像菜单显示角色与退出登录。

操作步骤

  1. 打开 http://<host>:9527，输入用户名与密码，点击登录/确认按钮。
  2. 若出现图形验证码，按图片输入；验证码错误会阻止本次登录。
  3. 确认初始化：首次登录应能进入首页并看到菜单。若提示未初始化、接口 502 或菜单为空，先回部署侧检查 -init-db 与日志。
  4. 修改初始密码：点击右上角头像 →「个人信息」→「修改密码」，输入原密码、新密码并再次确认。
  5. 选择产品：点击顶栏产品选择器。若尚未设置，系统会自动选择第一个可见产品。
  6. 切换角色（可选）：头像菜单 →「切换角色」，选择另一个已分配角色；切换后页面会刷新，菜单与按钮权限随角色变化。

字段与状态

字段/状态说明
用户名、密码由管理员创建；初始账号以种子/交付配置为准
图形验证码连续失败达到阈值后出现，用于防暴力尝试
记住我登录页选项；是否影响会话保持以实际版本为准，公用电脑不建议勾选
当前产品决定项目、QA、AT 等页面的数据上下文；产品与项目一对一
当前角色用户可能有多个角色，同一时刻只有一个激活角色
原密码/新密码/确认新密码修改密码必填；新密码需满足系统安全策略

注意事项与 FAQ

  • 初始化由谁完成？ 推荐路径下由 omni-server 的 -init-db 自动建表并注入种子；源码部署首次启动也要带该参数。前端 /init 是预留入口，推荐流程不依赖它，是否可用以实际页面为准。
  • 忘记密码？ 联系管理员重置；邮件自助重置取决于配置。
  • 登录成功但看到 403？ 当前角色没有该菜单或接口权限，联系管理员在「权限管理」中授权。
  • 产品下拉为空？ 没有已同步且对当前角色可见的产品；检查禅道同步、产品授权与平台监管开关。
  • 看不到「切换角色」？ 账号只有一个角色时不会显示该菜单。
  • 是否强制首次改密？ 安全配置提供「新用户首次登录强制改密」开关（默认关闭）；无论是否开启，都建议立即改密。
