本地开发

内容状态：基于代码与文档整理，待产品负责人复核。

本地开发不经过 Nginx：浏览器直连 Vite 开发服务器，Vite 按 VITE_SERVICE_BASE_URL 访问 8888 的 API。最小闭环是“后端 + 前端”，需要执行用例时再加“引擎 + Jenkins 或本地通道”。

浏览器 → Vite 9527（/proxy-default）→ omni-server 8888 → SQLite/MySQL
执行用例：omni-server → 本地/SSH/Jenkins → omni-engine → 回调 omni-server

启动后端

仓库已带 conf/.env.debug.yaml，可直接使用；若本地缺失，再从模板复制一份。

cd omni-server
cp conf/.env.example.yaml conf/.env.debug.yaml
go run cmd/api/main.go -c conf/.env.debug.yaml -init-db -gin-mode debug

-init-db 写入菜单、角色、字典等种子数据，可重复执行；-gin-mode debug 打开 Gin 调试日志。调试配置默认 db-type: sqlite，数据库文件落在 omni-server/ 工作目录，不需要额外安装数据库。

Windows 下也可运行仓库根目录的 run_server.bat，它等价于 go run cmd/api/main.go -init-db -gin-mode debug。脚本内的工作目录是本机绝对路径，迁移仓库后需改成自己的路径；它不带 -c，会使用服务端默认配置文件。初次运行建议仍显式指定 -c conf/.env.debug.yaml，避免默认配置指向 MySQL 或联调环境。

本地不想导入 License 时，用 licensefree 构建标签跳过校验：

go run -tags licensefree ./cmd/api/main.go -c conf/.env.debug.yaml -init-db -gin-mode debug

该模式只用于开发，生产构建不得带此标签。

启动前端

cd omni-web
pnpm install
pnpm dev

开发服务器默认 http://127.0.0.1:9527，支持 HMR。.env.development 已把 API 指向 http://127.0.0.1:8888，并通过 Vite 代理避免跨域。若后端端口改变，同步修改 VITE_SERVICE_BASE_URL。

仓库根目录的 run_web.bat 封装了 npm run dev / build / preview 等命令；项目使用 pnpm workspace，建议仍以 pnpm 为准。

启动引擎

cd omni-engine
python -m venv venv
# Windows: venv\Scripts\activate
# Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
pip install -e .
omni-engine-cli --version

需要 K8s、混沌、性能或 AI 能力时，再安装对应 extras，例如 pip install -e ".[k8s,chaos,performance,ai]"。平台内执行还要求 agent 上有可用的 Jenkins job、Python 虚拟环境与共享日志目录，见部署运维 · Jenkins 通道。

验证

curl http://127.0.0.1:8888/health
curl http://127.0.0.1:8888/version
  • /health 返回成功表示数据库可用；数据库不可用时返回 503。
  • /version 返回服务端构建版本。
  • Swagger UI：http://127.0.0.1:8888/swagger/index.html。
  • 浏览器打开 9527，使用初始化账号登录；默认账号与改密流程见首次登录。

常见问题与边界

  • 端口冲突：8888 被占用时改 system.addr，并同步前端 VITE_SERVICE_BASE_URL。
  • SQLite 只适合单机开发，生产必须使用 MySQL 或 PostgreSQL。
  • 本地调试配置可以写占位密码，但不要提交真实凭据；密钥、Token、回调 Secret 一律走环境变量或本机配置。
  • 修改后端表结构时，必须同时更新实体与 migrations/ 脚本，见贡献指南。
  • 全量配置项见配置索引，Docker 形态见部署运维。
