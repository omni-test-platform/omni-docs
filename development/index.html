开发

内容状态：基于代码与文档整理，待产品负责人复核。

本栏目面向需要阅读、扩展或二次开发 Omni 平台的工程师。产品运行形态见平台架构，这里只讲代码如何分层、请求如何流转，以及改代码前必须知道的协议与约定。

页面索引

页面内容建议前置
代码架构六仓库调用链、Controller→Service→Repository、API/worker、执行数据流无
本地开发run_server.bat / run_web.bat、licensefree、本地 venv、无 Nginx 联调代码架构
API 约定Swagger 入口、鉴权、响应码、分页与路径前缀代码架构

前端开发动态路由、后端菜单、i18n、按钮权限、目录约定代码架构
贡献指南分支、提交规范、OpenSpec、各仓库验证要求本地开发

建议阅读顺序

  1. 先读代码架构，建立“请求从哪进、数据往哪落、执行如何回传”的整体图。
  2. 按需进入本地开发跑起前后端；只在排查接口时读API 约定。
  3. 改执行链路或接入新执行器时，再读回调协议。
  4. 改页面前读前端开发；提交前按贡献指南自检。

前置知识

  • 后端：Go、Gin、GORM、Casbin 的基本用法，了解分层与依赖注入即可。
  • 前端：Vue 3、TypeScript、Vite、Pinia 与 Vue Router；不要求先读完整框架源码。
  • 引擎：Python、pytest、虚拟环境与 entry_points；做扩展时再看插件注册表。
  • 交付：Docker Compose、Nginx 与 systemd 的常见操作，便于理解本地与生产的差异。

事实口径

  • 代码与配置是唯一事实源。页面与仓库注释冲突时，以当前代码为准，并在页面中标注差异。
  • 组件版本以各仓库版本文件为准，产品版本统一为 v1.1.2，差异见兼容矩阵。
  • 本栏目所有页面为 draft，表示内容完整但尚未经产品负责人逐页复核。

边界

本栏目不替代各仓库的 README 与 openspec/ 变更记录，也不描述生产部署步骤。部署形态见部署运维，引擎自身用法见执行引擎。
