前端开发

内容状态：基于代码与文档整理，待产品负责人复核。

omni-web 采用 Vue 3 + Vite + Naive UI + Pinia，路由由 @elegant-router/vue 依据 src/views/ 目录生成，业务路由在运行时从后端加载。本页讲改页面前必须遵守的约定；页面长什么样由业务模块决定，不在此展开。

分层与调用链

src/views/<module>/<page>/index.vue
   │ 使用 hooks / service/api
   ▼
src/service/api/**  →  request 封装（x-token、错误码、续期）
   ▼
src/store/modules/{auth,route,tab}  →  vue-router
  • views 只放页面与页面私有组件，跨页面复用放 src/components。
  • 接口调用统一走 src/service/api/，不要在页面里直接写 axios。
  • 路由、菜单、按钮权限都在 store/modules/route 与 store/modules/auth 中收敛，页面只读结果。

目录与路由约定

  • 每个路由目录对应 src/views/ 下同路径目录，页面文件为 index.vue；动态参数用 [param].vue。
  • 路由名使用小写字母、数字、连字符；多级路由用 _ 连接，如 at_execution_task。
  • 以 _ 开头的目录（如 _components/）不生成路由。
  • 新建页面优先执行 pnpm gen-route，再启动 dev server 触发生成；生成文件在 src/router/elegant/，不要手改。
  • 生产环境 VITE_AUTH_ROUTE_MODE=dynamic：启动后拉取常量路由与用户路由；static 模式仅用于开发或无后端兜底。

后端菜单与动态路由

登录后 initAuthRoute() 调用：

用途实际接口
常量路由GET /system/permission/routes/constants
用户路由GET /system/permission/routes/user
路由是否存在GET /system/permission/routes/exist

/user 返回 { routes, home }。前端把路由树转成 Vue Router 记录后逐条 addRoute，并用 meta.hideInMenu、meta.sort、meta.roles 生成侧边栏与访问控制；一级菜单可用后端 group_name 分组。src/service/api/route.ts 里 /route/... 是旧路径，实际以 src/service/api/system/permission/route/index.ts 为准。

菜单数据在数据库 sys_base_menus 中维护，新增页面后必须同步菜单记录，否则页面存在但侧边栏不可见。

i18n

  • 语言文件：src/locales/langs/zh-cn.ts 与 en-us.ts，两者键必须成对。
  • 路由段必须覆盖全部 RouteKey（类型为 Record<I18nRouteKey, string>）；页面文案放在对应模块的 page 段。
  • 组件中使用 $t('page.at.xxx')；切换语言由 setLocale() 同步 <html lang>。
  • 提交前 pnpm typecheck 会检查缺失的路由键与类型。

按钮权限

后端菜单节点的 btns 是“按钮码 → 数值”的映射。登录后前端遍历路由树，把所有 btns 的键收集到 authStore.userInfo.buttons。页面用：

const { hasAuth } = useAuth();
const canExport = hasAuth('at_execution_export');

hasAuth(codes) 在未登录时返回 false；传数组时命中任意一个即通过。isStaticSuper 只在 static 路由模式下对超级角色生效，动态模式不要依赖它做按钮判断。

示例：新增一个执行报告页

  1. 执行 pnpm gen-route 创建 at_execution_report，确认 src/views/at/execution/report/index.vue 生成。
  2. 在 zh-cn.ts / en-us.ts 的 route 段增加 at_execution_report，在 page 段增加页面文案。
  3. 后端新增菜单记录，路由名与前端一致，按需配置 btns（如导出按钮）。
  4. 在 src/service/api/at/execution/ 增加接口函数，页面通过 useTable 等 hooks 调用。
  5. 运行 pnpm typecheck && pnpm lint，登录后确认菜单、路由与按钮权限都生效。

边界

  • 不要在前端硬编码角色名判断权限，统一用 hasAuth 与后端按钮码。
  • 动态路由下，前端路由表不是权限的最终来源；后端菜单与 Casbin 才是。
  • 目录结构、主题、布局属于框架层，改动前先确认不会影响 _builtin 与生成文件。

权限模型见权限管理，前端在整体链路中的位置见代码架构。
