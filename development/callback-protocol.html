回调协议

内容状态：基于代码与文档整理，待产品负责人复核。

平台接收引擎执行结果的入口是 POST /at/executions/callback。它挂在公开路由组，不校验 JWT，改用 HMAC 签名防伪造；平台按 type 把消息分流为实时用例进度或任务完成汇总。引擎侧的协议视角见平台集成，本页讲平台实际接收的字段与处理规则。

端点与签名

POST /at/executions/callback?pipelineExecID=<id>&stageExecID=<id>
Content-Type: application/json
X-Omni-Sign: <hex(HMAC-SHA256(rawBody, OMNI_CALLBACK_SECRET))>
  • pipelineExecID、stageExecID 可选，用于计划/阶段编排时关联上层执行。
  • 签名对原始请求体字节计算，不是对重新序列化后的 JSON；客户端必须发送与签名时完全一致的字节。
  • OMNI_CALLBACK_SECRET 未配置时跳过校验，便于简单部署；启用时服务端与执行机必须配置同一个值。
  • 校验失败返回业务失败，不写入任何执行记录。
import hashlib, hmac, json, requests

body = json.dumps(payload, ensure_ascii=False, separators=(",", ":")).encode("utf-8")
headers = {
    "Content-Type": "application/json",
    "X-Omni-Sign": hmac.new(secret.encode("utf-8"), body, hashlib.sha256).hexdigest(),
}
requests.post(callback_url, data=body, headers=headers, timeout=30)

统一 payload

字段类型说明
task_idstring平台任务执行 ID（task_exec_id 的字符串形式）
typestringCASE 实时用例；DONE 或空表示完成汇总；STEP 当前未单独处理
statusstringCASE 用例状态：PASSED / FAILED / BROKEN / SKIPPED / RUNNING；完成回调不依赖该字段
case_idint平台用例 ID，可选；缺省时按脚本身份反查
file_path / class_name / method_namestring引擎实际执行的用例身份
resultobject用例结果，常见键为 duration_ms、error、nodeid
progressobjecttotal / current / failed，total 用于校正平台分母
timestampfloat秒级时间戳，用于推算起止时间
start_time / end_timeint完成回调的毫秒时间戳
total / passed / failed / skippedint完成回调的汇总计数
resultsarray完成回调的逐条结果，字段含 status、duration_ms、error_msg、log_path、allure_uuid 等

CASE 消息按 (task_exec_id, test_case_id) upsert 用例执行记录，避免实时回调与完成回填重复写入。case_id 缺失时，平台用 (file_path, class_name, method_name) 反查；反查不到会记录“未纳管用例”并跳过，不会写入伪 ID。

完成回调与 WS 进度

非 CASE 消息进入完成回调路径：按 results 逐条写入用例执行记录并汇总 passed / failed，DONE 只是推荐写法，空 type 也兼容。当前实现按 type != CASE 统一分流，STEP 不会单独写步骤记录；步骤级实时进度需依赖 WS。任务/阶段状态由编排器与轮询收敛，回调本身不直接覆写阶段状态，避免与编排器双写。

WS 进度是引擎侧可选通道：ProgressReport 包含 task_id、type（STEP/CASE/TASK）、step_id、status、duration_ms、step_type、message、progress。report_progress() 每次建立短连接发送一条消息，未配置 WS 地址或发送失败时返回 False，不阻塞执行。平台当前未注册固定 WS 路由；实际页面进度主要来自 CASE HTTP 回调与 GET /at/tasks/{id}/progress（含 SSE 版本）。部署若要启用 WS，需要自行提供接收端并在调用处传入地址。

协议差异

引擎 omni/integrations/platform/protocol.py 还定义了 CaseCallback（/api/v1/at/cases/callback）与 TaskCallback（/api/v1/at/tasks/callback）模型。当前 omni-server 只注册了 /at/executions/callback，未注册这两个路径；生产链路以 Jenkins job 传入的统一回调地址为准。对接旧客户端时，需在网关或客户端侧自行完成路径与前缀映射。

重试与边界

引擎发送端对异常与 5xx 最多重试 max_retries 次，退避为 2^attempt 秒；HTTP 状态小于 500 即视为已送达，因此业务失败仍要看响应 code 与服务端日志。回调在公网暴露时必须启用 OMNI_CALLBACK_SECRET，并限制来源网络；不要在校验失败时重试同一份被篡改的报文。
