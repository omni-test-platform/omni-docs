代码架构

内容状态：基于代码与文档整理，待产品负责人复核。

本页讲代码如何分层、调用如何流转；运行时拓扑、部署形态与仓库定位见平台架构，两页不重复。

六仓库调用链

omni-web (views / router / store)
   │  HTTP + x-token
   ▼
omni-server (router → controller → service → repository → entity)
   │  task service / Jenkins executor
   ▼
Jenkins controller → agent → omni-engine (CLI / pytest)
   │  CASE/DONE 回调 + 进度查询（STEP 依赖 WS）
   └──────────────► omni-server（聚合执行状态）

omni-license ──签发 license.json──► omni-server 本地验签
omni-deploy  ──Compose / systemd / Nginx──► 上述运行物
omni-docs    ──独立静态站──► 不参与平台运行
  • omni-web：页面只做展示与交互，权限判断依赖后端下发的路由与按钮码；不直接连数据库。
  • omni-server：模块化单体，所有业务域的 HTTP 入口、事务、权限与调度都在这里。
  • omni-engine：可独立运行的 pytest 引擎；平台内默认由 Jenkins agent 调用，也支持本地/SSH 通道，结果按协议回传。
  • omni-deploy / omni-license：分别负责交付编排与离线授权，不进入业务请求链路。

服务端分层

Router → Controller → Service → Repository → Entity → DB
          ↑ DTO request        ↑ 事务边界        ↑ GORM
层目录职责
Routerinternal/router/<module>/注册路径、挂 JWT/Casbin/审计/License 中间件
Controllerinternal/controllers/api/v1/<module>/解析 DTO、校验参数、调用 Service、组装响应
Serviceinternal/services/<module>/业务编排、事务、跨模块协作、状态机
Repositoryinternal/repository/<module>/GORM 查询与写入，不主动开事务
Entityinternal/models/entity/<module>/表模型，统一嵌入 common.BaseModel
DTOinternal/models/dto/<module>/request / response，隔离对外契约

每个模块在各层保持同名子目录，用 enter.go 聚合类型、apis.go 统一 API 变量、aliases.go 兼容拆分后的实体别名。

API 与 worker

cmd/api 与 cmd/worker 是两个入口，共用同一镜像与配置：

  • API 进程执行 InitAll 后启动 Gin，处理同步 HTTP 请求，挂 JWT 与 Casbin。
  • worker 进程执行同一套初始化，常驻运行定时任务、异步队列与清理任务。
  • 两者都执行 AutoMigrate 与 License 初始化，因此升级时必须保证配置、数据库与二进制版本一致。

执行数据流

  1. 前端调用任务执行接口，Controller 交给任务 Service。
  2. Service 组装 EngineTask：生成临时 conf.xml、解析用例脚本身份、确定本地/SSH/Jenkins 通道。
  3. Jenkins 通道把 TASK_EXEC_ID、CALLBACK_URL、TASK_FILES 等参数传给参数化 job；agent 还原文件后调用 omni-engine-cli。
  4. 引擎按用例上报 CASE 回调，平台按 task_exec_id 与用例身份 upsert 执行记录并聚合进度；结束后 DONE 回调写入汇总。
  5. 前端轮询任务进度接口或 SSE，报告页读取执行记录与 Allure 地址。

示例：新增一个只读接口

以“查询某任务的执行记录”为例，改动顺序固定为：

  1. internal/router/at/execution/ 注册 GET tasks/:id/executions，挂 License 中间件。
  2. internal/controllers/api/v1/at/execution/ 增加 handler，绑定路径参数并调用 Service。
  3. internal/services/at/execution/ 增加查询方法，处理分页与权限。
  4. internal/repository/at/execution/ 增加 GORM 查询，返回 Entity。
  5. internal/models/dto/at/execution/response/ 定义响应结构，Controller 转 DTO 后返回。

每一层只依赖下一层；跨模块调用走 ServiceGroupApp，不要在 Controller 直接访问 Repository。

边界

  • 运行时拓扑、端口与部署形态见平台架构与部署运维。
  • 引擎内部执行模型与扩展点见执行引擎与扩展开发。
