API 约定

内容状态：基于代码与文档整理，待产品负责人复核。

omni-server 提供 RESTful HTTP API，默认监听 8888。本页只讲调用方需要遵守的通用约定；具体接口以 Swagger 与代码注解为准。

Swagger 入口

服务启动后访问：

http://<host>:8888/swagger/index.html

Swagger 由代码注解生成，产物为 omni-server/docs/swagger.yaml / swagger.json。重新生成：

cd omni-server
make swag

等价于 swag init -g cmd/api/main.go -o ./docs。注解写在 Controller 方法与入口文件的 @Tag 上；新增接口时若忘记写 @Router，Swagger 不会出现该路径，但 Gin 路由仍然生效。

路径前缀

默认 system.router-prefix 为空，业务路径直接以模块名开头：

前缀模块
/system/...登录、用户、角色、菜单、权限、License、日志
/at/...自动化测试：用例、任务、计划、执行、报告、环境
/project/...项目管理、阶段、评审、提测、版本
/qa/...质量分析、评分、门禁、报告
/resource/infra/...CMDB、机房、服务器、IPAM
/resource/inspect/...巡检模板、任务、计划、结果
/ai/...AI 助手、需求分析、技能、模型配置
/integrations/zentao/...禅道产品、用例、缺陷、版本同步
/crontab/...定时任务

部署若配置了 router-prefix（如 /api），所有路径前要加该前缀。反向代理只负责转发，不会自动改写路径。

鉴权

登录接口在公开组，不需要 Token：

curl -s -X POST http://127.0.0.1:8888/system/permission/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"<username>","password":"<password>"}'

成功响应中的 data.token 即 JWT。后续请求放在 x-token 请求头：

curl -s http://127.0.0.1:8888/at/tasks \
  -H 'x-token: <token>'

服务端同时支持从 Cookie 读取 x-token。私有路由组依次经过 JWTAuth() 与 Casbin：JWT 负责身份，Casbin 负责接口权限。Token 接近过期时，响应头会返回 new-token 与 new-expires-at，前端据此无感续期。

响应与错误码

除少数显式使用 HTTP 状态码的接口外，响应体统一为：

{ "code": 0, "msg": "success", "data": {} }
code含义
0成功
7通用业务错误
400参数不合法
401未登录或 Token 无效
403无权限
404资源不存在
409资源冲突（并发编辑、环境占用）
500服务端错误

401、403、404、409、500 在部分 helper 中会同时返回真实 HTTP 状态码；调用方应同时判断 HTTP 状态与 code，不要只看其中一个。

分页与字段

列表接口通用参数为 page、page_size，默认每页 10 条，page_size 上限 100；page_size < 0 表示不分页（仅用于全量树等场景）。字段名使用 snake_case，时间字段多为毫秒时间戳或 RFC3339 字符串，具体以接口定义为准。

边界

  • 回调接口 POST /at/executions/callback 不走 JWT，使用 HMAC 签名，见回调协议。
  • Swagger 可能落后于代码；路径与字段冲突时以路由注册、DTO 与 Service 为准。
  • 平台协同协议中的 /api/v1/at/... 是引擎客户端的契约模型，与 omni-server 当前注册路径存在前缀差异，接入前先确认网关与 router-prefix 配置，见平台集成。
