质量门禁

内容状态：基于代码与页面整理，待产品负责人复核。

质量门禁回答「能否放行」：看板看全局卡点，发布就绪看单产品结论与依据，阻塞清单看什么拖住发布。规则集的增删改只在项目管理侧，本组只读。

用途

  • 一屏查看多项目门禁状态，区分通过、失败、跳过与未配置。
  • 给出四态结论并完整展示判定依据。
  • 合成禅道致命未关闭缺陷与 IPD 项目风险，按阻塞时长排序。

入口与前置

菜单「质量管理 → 质量门禁」，下含「门禁看板」「发布就绪」「阻塞清单」。需 qa-analysis 授权。门禁数据来自项目管理侧已触发校验；缺陷来自禅道，风险来自 IPD。未配规则或未校验的项目不能视为已放行。

界面区域

📷 截图位：待补充（203 测试数据待脱敏）

门禁看板：矩阵行是项目，列是门禁维度（用例通过率、遗留缺陷数、阻塞缺陷数、需求覆盖率、测试执行完成率），末列为结论与校验时间。单元格显示「实际值 运算符 阈值」；「跳过」为灰色，表示取不到数据、未参与判定，与红色「未通过」区分。

发布就绪：顶部为四色结论与理由；下方「判定依据」逐项列通过、未通过、数据不足，展示实际值、要求与是否一票否决。未通过项另列「阻碍发布的问题」。

阻塞清单：顶部为阻塞事项、致命缺陷、项目风险、最久阻塞天数；表列来源、标题、严重度、项目、责任人、状态、已阻塞天数与起始时间。按阻塞时长降序，超过 7 天标红。

操作步骤

  1. 进入「门禁看板」，先看未通过数量与红色单元格。
  2. 悬停单元格查看实际值、阈值与说明；调整规则或重新校验去「项目管理 → 质量门禁」。
  3. 进入「发布就绪」，先读结论与理由，再逐项核对依据，一票否决项优先处理。
  4. 数据不足项单独确认，不能当作通过。
  5. 进入「阻塞清单」，按来源筛选，优先处理阻塞最久的事项。

字段与状态

对象取值含义
门禁结论通过 / 未通过 / 未配规则 / 未校验后两者不等于通过
单元格通过 / 未通过 / 跳过跳过是数据不可得
发布就绪就绪 / 有条件就绪 / 不就绪 / 数据不足数据不足不得显示为就绪
阻塞来源缺陷 / 风险禅道致命未关闭缺陷、IPD 未闭环风险

注意事项与常见问题

  • 能改规则吗？ 不能。规则唯一来源在「项目管理 → 质量门禁」，本页只读。
  • 为什么显示「未配规则」？ 项目管理侧尚未配置规则集，不能视为已放行。
  • 「跳过」是失败吗？ 不是，表示取不到数据、无法判定，页面用灰色区分。
  • 阻塞清单为空但来源缺失？ 页面会提示缺失来源，此时清单可能不完整。
