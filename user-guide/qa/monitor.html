质量监控

内容状态：基于代码与页面整理，待产品负责人复核。

质量监控是「进行时」视图：测试进度看跑到哪、还剩多少，风险预警看什么需要立即处理。

用途

  • 用完成率回答「此刻跑到哪」，用燃尽曲线回答「按当前速度能否跑完」。
  • 标识长时间停留在运行中或等待中的执行，暴露环境或编排问题。
  • 按规则主动发现缺陷超期、反复重开、执行失败率异常等风险，并给出建议动作。

入口与前置

菜单「质量管理 → 质量监控」，下含「测试进度」与「风险预警」。需 qa-analysis 授权。进度数据来自平台执行记录；预警依赖禅道缺陷数据、门禁结果与执行记录，缺失时对应规则不会产生预警。

界面区域

📷 截图位：待补充（203 测试数据待脱敏）

测试进度顶部：用例总数、执行完成率、剩余未执行、卡住的执行数；右侧切换近 7/30/90 天。

燃尽图纵轴为剩余未执行用例，曲线下降速度即执行速度。下方展示「预估完成」；无足够速率时只说明原因，不编造时间。

风险预警列表：按未处理 / 已知悉 / 已解决筛选，顶部显示各严重度数量。表格列为严重度、规则、对象、说明、建议动作、触发时间与操作。

操作步骤

  1. 进入「测试进度」，先确认时间窗口与产品。
  2. 看完成率与剩余量，再看燃尽曲线是否按预期下降。
  3. 若「卡住的执行」大于 0，展开表格查看来源、状态与已持续时长，转交环境或编排负责人。
  4. 进入「风险预警」，默认查看「未处理」。
  5. 点「立即评估」可不等定时任务，手动跑一次规则；点「规则设置」调整阈值、严重度、建议动作与启停。
  6. 对每条预警点「查看」下钻；确认无需处理时标「已知悉」，问题消失后标「已解决」。

字段与状态

对象取值含义
预警状态未处理 / 已知悉 / 已解决默认只看未处理；已处理不反复出现
严重度严重 / 重要 / 轻微列表按严重度排序
规则缺陷超期、长期未解决、反复重开、致命停留、无人认领、执行失败异常、门禁失败覆盖核心异常模式
任务进度完成率、剩余、卡住完成率按计划汇总
结果行计划、总数、已完成、剩余、完成率剩余多的计划排前面

注意事项与常见问题

  • 预估完成可靠吗？ 它是历史速率外推值，需结合燃尽形状判断；数据不足时不给日期。
  • 阈值 0 是什么意思？ 该规则不使用数值阈值，按截止日期或派单状态判定。
  • 预警会重复吗？ 已认领且条件持续时不会重复；条件消失后自动解决。
  • 进度一直是 0？ 检查是否有执行中的计划、执行记录是否已回写。
