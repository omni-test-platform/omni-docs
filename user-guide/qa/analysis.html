质量分析

内容状态：基于代码与页面整理，待产品负责人复核。

五个入口回答：缺陷为何产生、处理快不快、哪个版本更稳、用例是否健康、测试有没有用。

用途

  • 缺陷分析：从存量、趋势、分布、根因、流出定位问题。
  • 时效与版本：分别看处理速度与版本横比。
  • 用例与有效性：看用例资产健康度和测试实际价值。

入口与前置

菜单「质量管理 → 质量分析」，需 qa-analysis 授权。缺陷与用例来自禅道，执行数据来自平台；顶部产品决定范围。未同步时显示空态，不画全 0 图。

界面区域

📷 截图位：待补充（203 测试数据待脱敏）

缺陷分析：五个 Tab。概览为四张分布图；趋势为逐日折线，可选 7/30/90 天或自定义；分布按模块、版本、责任人切换；根因为解决方式、类型、发现阶段横条图；流出含总数、流出率、趋势与明细。

缺陷时效：顶部为平均解决、平均存续、重开率、超期未解决；中部为时长直方图；底部按严重程度列缺陷数与时效。区间可选 30/90 天或全部。

版本对比：选择至少两个版本与指标生成柱状图；表格另列致命占比、重开率、平均解决与 DI，「未关联版本」固定最后。

用例质量：总览展示用例总数、执行率、通过率、自动化率；模块分布为通过/失败/未执行堆叠图；趋势展示三条比率曲线。

测试有效性：展示命中率、命中用例数、评审覆盖、盲区数，可按类型与阶段过滤。散点图横轴用例数、纵轴缺陷数，红点为盲区；右侧为发现阶段分布。

操作步骤

  1. 选择分析入口，确认产品与时间范围。
  2. 缺陷分析先用概览看存量，再看趋势、分布、根因与流出。
  3. 时效分析优先看超期数与长尾桶，注意缺失记录数量。
  4. 版本对比默认选最新两个真实版本，可按需增减。
  5. 有效性分析先按类型/阶段聚焦再解读命中率；盲区表按缺陷数降序。
  6. 异常结论回到质量总览或质量门禁。

字段与状态

分析关键指标判读
缺陷状态、严重度、类型、发现阶段、流出率存量与流量分开
时效TTR、TTL、重开率、超期数未解决不计入 TTR
版本缺陷数、致命占比、遗留、重开率、DI致命占比优先
用例总数、执行率、通过率、自动化率看模块短板
有效性命中率、评审覆盖、盲区低命中率未必是用例差

注意事项与常见问题

  • 命中率低就是测试差吗？ 不是。回归用例本就不应发现新缺陷，先按类型/阶段过滤。
  • 为什么有「未关联版本」？ 影响版本为空的缺陷不推测回填。
  • 数字对不上？ 概览取每日快照，趋势与根因取缺陷明细；未成图指标以页面为准。
