版本管理

内容状态：基于代码与页面整理，待产品负责人复核。

用途

版本是项目在某时间点的交付范围，串联需求、测试计划、提测单与发布评审。版本管理页负责创建版本、维护计划发布时间，并在发布评审通过后执行发布。

入口与前置

  • 入口：顶部「项目」→ 左侧菜单「版本管理」，路径 /project/version。
  • 前置：已在顶栏选择项目；发布前应先发起并完成该版本的发布评审。
  • 新建、编辑、发布、删除需要项目写权限。

界面区域

列表列有版本号、状态、计划发布时间、实际发布时间、发布评审、关联（需求/计划/提测/评审数量）、版本说明与操作。操作包括编辑、发布、删除；已发布或已归档的版本不再允许发布。从里程碑交付物跳转时带 ?id=<版本 ID>，对应行高亮。

新建/编辑抽屉只包含版本号、计划发布时间与版本说明。状态与实际发布时间不在编辑项中：状态由系统流转，实际发布时间在发布成功时写入。

操作步骤

  1. 点击「新建版本」，填写版本号（如 V1.2.0）、计划发布时间与版本说明后保存。
  2. 在测试计划页把计划关联到该版本，在提测管理页按版本提交提测，在评审中心发起该版本的发布评审。
  3. 打开「评审中心」，确认该版本的发布评审结论。
  4. 回到版本管理，点击「发布」。若关联评审已通过或已闭环，发布成功；若未通过、评审中或有条件通过，服务端拒绝并提示原因；若从未发起评审，允许发布但提示未经把关。
  5. 发布后列表显示实际发布时间，版本状态变为「已发布」。

字段与状态

字段/状态说明
规划中 / 开发中 / 已提测版本推进中的状态，具体流转以实际页面为准
已发布发布成功，记录实际发布时间
已归档只读，不再允许修改关联关系
计划发布时间手工填写的计划日期，未填显示「未设置」
实际发布时间发布动作产生的日期，未发布显示 —
发布评审未评审、待评审、评审中、评审通过、有条件通过、评审未通过、评审已闭环
关联数量需求、测试计划、提测单、评审单四类关联计数

注意事项与 FAQ

  • 发布和编辑状态是一回事吗？ 不是。发布是独立动作，编辑接口不接受状态与实际发布时间，避免绕过评审闸门。
  • 评审还没通过能发布吗？ 不能。评审为拒绝、待评审、评审中或有条件通过时，发布会被拒绝。先推动评审闭环。
  • 没发起评审能发布吗？ 可以，但系统会提示「未经评审把关」。建议先完成发布评审。
  • 计划发布时间和实际发布时间有什么区别？ 前者是排期，后者是事实；未发布时实际发布时间为空，不能用计划时间代替。
  • 删除版本会影响什么？ 关联的计划、提测与评审不会自动删除，但会失去版本归属；删除前请确认。
  • 已归档版本还能改吗？ 不能，归档版本只读。
