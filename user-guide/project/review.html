评审中心

内容状态：基于代码与页面整理，待产品负责人复核。

用途

评审中心统一管理需求、用例与发布评审：发起评审、指派评审人、收集意见与结论，并把「有条件通过」的跟进项跟踪到闭环。发布评审结果是版本发布的前置闸门。

入口与前置

  • 入口：顶部「项目」→ 左侧菜单「评审中心」，路径 /project/review。
  • 前置：已在顶栏选择项目；发起发布评审时项目下需已有版本；当前角色需为项目可写角色。
  • 归档或关闭平台监管的项目会被服务端拒绝发起评审。

界面区域

顶部按评审类型与状态筛选，右侧为「发起评审」。列表列有评审标题、类型、状态、结论、说明与操作；从里程碑交付物跳转时带 ?id=<评审单 ID>，目标行高亮但不自动展开详情。

发起评审抽屉包含类型、标题、关联版本（仅发布评审）、评审人与说明。发布评审必须选择版本并至少指定一名评审人，否则结论无法汇总，版本无法通过发布闸门。

详情抽屉分三块：提交意见（通过、有条件通过、拒绝）、意见列表、跟进项。跟进项可填内容、负责人与期望闭环时间，未闭环项可点击「闭环」。

操作步骤

  1. 点击「发起评审」，选择类型，填写标题与说明；发布评审选择关联版本并指定评审人。
  2. 被指派的评审人打开详情，在「提交评审意见」中选择结论并填写意见后提交。
  3. 结论为「有条件通过」时，逐条添加跟进项，指定负责人与期望闭环时间。
  4. 跟进项完成后点击「闭环」，直至全部闭环。
  5. 在列表中按类型或状态筛选，查看评审进展与最终结论。

字段与状态

字段/状态说明
待评审评审单已创建，尚未有人提交意见
评审中已有评审人提交意见，结论尚未汇总
通过 / 有条件通过 / 拒绝评审结论；有条件通过必须产生跟进项
已关闭评审结束；存在未闭环跟进项时不可关闭
评审类型需求评审、用例评审、发布评审
评审人可搜索姓名或账号；发布评审必填
跟进项记录内容、负责人、期望闭环时间与闭环状态

注意事项与 FAQ

  • 发布评审为何必须选版本？ 发布闸门按关联版本反查评审单，没有关联就识别不到，发布便绕开了把关。
  • 发布评审可以不选评审人吗？ 不可以。没有评审人就汇总不出结论，评审单停在「评审中」，版本会被卡死。
  • 跟进项没闭环能关闭吗？ 不能，全部闭环后自动流转为已关闭，具体交互以实际页面为准。
  • 结论能改吗？ 已通过、已拒绝或已关闭的评审单不再显示意见提交区，需重新评审时请新建。
  • 删除评审单有风险吗？ 删除不可恢复，且会影响关联版本的发布依据，操作前请确认。
  • 从里程碑跳转为什么不自动打开详情？ 详情内有可写的意见与跟进项，自动展开容易误触，因此只做行高亮。
