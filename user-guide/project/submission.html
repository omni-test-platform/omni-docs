提测管理

内容状态：基于代码与页面整理，待产品负责人复核。

用途

提测管理承载研发向测试的交付交接：研发提交提测单，测试接收后给出通过或退回结论，终态关闭；同一版本可多次提测，历史全部保留。页面下部汇总禅道缺陷。

入口与前置

  • 入口：顶部「项目」→ 左侧菜单「提测管理」，路径 /project/submit。
  • 前置：已在顶栏选择项目；项目下已有版本或需求可用于关联；缺陷看板依赖禅道同步。
  • 提交、接收、通过、退回、关闭、删除均需要项目写权限。

界面区域

顶部可按状态与版本筛选，右侧为「提交提测」。列表列有提测标题、版本、提测人、自测、状态、缺陷数、提交时间与操作。操作列只显示当前状态可做的事：已提交显示「接收」；测试中显示「通过」「退回」；通过或退回显示「关闭」；任何状态都可「详情」。

详情抽屉展示提测标题、状态、自测结果、关联版本、提交时间、变更范围、自测说明、测试反馈，以及关联需求与关联缺陷；未关联时显示「未关联」，不是加载失败。删除入口也在详情内。

项目缺陷看板展示缺陷总数、未关闭数、按严重级与按状态的分组计数、最近缺陷列表；右上角「同步禅道缺陷」用于拉取最新数据。无数据时显示空态并提示同步。

操作步骤

  1. 点击「提交提测」，填写提测标题、关联版本、关联需求 ID（多个用逗号分隔）、变更范围与自测结果。
  2. 提交后提测单为「已提交」；测试人员点击「接收」，状态变为「测试中」。
  3. 测试完成点击「通过」或「退回」。退回必须填写测试反馈；通过时反馈选填。
  4. 通过或退回后点击「关闭」结束流程；需要查看正文时打开「详情」。
  5. 在缺陷看板点击「同步禅道缺陷」刷新缺陷统计与最近缺陷。

字段与状态

字段/状态说明
已提交研发已提交，等待测试接收
测试中测试已接收，等待结论
通过 / 退回测试结论；退回必须填写反馈
已关闭终态，流程结束
自测通过 / 未通过；未通过不允许提交
变更范围必填，说明本次改动内容
关联需求 / 版本至少关联其一，否则准入校验拒绝
缺陷数该提测单关联的缺陷数量，由服务端统计；0 表示确实未关联

注意事项与 FAQ

  • 提测提交不了？ 准入条件为自测通过、变更范围非空、至少关联一个需求或版本；校验在服务端执行。
  • 同一版本能提测多次吗？ 可以。每次提测独立成单，历史不覆盖，版本视图可看到多次提测与各自结论。
  • 退回后要重新建单吗？ 修复后再次提测即可，旧单保留。
  • 缺陷看板是空的？ 产品可能尚未同步缺陷，或「禅道同步」开关已关闭；先执行同步并确认产品配置。
  • 为什么列表没有变更范围？ 它与测试反馈是长文本，放在详情抽屉，避免撑高行高。
  • 已归档项目能提测吗？ 不能，归档后写操作被拒绝。
