巡检管理

内容状态：基于代码与页面整理，待产品负责人复核。

巡检管理对 Linux 服务器做自动化健康检查，流程为：配置模板 → 创建任务 → 执行 → 查看结果与报告。

用途

  • 用模板选择检查项并设置阈值，对多台服务器并发巡检。
  • 查看节点 HTML 报告、历史记录与任务汇总报告。
  • 用 Cron 配置周期巡检。

入口与前置

菜单「资源 → 巡检管理」，下含「巡检任务」与「巡检配置」。需 test-platform 授权。目标服务器须在 CMDB 登记且 SSH 可达；引擎可选 Go 原生或 SSH 推脚本。系统模板只读，自定义模板可编辑。

界面区域

📷 截图位：待补充（203 测试数据待脱敏）

巡检配置：表列模板名称、描述、类型、创建时间与操作。抽屉含名称、描述、检查项树（基本信息、CPU、内存、磁盘、网络、进程、服务、Docker、安全、SSL、日志等）与四个阈值。

巡检任务：表列任务名称、模式、状态（含进度）、目标服务器数、定时配置、上次/下次执行与操作。操作含执行、停止、编辑、详情、删除。创建抽屉含名称、引擎、模板、服务器穿梭框、是否定时与 Cron。

任务详情：四个 Tab。「执行进度」含任务信息、节点进度与结果表（IP、状态、耗时、错误）；「节点报告」渲染节点 HTML，可切换历史；「汇总报告」渲染任务级 HTML；「趋势分析」当前开发中。

巡检计划：独立页面维护 Cron 任务，字段含名称、Cron、引擎、模式、服务器 ID 与启停。该页当前不在常规菜单中，入口以实际配置为准。

操作步骤

  1. 在「巡检配置」确认或新建模板，勾选检查项并设置阈值。
  2. 在「巡检任务」点「创建任务」，填写名称，选择引擎、模板与目标服务器。
  3. 需要周期执行时打开「定时执行」并填写 Cron。
  4. 点「执行」启动，运行中可「停止」。
  5. 进入「详情」查看进度、节点报告与汇总报告；需要独立计划时在巡检计划页创建 Cron 任务。

字段与状态

对象取值说明
任务状态pending / running / success / partial / failed待执行、执行中、成功、部分失败、失败
结果状态pending / running / success / failed单节点结果
执行引擎go / script原生或推脚本
巡检模式quick / full / template快速、完整、模板
计划模式basic / full / custom基础、完整、自定义
默认阈值CPU 80%、内存 85%、磁盘 90%、SSL 30 天可在模板调整

注意事项与常见问题

  • 任务一直是待执行？ 确认任务已触发、服务正常；调度未启动时不会自动执行。
  • 全部节点失败？ 多为网络不通或 SSH 配置问题，先查连通性与端口。
  • 部分节点失败？ 看结果表错误信息，常见为凭据错误或禁止密码登录。
  • 报告有「待实现」章节？ 部分检查项尚未生成内容，以实际报告为准。
  • 失败节点会自动重试，次数与间隔以服务端配置为准。
