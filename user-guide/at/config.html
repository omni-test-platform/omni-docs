环境与配置

内容状态：基于代码与页面整理，待产品负责人复核。

用途

「环境与配置」集中管理 AT 运行所需的辅助能力：Mock 服务、全局变量、定时任务、数据工厂、执行引擎、模块分组与 Swagger 导入。它们不直接产生用例，但决定用例能否复用数据、能否定时执行、以及在哪个引擎上运行。

入口与前置

  • 入口：自动化测试 → 环境与配置（/at/settings/*）。
  • 前置：具备相应管理权限；执行引擎与 Jenkins 配置通常由管理员维护。
  • 相关：执行环境本身在环境管理中维护，不在本页重复。

界面区域与配置项

页面主要配置
Mock 服务查看运行状态，填写项目 ID 与端口（1024–65535）后启动/停止；服务按项目接口定义生成响应
全局变量左侧执行分组树、变量列表与编辑抽屉；变量含名称、类型（字符串/数字/布尔/JSON）、作用域（全局/项目）、加密开关、排序、分组、值与描述
定时任务任务名称、类型（AT 测试计划/测试任务、系统清理、禅道同步）、任务配置、Cron、描述、启用状态、执行次数、上次结果与日志
数据工厂按工具分类浏览；填写参数后执行或批量生成，查看历史记录
执行引擎本地执行（名称、引擎目录、Python 解释器、超时）、SSH 节点（主机、端口、用户、状态、负载/并发、能力、心跳）、Jenkins
模块分组功能模块与分组管理，层级为 L1 子系统、L2 功能域、L3 特性、L4 页面、L5 接口
Swagger 导入文件/URL/定时导入；格式含 Swagger、Postman、Har、Jmeter（选择仅切换界面）
配置管理AT 执行容量、Git 仓库、AI 生成模型三个 Tab

配置管理

  • AT 执行容量：本地/SSH 并发上限、Jenkins 在途上限、单用户/单项目同时在跑上限，以及执行记录与报告产物保留天数、清理任务间隔。保存后立即生效，无需重启。
  • Git 仓库：仓库名称、Git URL、分支、认证方式（SSH / HTTP Token / 无）、凭证、定时同步与 Cron、克隆路径、测试根目录、测试框架，并提供「立即同步」。
  • AI 生成模型：用于 AI 生成用例的模型配置，具体字段以实际页面为准。

Jenkins 配置不在「配置管理」页，而在「执行引擎 → Jenkins」Tab，可维护名称、URL、用户名、密码、超时、启用与默认配置，并支持测试连接。

📷 截图位：at/config-settings

操作步骤

  1. 在「全局变量」新建分组与变量，选择作用域和类型后保存；接口与场景可通过变量名引用。
  2. 需要模拟接口时，在「Mock 服务」填写项目 ID 与端口，启动后使用页面提示的地址访问。
  3. 需要周期执行时，在「定时任务」新增任务，选择 AT 计划/任务并填写 Cron。
  4. 需要批量造数时，在「数据工厂」选择工具、填写参数并执行，结果可复制或查看历史。
  5. 在「执行引擎」维护本地引擎、SSH 节点与 Jenkins；节点需保持心跳正常。
  6. 在「Swagger 导入」选择文件或 URL，指定模块与覆盖策略后导入。
  7. 需要调整并发或保留期时，在「配置管理 → AT 执行容量」修改并保存。

注意事项与 FAQ

  • 定时任务与任务/计划表单中的定时开关联动；删除任务或计划前，请先到定时任务页处理对应记录。
  • 执行容量修改立即影响新提交的执行，已在跑的执行不受影响。
  • 生成数据可能含随机值，重要用例应固定关键字段。
  • Swagger 导入的「覆盖」只更新请求参数不一致的同一接口，「不覆盖」则跳过已存在接口；导入格式选择当前只切换界面，实际解析以导入内容为准。
  • Mock 端口需未被占用；启动失败先检查端口与接口定义。
  • 字段以实际页面为准。
