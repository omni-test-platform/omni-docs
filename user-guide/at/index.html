自动化测试 AT

内容状态：基于代码与页面整理，待产品负责人复核。

用途

自动化测试（AT）覆盖从用例设计、任务/计划执行到结果聚合与报告的闭环。接口、Web、性能、混沌与渗透测试共用同一套用例、环境与执行模型，由 Jenkins 或本地/SSH 节点调度 omni-engine 运行。

入口与前置

  • 入口：顶部「测试」进入 /at/workspace 工作台，左侧菜单进入各子域。
  • 前置：当前产品/项目已创建；至少有一个测试环境；Jenkins 通道需管理员完成配置与 agent 准备。
  • 权限：菜单与按钮受角色权限与 License 控制，不可见表示无权限或未授权。

界面区域

工作台顶部为时间范围与刷新，主体是可配置卡片区：

卡片内容
基础统计用例、计划、任务、环境总数、活跃计划、待审核用例
质量统计接口定义与覆盖率、近 7 天通过率、今日执行、失败用例
最近执行近期执行记录及状态
我的待办我的创建、待我处理与执行概况
快捷入口新建用例、计划、发起执行、报告、环境、仪表盘

性能、混沌另有卡片。

执行链路

omni-web 页面
  → omni-server（任务/计划 API、worker 队列、环境租约）
  → 调度通道：Jenkins / 本地 / SSH
  → omni-engine（pytest 批处理或 suite 套件）
  → 统一回调 /at/executions/callback（CASE 实时进度 + DONE 完成汇总）
  → omni-server 聚合
  → 报告 / Allure / 禅道回填

Jenkins 通道下，server 把引擎任务文件与回调地址下发给参数化 job，agent 执行引擎并逐用例回调；本地与 SSH 通道由 server 直接拉起引擎进程，回调协议一致。平台只负责触发、聚合与展示。

与执行引擎 Skills 的关系

平台 AT 负责用例管理、任务/计划调度与报告；用例的生产与追溯可以在仓库中由执行引擎的 Skills 体系完成：从需求/页面生成测试方案、禅道用例与自动化脚本，再通过 omni-platform-case-push 推送到平台。详见 Skills 全流程自动化。

操作步骤

  1. 在「环境管理」准备测试环境与执行节点。
  2. 在「接口管理」「页面管理」或「用例列表」准备用例。
  3. 在「测试任务」选择用例并配置环境、分支、通道与参数。
  4. 多任务编排时创建「测试计划」，在流水线配置阶段、任务与依赖。
  5. 手动执行或等待 Cron，在「执行详情」查看进度、日志与报告。
  6. 在「测试报告」查看历史、对比或批量重跑。

状态说明

状态含义
待执行 / 排队中已受理，尚未开始；独占环境被占用时排队
执行中已分配执行器，正在执行
成功 / 部分失败全部通过，或存在失败、跳过用例
失败 / 异常用例失败或执行链路异常
已取消用户取消或执行被中止
跳过 / 未执行用例未运行或按规则跳过

注意事项与 FAQ

  • 任务是执行单元；计划按阶段编排多个任务并可定时执行。
  • 计划执行参数留空沿用任务配置，填写则覆盖全部任务；分支与关联版本必填。
  • 独占环境同一时间只允许一个执行，其余排队；共享环境不建立独占租约。
  • 报告中的环境、分支与版本取执行时快照，临时覆盖不写回配置。
  • 未上线能力会在对应页面标注「建设中」；具体字段以实际页面为准。
