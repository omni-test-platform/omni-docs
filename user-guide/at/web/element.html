元素管理

内容状态：基于代码与页面整理，待产品负责人复核。

用途

元素管理维护浏览器页面上的可操作对象及其定位方式。一个元素由类型、主定位、若干备用定位与等待参数组成，供功能库和 Web 用例引用。定位器越稳定，UI 变更造成的用例失败越少。

入口与前置

  • 入口：自动化测试 → Web 测试 → 元素管理（/at/web/element）。
  • 前置：已创建页面；元素需归属页面才能被用例按页面筛选。
  • 权限：新建、编辑、验证、复制、删除受角色权限控制。

界面区域

页面左侧为页面树，可选择页面过滤元素；右侧上方为搜索区（元素名称、定位方式、元素类型），下方为元素表格。表格列包含 ID、元素名称、类型、定位方式、定位值、所属页面、验证状态与描述。

📷 截图位：待补充（203 测试数据待脱敏）

新建/编辑使用右侧抽屉，包含元素名称、元素类型、所属页面、组件名称、定位策略、等待超时、是否唯一、强制操作、定位表达式、备用定位与描述。

操作步骤

  1. 在左侧页面树选择目标页面。
  2. 点击新增，填写元素名称并选择元素类型。
  3. 选择定位策略，按提示填写定位表达式。
  4. 按需开启「是否唯一」；对 visibility:hidden 的元素可开启「强制操作」。
  5. 添加备用定位：每条由策略与表达式组成，主定位失败时按顺序尝试。
  6. 设置等待超时（0–120 秒）与描述后保存。
  7. 在列表点击「验证」，查看验证状态与日志。
  8. 需要复用定位时点击「复制」，再修改名称与表达式。
  9. 勾选多个元素可批量迁移到目标页面或批量删除；导入/导出入口在列表右上角。

元素类型与定位策略

元素类型包括输入框、按钮、链接、下拉框、复选框、单选框、文本、图片、容器、表格、表单与弹窗。

验证状态

状态含义
有效定位器在当前页面可命中元素
无效定位失败或命中多个元素（开启唯一校验时）
待验证尚未执行验证
未知无验证结果或无法判断

注意事项与 FAQ

  • 建议优先使用 Test ID、ID、CSS 等稳定属性，避免依赖易变的文本或层级 XPath。
  • 「是否唯一」会校验定位器是否只命中一个元素，关键元素建议开启。
  • 备用定位按主定位、备 1、备 2 的顺序尝试；过多备用定位会拖慢失败场景。
  • 支持从 JSON 或 YAML 导入元素，并可导出 JSON；页面没有独立的 AI 探查按钮，探查需使用引擎 CLI 的 probe 命令，再把 YAML 粘贴导入。
  • 导入后仍建议逐条「验证」；YAML 导入要求包含 product_id 或 page_id，否则会被拒绝。
  • 删除元素前确认功能库与用例是否引用；删除后相关步骤会失去目标。
  • 验证时若元素所属页面配置了基础 URL，会启动真实浏览器校验；否则退化为语法与库内唯一性检查。
  • 备用定位、是否唯一、强制操作与等待超时目前只在元素验证时生效，不会随用例执行下发给引擎，执行仍只使用主定位。
  • 具体字段与验证行为以实际页面为准。
