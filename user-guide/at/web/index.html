Web 测试

内容状态：基于代码与页面整理，待产品负责人复核。

用途

Web 测试子域用于维护浏览器自动化的页面对象与用例。它把「页面 → 元素 → 功能组件 → 用例步骤」分层组织：元素保存定位器，页面承载元素，功能库把常用元素操作封装成可复用步骤，Web 用例再把元素与功能组件编排为完整流程。

入口与前置

  • 入口：自动化测试 → Web 测试（/at/web 为菜单分组，没有独立概览页），下含元素管理、页面管理、功能库、用例管理。
  • 前置：已选择产品/项目；执行时需要可用的测试环境与浏览器执行器（Playwright 或 Selenium）。
  • 权限：新建、编辑、删除、执行受角色权限控制。

界面区域

菜单路由用途
元素管理/at/web/element维护页面元素与多候选定位
页面管理/at/web/page维护页面层级与基础 URL
功能库/at/web/library把元素操作封装为可复用功能组件
用例管理/at/web/case编排并运行 Web 用例

📷 截图位：待补充（203 测试数据待脱敏）

元素管理左侧为页面树，右侧为元素列表；页面管理左侧为功能模块树，右侧为页面表格；功能库以列表加步骤编辑抽屉呈现；用例管理左侧为模块树，右侧为用例表格与步骤编辑区。

操作步骤

  1. 在「页面管理」新建页面，填写名称、父页面、基础 URL 与描述。
  2. 在「元素管理」选择页面，新建元素，填写类型、定位策略、定位表达式与备用定位。
  3. 点击「验证」确认定位器在当前页面可用；必要时调整。
  4. 在「功能库」新建组件，引用元素编排常用步骤（打开、点击、输入、等待、断言等）。
  5. 在「用例管理」新建用例并保存，再点「编辑」进入步骤编排区。
  6. 拖拽调整步骤顺序，为每步选择动作类型、目标元素或功能组件，填写输入值、等待时间与断言。
  7. 保存后选择目标环境、执行引擎、浏览器与有头/无头模式，点击「运行」查看结果。
  8. 评审通过后，用例可被任务/计划引用执行。

分层关系

页面（Page）
  └─ 元素（Element，定位器 + 备用定位）
       └─ 功能组件（Library，可复用步骤序列）
            └─ Web 用例（Case，步骤编排）

功能组件与用例都按步骤执行；用例可直接引用元素，也可引用功能组件。执行时组件步骤会展开为对应步骤序列。

注意事项与 FAQ

  • 元素定位策略与引擎统一：ID、CSS、XPath、Name、Class、Tag、Text、Placeholder、Role、Label、Title、Test ID。
  • 建议为关键元素开启「是否唯一」校验，并配置 1–2 个备用定位，降低 UI 变更导致的失败。
  • 页面层级用于组织元素，不改变执行顺序；用例步骤顺序由编排决定。
  • 执行引擎支持 Playwright 与 Selenium，浏览器支持 Chrome、Firefox、Edge；无头模式适合 CI。
  • 元素支持从 JSON 或 YAML 探查结果导入，导入后仍需人工核对定位器；页面没有 AI 探查按钮，探查使用引擎 CLI。
  • 功能库新建抽屉当前没有「所属页面」字段，新建组件会显示为未关联，页面树筛选可能看不到；需要归属时以实际页面能力为准。
  • 具体字段以实际页面为准。
