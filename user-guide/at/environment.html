环境管理

内容状态：基于代码与页面整理，待产品负责人复核。

用途

环境管理维护被测系统的地址、凭证、节点与测试床参数。一次执行使用的环境、分支与版本共同决定引擎拿到的上下文；环境还决定独占/共享的使用方式与执行排队行为。

入口与前置

  • 入口：自动化测试 → 环境与配置 → 环境管理（/at/settings/environment）。
  • 前置：具备环境管理权限；删除环境前需确认没有计划或任务仍引用它。
  • 相关配置：执行器节点、执行容量与租约参数由管理员在管理员指南中维护。

界面区域

列表区支持按名称、状态、责任人与使用策略筛选。表格列有 ID、环境名称、描述、责任人、使用策略、运行中（计划/任务数）、排队中（计划/任务数）、状态、启用开关与操作；使用数量可点击下钻到「环境使用概况」列表。

📷 截图位：at/environment-list

新增/编辑使用右侧抽屉，顶部为名称、描述、责任人、状态与使用策略，主体按场景分为「基础配置」「接口测试」「可靠性测试」三个分组；场景只作归类，切换不会限制编辑其他参数。

配置分组

分组内容
基础配置端点：API 入口、API 用户/密码、Web 访问地址、Web 用户/密码、超时、文件共享 VIP；三员：角色、登录名、密码、说明；租户：标识名、显示名、用户（用户名、密码、用途）；子系统：名称、端点地址、附加参数
接口测试环境变量、请求头、参数、HTTP 配置、数据库配置、HOST 配置、前置操作、后置操作、断言配置
可靠性测试服务端节点与客户端节点：IP、端口、用户、密码、密钥文件

三员的登录名为纯用户名，按角色寻址；租户用户登录名为「用户名@租户」，用途需跨租户唯一。端点密码不回显明文，留空表示沿用已存值；三员与租户密码保存后加密存储，回显用于确认账号配置。

操作步骤

  1. 点击「新增环境」，填写名称、描述，选择责任人、状态与使用策略。
  2. 在「基础配置」填写 API 入口、Web 地址与凭证，按需配置三员、租户与子系统。
  3. 在「接口测试」配置环境变量、请求头、数据库、HOST、前后置与断言。
  4. 在「可靠性测试」添加服务端/客户端节点。
  5. 点击保存。列表右上角的「全局请求头」入口当前仅提供界面与批量粘贴交互，保存尚未接入持久化接口，以实际页面提示为准。
  6. 在列表中启用环境，执行任务或计划时即可选择。
  7. 删除环境前查看影响面确认，确认后平台清除计划/任务上的环境配置。

使用策略与状态

项说明
独占（exclusive）默认。执行时建立独占租约，同一时间只允许一个执行，其他执行排队
共享（shared）不建立独占租约，允许多个执行并发使用
在线 / 离线 / 维护中 / 空闲环境状态；停用或维护中的环境不能启动执行
运行中 / 排队中使用概况中的计划与任务计数，子任务归计划维度统计

注意事项与 FAQ

  • 执行前会校验环境：未配置、已删除、停用或维护中都会被拒绝。
  • 临时改环境只对本次执行生效，不写回配置。
  • 删除环境会软删除并把计划/任务的环境置空，历史执行保留快照。
  • 全局请求头入口支持批量粘贴，每行「Header 名:Header 值」或「Header 名:Header 值#描述」；保存当前为模拟，不会真正持久化。
  • 端点密码不回显；留空表示沿用已存值，避免误改。
  • 字段以实际页面为准。
