测试计划

内容状态：基于代码与页面整理，待产品负责人复核。

用途

测试计划把多个测试任务按阶段组织成一条可重复执行的流水线：阶段按顺序推进，阶段内任务可并行，也可通过依赖关系串行。计划支持手动、定时与接口触发，适合回归、版本验证和发布前检查。

入口与前置

  • 入口：自动化测试 → 测试执行 → 测试计划（/at/execution/plan）；流水线编排页为 /at/execution/plan/pipeline。
  • 前置：已有测试任务；计划中引用的任务应配置好环境与用例。
  • 权限：新增、编辑、执行、删除与流水线编排按钮受角色权限控制。

界面区域

计划列表包含搜索区、操作按钮与表格。表格列有计划名称、状态、分支、版本、执行环境、分组、耗时、阶段数、任务数、用例数、通过率、上次/下次执行时间与操作；行内可查看详情、执行与查看历史。列表顶部提供「新增计划」。

📷 截图位：待补充（203 测试数据待脱敏）

计划详情由执行记录选择器与六个 Tab 组成：基本信息、执行进度、报告汇总、重跑分析、历史记录、趋势分析。基本信息含计划配置卡、最新执行信息卡与流水线卡；执行进度按「阶段 → 任务 → 用例」层级展示。

流水线编排页由顶部阶段概览、左侧阶段列表与右侧阶段内任务组成，并提供「阶段配置」抽屉。

操作步骤

  1. 点击「新增计划」，填写计划名称、描述与分组。
  2. 在执行参数区选择执行环境、分支、调度通道、Jenkins Job，并按需填写重试、超时、并行数、关联版本与自定义参数。
  3. 需要定时执行时打开定时开关并填写 Cron 表达式。
  4. 保存后进入「流水线」编排页，添加阶段并命名；阶段按 Order 依次执行。
  5. 打开「阶段配置」，勾选该阶段包含的任务；无依赖的任务并行执行，设置依赖后按依赖关系串行。
  6. 保存流水线后回到列表点击「执行」，在确认弹窗中确认环境、版本、测试单与临时参数。
  7. 在计划详情查看本次执行的阶段进度、报告汇总与历史记录。

字段与规则

项说明
执行参数与任务表单同形；除分支与关联版本外，留空表示沿用各任务自己的配置，填写则覆盖计划下全部任务
分支 / 关联版本必填，不适用留空继承；执行时覆盖全部任务
自定义参数与任务参数按层合并，同名键以计划侧为准
触发类型手动、定时；接口触发有文案但当前无配置入口
阶段按 Order 顺序推进；阶段内任务默认并行
任务依赖为任务指定前置任务后，该任务等待依赖完成再执行
环境覆盖执行确认弹窗中临时改环境会对该计划下全部任务生效，不修改配置

注意事项与 FAQ

  • 计划执行参数是执行时的整体覆盖，不会写回任何测试任务。
  • 独占环境被占用时，计划执行进入「排队中」；平台按提交时间对计划与任务统一 FIFO 仲裁。共享环境不排队。
  • 阶段配置抽屉中的执行策略与依赖关系决定任务顺序；禁用任务不会参与本次执行。
  • 执行记录选择器默认选中运行中/待执行的记录，其次选最新一条；选择会写入 URL 的 exec 参数，刷新后保持。
  • 趋势分析支持按天与按版本两种视图，版本取执行记录快照，临时覆盖按实际使用值归组。
