测试执行

内容状态：基于代码与页面整理，待产品负责人复核。

用途

测试执行子域负责把用例真正跑起来，并把结果沉淀为执行记录与报告。它由执行仪表盘、测试任务、测试计划和流水线编排组成：任务是执行单元，计划负责多任务编排，仪表盘汇总执行态势。

入口与前置

  • 入口：自动化测试 → 测试执行 → 仪表盘 / 测试任务 / 测试计划（/at/execution/*）。
  • 前置：已有可执行用例与测试环境；使用 Jenkins 通道时需管理员完成 Jenkins 配置，并保证 agent 能回调平台。
  • 权限：执行、取消、重跑等操作受角色权限控制。

界面区域

执行仪表盘提供「概览」与「趋势与分布」两个 Tab。概览含执行成功率、用例通过率、用例总数、进行中、失败、平均耗时等 KPI，以及近期执行、按项目/环境的维度统计和失败 TOP 10；趋势与分布含通过率趋势（执行与用例双口径）、每日执行结果构成和状态分布。

任务与计划列表遵循同一套交互：搜索区、操作按钮、表格与行操作。执行详情统一由执行记录选择器与 Tab 页承载。

执行方式

调度通道执行位置适用场景
本地omni-server 所在主机直接拉起 omni-engine单机部署、调试或轻量任务
SSH 执行器通过 SSH 在指定执行节点运行引擎引擎与平台分离、指定测试机
Jenkinsserver 触发参数化 job，agent 执行 omni-engine生产回归、需要构建环境与 Allure 托管

三个通道使用同一套引擎任务与回调协议；差别只在进程由谁拉起、代码由谁检出。Jenkins 通道支持分支检出与 Jenkins 构建外链。

执行链路

页面发起执行
  → omni-server 校验环境并创建执行记录（独占环境先取租约）
  → worker/队列异步调度
  → Jenkins / 本地 / SSH 拉起 omni-engine
  → 引擎逐用例回调 + WebSocket 进度上报
  → server 聚合状态、写报告、可选回填禅道

执行中的状态由用例回调实时聚合；Jenkins 构建结束只是触发终态复核，最终结果仍以用例记录为准。

操作步骤

  1. 在仪表盘确认整体通过率与失败集中区域。
  2. 在「测试任务」创建执行单元并编排用例，或在「测试计划」编排阶段与任务。
  3. 点击「执行」，在确认弹窗中确认执行环境、关联版本、回填测试单与临时参数。
  4. 在任务/计划详情查看进度；运行中的记录自动轮询。
  5. 执行结束后查看报告汇总、用例日志与 Allure。
  6. 在报告中心对比历史、批量重跑或导出报告。

状态与口径

项说明
执行成功率成功执行数 / 已得出结论的执行数，排除取消、跳过与未终结
用例通过率通过用例数 / 已结束用例数，失败含异常、错误与阻塞
排队中独占环境被占用或并发槽已满，平台已受理但尚未开跑
部分失败执行完成但存在失败或跳过用例

注意事项与 FAQ

  • 任务与计划是不同维度：任务状态只反映手动/调试执行，计划内执行结果请查看计划报告。
  • 独占环境同一时间只允许一个执行；共享环境不建立独占租约，可并发使用。
  • 环境缺失、已删除、停用或维护中时，执行会在创建记录前被拒绝并提示原因。
  • 所有执行入口（详情、列表、单条重跑、批量重跑）都使用同一确认弹窗，临时覆盖不写回配置。
  • 快速调试产生的执行记录来源为「快速调试」，与任务、计划记录分开编号。
