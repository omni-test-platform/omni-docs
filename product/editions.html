版本与授权

内容状态：基于代码与配置整理，待产品负责人复核。

授权模型

平台使用离线 License 文件授权：签发方用 RSA 2048 私钥对 License 全部业务字段做 SHA-256 签名，平台内置公钥负责验签。License 管控始终启用，不提供配置文件开关；本地开发可用 -tags licensefree 编译跳过校验。

License 导入时校验签名、有效期与机器码；服务启动及每 24 小时复核签名与有效期；功能是否可用最终看 feature 是否命中模块树。

模块树与继承

授权父模块会自动获得其全部后代模块的权限：

root
├─ basic-modules
│  ├─ system        系统管理
│  ├─ home          首页工作台
│  ├─ example       示例模块
│  └─ crontab       定时任务
├─ test-platform   测试平台
│  ├─ test          自动化测试
│  ├─ perf          性能测试
│  ├─ infra         基础设施管理（CMDB）
│  └─ inspect       巡检管理
├─ chaos-engine    混沌工程
├─ qa-analysis     质量分析
│  ├─ quality       质量评估
│  └─ project       项目管理
├─ toolkit         工具集
│  ├─ tools-dev     开发工具
│  └─ tools-test    测试工具
├─ ai-assistant    AI 助手
│  ├─ ai-requirement     需求分析
│  ├─ ai-assistant-chat  智能对话
│  ├─ ai-skills          技能管理
│  └─ ai-apps            AI 应用
└─ advanced        高级功能

例如授权 test-platform 即自动获得 test、perf、infra、inspect；授权 qa-analysis 即自动获得 quality 与 project。菜单和路由中间件按这些 feature key 做可见性与访问控制。

用户数、机器码与有效期

项规则
用户数上限License 的 maxUsers 字段，0 表示不限制；当前代码提供 CheckUserLimit 校验能力，但未在创建用户路径强制调用，超限是否阻断以实际版本为准。不按 edition 固定档位
机器码License 的 hardware.machineCode，形如 MACH-...，由主机 UUID 与 CPU 指纹生成；导入时与当前实例不匹配则拒绝
有效期License 的 expiresAt，由签发时指定；过期后功能不可用，续期需重新签发并导入
Editionbasic、standard、enterprise、ultimate、custom 五值；custom 不套用预设集合
校验周期导入时校验签名/有效期/机器码；启动与每 24 小时复核签名/有效期；API/菜单按内存缓存判断

注意事项

  • 更换服务器、主板或导致机器码变化的硬件后，原 License 会失效，需要重新签发。
  • Basic 只能使用系统管理、首页、示例与定时任务；项目、测试、QA、资源、AI 等业务域需要更高 edition 或 custom features。
  • 授权导入、机器码获取、续期与排障见授权管理；产品与组件版本对应关系见兼容矩阵。
  • 部署与首次登录分别见快速部署和首次登录。
