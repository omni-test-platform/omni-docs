License 授权

内容状态：基于代码与配置整理，待产品负责人复核。

用途

License 决定平台可用的功能模块、用户数上限与有效期。平台只负责展示机器码、导入并校验 License；签发由厂商侧的 omni-license 工具完成，客户环境不持有私钥。

入口与前置

  • 入口：系统 → 授权管理，对应 /system/license。
  • 默认由系统管理员（角色 3）导入；管理员（2）和普通用户（6）可只读查看，安全管理员（4）与审计员（5）默认无授权读权限。
  • 导入前需取得与本机机器码绑定、由厂商签发的 JSON 文件。

界面区域

页面展示授权版本、状态、客户名称、授权用户数（当前/上限）、授权期限、剩余天数与功能模块；下方单独展示本机机器码。右上角“导入 License”打开文件选择弹窗。

📷 截图位：admin/license-overview

操作步骤

  1. 在“本机机器码”区域复制 MACH-... 机器码，提供给厂商。
  2. 厂商使用 omni-license 生成 RSA 2048 密钥对并签发 License，私钥由厂商保管。
  3. 管理员点击“导入 License”，选择 .json 文件并确认。
  4. 服务端依次验签、检查有效期、比对机器码；通过后写入数据库并刷新缓存。
  5. 页面刷新后核对版本、模块、用户数与到期日；到期前 30 天和 3 天页面会给出提醒。

字段与状态

字段说明
editionbasic、standard、enterprise、ultimate、custom
features授权的顶层模块，父模块自动继承全部子模块
maxUsers用户数上限；0 表示不限制
expiresAt到期时间，过期后功能不可用
machineCode与部署实例绑定，硬件或虚拟化标识变化后需重新签发
status1 有效、2 已过期、3 已吊销
edition顶层模块
basicbasic-modules
standardbasic + test-platform、qa-analysis、chaos-engine、toolkit
enterprisestandard + ai-assistant
ultimateenterprise + advanced
custom签发者自由指定 features

注意事项与 FAQ

  • 模块树继承：授权 test-platform 即自动获得其下 test、perf、infra、inspect 等子模块，无需逐项授权。
  • 过期与续期：过期后 License 状态变为“已过期”，功能校验返回不可用，菜单隐藏、相关接口被拦截，已有业务数据保留；导入新 License 即可续期，同 licenseId 会更新原记录，旧 License 自动标记过期。
  • 24 小时重检与状态自愈：服务启动时完整验签，之后每 24 小时重新从数据库加载；系统不信任数据库中的 status 字段，篡改状态会在下次加载时被纠正。
  • 用户数：页面显示当前用户数与上限；当前代码中 CheckUserLimit 未在创建用户路径调用，超限是否阻断需产品复核，不能仅依赖页面提示。
  • licensefree 仅限开发：-tags licensefree 会跳过全部校验并放开所有功能，禁止用于生产或对外交付。
  • 导入失败常见原因：签名不匹配、机器码不一致、文件已过期、JSON 格式错误。界面版本标签目前覆盖 basic/standard/enterprise/custom，ultimate 可能显示原值，属展示缺口。
