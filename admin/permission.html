权限与角色

内容状态：基于代码与配置整理，待产品负责人复核。

用途

平台以角色为核心：用户关联角色，角色关联菜单、接口、产品与数据范围。内置角色按三权分立设计，确保管配置、管权限、看日志互不重叠。

入口与前置

  • 入口：系统 → 权限管理 → 角色管理 / 用户管理 / 菜单管理 / 接口管理 / API 令牌，对应 /system/permission/*。
  • 权限治理增删改仅安全管理员（角色 4）可执行，管理员（2）与系统管理员（3）可读；安全配置归系统管理员（3）。
  • 修改角色权限前，先确认该角色的默认菜单范围与业务边界，避免误删必选权限。

界面区域

角色列表展示名称、描述、状态与操作；点击“权限”打开抽屉，含菜单、API、产品、数据四个页签。菜单树按大模块分组，API 树按大模块与 api_group 分组，均支持级联勾选。

内置角色

ID角色定位关键边界
1超级管理员应急与初始化，全量放行无逐条策略，依靠 matcher 旁路
2管理员业务全权，系统只读不能改权限、不能改配置
3系统管理员配置、日志删除、授权、发版不碰业务与权限治理
4安全管理员用户、角色、菜单、接口、策略、令牌能改权限，删不掉日志
5安全审计员只读审计，不能修改被审计对象只有审计日志入口
6普通用户业务执行，不碰系统管理业务可读写
7只读用户业务只读，零写权限仅业务读与自助接口
200用例管理员/at/* 读写，供流水线同步用例仅测试用例域

策略由接口清单自动生成，数量随版本和新增接口变化，不在文档中固化；以 go test ./internal/source/system/ 的权限守卫测试为准。

权限类型

类型作用要点
菜单权限控制路由与侧边栏按大模块 → 一级 → 子菜单勾选；首页必选、锁定
API 权限控制接口调用按大模块 → api_group → 接口勾选；自助接口必选，通配策略展开回显
产品权限控制可访问产品仅列出已开启平台监管的产品
数据权限控制数据可见范围五档：全部、本部门及以下、本部门、仅本人、自定义；当前主要用于用户列表
按钮权限控制页面内按钮菜单按钮 + 角色按钮关联；前端用 hasAuth 判断

新增接口如何授权

  1. 业务接口路径落在 /at/*、/qa/*、/project/*、/ai/*、/resource/* 等 bizPrefixes 下时，策略按前缀自动覆盖，无需逐条添加。
  2. /system/** 接口需在 casbin.go 的 permRead/permWrite、configRead/configWrite、logRead/logDelete、licenseRead/licenseWrite、aboutRead/aboutWrite、securityConfig 等集合中显式登记。
  3. 新增业务模块前缀时，同步加入 bizPrefixes。
  4. 运行 go test ./internal/source/system/，通过“每个接口至少有一个角色可调用”“只读用户无写权限”等守卫。

注意事项与 FAQ

  • 超级管理员没有逐条策略：其放行来自 Casbin matcher 的 checkSuperadmin 旁路，收紧超管权限不能靠改策略，必须改 matcher。
  • 管理员（2）默认不含组织管理、权限管理与系统设置；安全管理员（4）可改权限但删不掉日志；审计员（5）能看日志但改不了任何对象。
  • 保存角色权限时，服务端会补齐必选菜单与必选接口；取消父节点不会导致必选权限丢失。
  • 当前菜单编辑页未提供按钮维护入口，按钮 code 随种子或后端配置维护；新增按钮时需同步前端 hasAuth 判断。
  • 200 仅测试用例域，不涉及系统管理。
