第三方集成

内容状态：基于代码与配置整理，待产品负责人复核。

用途

把外部研发工具接入平台：禅道提供项目、用例与缺陷数据，GitLab 提供测试代码仓库，Jenkins 提供远端执行通道，LDAP 提供域账号登录。集成不改变平台权限模型。

入口与前置

集成入口前置
禅道系统 → 第三方集成 → 禅道集成，/system/integrations/zentao可访问的禅道地址、账号与密码
代码仓库测试 → 环境与配置 → 配置管理 → Git仓库，/at/settings/config仓库地址、分支与凭据
Jenkins测试 → 环境与配置 → 执行引擎 → Jenkins，/at/settings/engineJenkins 地址、账号与可用 agent
LDAP系统 → 第三方集成 → LDAP集成（当前为占位页）服务端 ldap 配置段，修改后重启生效

说明：系统的 GitLab 集成页目前是占位页；实际可用的 Git 仓库配置在 AT 配置管理的“Git仓库”页签。LDAP 页面同样未提供表单，需在 production.yaml 中配置。

界面区域

禅道页包含数据同步、用例列表、缺陷列表、禅道配置四个页签；Git 仓库页展示名称、地址、分支、认证方式、同步状态与最近同步时间；Jenkins 页展示配置列表、默认标记、启用状态与连接测试。

📷 截图位：admin/integration-zentao-config

配置与同步范围

集成关键配置同步/作用范围
禅道名称、访问地址、用户名、密码、版本、启用、Cron产品、项目、构建版本、模块、测试用例、缺陷列表及每日统计；支持多实例，默认实例不可删除，可验证连通性
Git 仓库名称、仓库地址、分支、认证方式（SSH/HTTP Token/无）、凭据、本地克隆路径、测试根目录、框架、定时同步拉取测试代码并同步用例；可手动“同步”，也可按 Cron 定时
Jenkins名称、地址、用户名、密码、超时、描述、启用、默认平台触发 Jenkins job 执行 AT 任务/计划；参数、共享存储与回调见部署运维 · Jenkins 通道
LDAPenable、address、bind-dn、filter、user-attr、nickname-attr、email-attr、phone-attr、default-authority-id登录时校验域账号；本地用户不存在则自动创建，默认角色 6；不同步部门与岗位

操作步骤

  1. 禅道：新增实例，填写地址与账号，先“验证”连通性，再设置启用与同步 Cron；在“数据同步”选择产品、项目、构建、模块、用例、缺陷后立即同步。
  2. Git 仓库：新增配置，选择认证方式并填写凭据，设置分支与测试根目录；保存后点击“同步”验证。
  3. Jenkins：新增配置并设为默认，点击“测试连接”确认版本；执行通道联调按部署文档完成。
  4. LDAP：在服务端配置文件中填写 ldap 段，启用后重启服务；首次登录自动建号，再在组织管理中补充部门、岗位与角色。

注意事项与 FAQ

  • 凭据以加密形式落库，编辑时留空表示保留原值；不要在文档、截图或工单中粘贴明文密码。
  • 禅道多实例按产品与实例隔离；默认实例不可删除，删除其他实例前确认无同步任务引用。
  • Git 仓库同步依赖网络与凭据，失败时先看同步状态与最近同步时间，再检查分支与测试根目录。
  • LDAP 只负责认证与建号，不覆盖本地角色调整；域账号删除后本地用户不会自动删除，需手工冻结。
  • 集成地址使用 <禅道地址>、<GitLab 地址>、<Jenkins 地址> 等占位，不在此写入真实环境信息。
