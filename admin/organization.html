组织管理

内容状态：基于代码与配置整理，待产品负责人复核。

用途

维护平台的组织架构与账号：部门树决定数据范围的归属，岗位用于描述职责，用户通过“角色 + 部门 + 岗位”获得登录身份与业务权限。组织管理不直接授予功能权限，功能权限在权限与角色中配置。

入口与前置

  • 入口：系统 → 组织管理 → 用户管理 / 部门管理 / 岗位管理，对应 /system/organization/user、/system/organization/dept、/system/organization/position。
  • 默认由安全管理员（角色 4）维护；其他角色需同时获得组织管理菜单与对应用户、部门、岗位接口权限。
  • 新增用户前应先建立部门和岗位；分配角色前应确认该角色已配置菜单与接口权限。

界面区域

用户列表提供搜索、列设置、新增、刷新，以及行内编辑、重置密码、删除；部门页为树形结构，支持新增根部门或子部门；岗位页为列表，维护岗位名称、编码、排序与状态。

操作步骤

  1. 在部门管理新增根部门或子部门，填写名称、上级部门、负责人、联系方式、排序与状态。
  2. 在岗位管理新增岗位，填写名称、编码、排序、状态与备注。
  3. 在用户管理点击新增，填写用户名、初始密码、昵称、性别、手机号、邮箱、状态，选择一个主部门、若干岗位与角色。
  4. 员工转岗时调整部门、岗位与角色；离职时优先冻结账号，确需删除时确认其业务数据归属。
  5. 用户忘记密码时，由有权限的管理员执行重置密码，并通知本人首次登录后修改。

字段与状态

对象关键字段说明
用户用户名、昵称、手机号、邮箱、状态、角色、部门、岗位状态为正常/冻结；角色可多选，部门为主部门，岗位可多选
部门名称、上级部门、负责人、电话、邮箱、排序、状态树形结构，负责人关联用户
岗位名称、编码、排序、状态、备注岗位是职责标签，不直接等于角色

注意事项与 FAQ

  • 内置用户和内置角色禁止删除：角色 ID 1–7、200 为内置角色；内置用户为各内置角色对应的初始账号。服务端在删除接口拦截，列表返回 is_builtin，前端据此禁用删除按钮。项目角色等非内置角色仍可删除。
  • 用户名是登录标识，创建后变更会影响登录与审计追溯，应先评估。
  • 删除部门前先迁移子部门与用户；删除岗位前先解除用户关联。
  • 角色分配受操作者自身权限约束，不能分配超出自己权限范围的角色。
  • 账号数量与 License 用户数上限相关；当前版本未在创建用户路径强制阻断超限，详见License 授权。初始密码与锁定策略见审计与安全。
