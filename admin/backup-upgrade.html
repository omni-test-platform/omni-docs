备份与升级

内容状态：基于代码与配置整理，待产品负责人复核。

用途

明确平台管理员在备份、升级与回滚中的职责：管理员负责变更窗口、数据冻结、升级后业务验证与授权/通知检查；服务器、数据库与容器操作由部署运维执行。具体命令与脚本参数不在本页重复。

入口与前置

  • 平台内没有独立的“备份/升级”菜单；版本信息在系统 → 关于，/system/about，可查看后端版本与前端构建时间。
  • 备份、恢复、升级与回滚入口在部署侧：参见备份与恢复与升级与回滚。
  • 升级前需获得变更授权，确认当前版本、目标版本、维护窗口与回滚方案。

责任边界

事项平台管理员部署运维
变更窗口与业务通知负责配合
停止/启动服务配合确认负责
数据库与上传文件备份确认范围负责执行
升级与回滚命令不直接执行负责执行
升级后登录、菜单、AT 任务、License、通知验证负责配合

操作步骤

  1. 升级前在“关于”页记录当前版本与构建时间，通知用户停止提交与执行任务。
  2. 由运维备份数据库；报告产物与上传文件不在数据库备份内，需要时单独打包或做文件系统快照。
  3. 确认备份文件非空并留存校验信息，再执行升级；升级脚本会保留 .bak，用于失败回滚。
  4. 升级后依次验证：服务健康检查、登录、菜单与权限、AT 任务列表与执行、License 状态与到期日、通知渠道测试发送。
  5. 如验证失败，按部署文档回滚到上一版本；数据库恢复必须显式指定目标库并确认，避免误写生产库。

项目说明
备份产物omni-<时间>.sql.gz 为表结构与数据；uploads-<时间>.tar.gz 仅在显式包含上传文件时生成
保留份数由备份脚本的保留参数控制，按文件名时间删除最旧备份

授权状态License 存于数据库，恢复旧库会回退授权记录，恢复后应重新导入最新 License

注意事项与 FAQ

  • 备份文件含账号密码哈希、集成凭据密文等敏感数据，按敏感数据保管，不要放入公开仓库或聊天工具。
  • 报告目录默认不在数据库备份内；需要保留报告时使用上传文件打包或单独快照，并注意报告保留期清理策略。
  • 恢复生产库前停止 API 与 worker，恢复后重启并检查健康接口、登录与 AT 任务列表。
  • 升级不改变 License 的机器码绑定；更换服务器或虚拟化标识后需重新签发，见License 授权。
  • 版本导入/导出属于高危操作，会覆盖菜单、接口与字典配置，仅系统管理员可执行；升级前不要用它替代正式备份。
