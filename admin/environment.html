执行环境与容量

内容状态：基于代码与配置整理，待产品负责人复核。

用途

本页配置执行器、执行容量、环境租约与任务队列。环境如何填写与使用，见用户手册 · AT 环境，本页不重复。

入口与前置

  • 执行器与 Jenkins：测试 → 环境与配置 → 执行引擎，/at/settings/engine，含“本地执行”“SSH 节点”“Jenkins”三个页签。
  • 执行容量：测试 → 环境与配置 → 配置管理 → “AT 执行容量”，/at/settings/config。
  • 环境与租约：测试 → 环境与配置 → 环境管理，/at/settings/environment。
  • 需要对应菜单与接口权限；SSH 节点需准备主机与凭据。

界面区域

SSH 节点列表展示名称、主机、端口、用户、状态、启用、负载/并发、能力、最近心跳与操作；执行容量页以表单展示并发与保留期；“环境管理”列表展示环境状态、使用策略、运行中/排队中数量。

操作步骤

  1. 新增 SSH 节点：填写名称、主机、端口、用户、认证方式与凭据，选择操作系统与执行类型。
  2. 设置“最大并发”，按需勾选能力（web/api/cli/script/headless）；Web 用例只会分配到具备 web 能力的节点。
  3. 节点配置可继承全局引擎配置，也可覆盖引擎路径、Python 环境与 Allure 路径；保存后点“检查”验证。
  4. 在执行容量页设置本地/SSH 并发上限、Jenkins 在途上限、单用户/单项目同时在跑上限，以及执行记录、报告产物保留天数与清理间隔。
  5. 环境被占用时，在环境详情查看当前租约、占用者与到期时间；必要时由运维调用强制释放接口。

字段与状态

对象关键字段说明
执行器名称、主机、端口、用户、认证方式、类型、OS、启用、最大并发、能力、标签、心跳状态 ONLINE/OFFLINE/BUSY；默认节点优先分配
执行容量本地/SSH 并发、Jenkins 在途、单用户上限、单项目上限、记录/产物保留天数、清理间隔保存后立即生效，无需重启
环境租约环境、执行根类型、占用者、获取时间、到期时间、释放原因同一环境同一时刻最多一条活跃租约
任务队列PENDING/RUNNING/SUCCESS/FAILED/DEAD、重试次数、下次执行时间、排队原因超过最大重试进入死信，需人工处理

注意事项与 FAQ

  • 自动分配：优先指定执行器；否则过滤已启用、ONLINE、未满载且能力匹配的节点，默认节点优先，再按负载升序与富余槽位排序。无可用节点时回退本地执行。
  • 排队原因包括等待用户配额、项目配额、本地执行槽、Jenkins 在途容量、环境空闲；任务详情会显示位次与原因。
  • 租约时长：独立任务/快速调试为 max(执行超时, 30 分钟) + 30 分钟；计划执行按 4 小时兜底，计划内子任务复用同一租约。租约到期且执行根不再运行会自动释放。
  • 强制释放接口为 POST /at/environments/:id/lease/release，会记录操作审计；当前前端未提供按钮，需由有权限的运维调用，释放前确认占用任务可以终止。
  • 容量字段填 0 表示回退到配置文件或内置默认值；修改容量不会终止已在运行的任务。
  • 节点离线先检查网络、SSH 凭据、心跳与引擎路径；Web 能力缺失时 Web 用例不会被分配到该节点。
